# Endpoint performance

Canic measures synchronous handlers generated by its update attribute. Sampling
starts after request admission and decoding and ends before reply encoding.
A trapped message rolls its sample back. A returned domain error is a completed
handler return. Async calls and query traffic are outside this measurement.

IC Metrics owns the summary arithmetic. Canic keys summaries by static exported
method names, so clients cannot allocate labels. Only executed handlers allocate
entries. Controller reads return up to sixteen names in lexical order with an
exclusive cursor. Separate pages observe the current incarnation independently.

Legacy Canic at `377fbce` used a static endpoint map in
`crates/canic-core/src/perf/mod.rs` and checked protected per-method instruction
counts in `qualification/canic-tests/tests/issuer_capacity`. This example keeps
those boundaries and limits sampling to a single execution. Root forwards reads
only for a ready ordinary child slot. It retains no second copy of the metrics.

## Sharing recordings across plugins

Endpoint instructions and timer events both use IC Metrics arithmetic. Canic
owns the per-method summaries. With its `metrics` feature, IC Timers 0.46.13
accepts an `Rc<MetricsStorage>`. Root and other packages call
`canic::lifecycle::initialize_timers()` to supply this handle from the
canister’s metrics store. Timer events update six wide
counters there, and Root reads their snapshot from that same handle. Repeated
reads preserve the counts. An absent source remains absent from the report.

For shared retention, distinguish a source, metric identity and unit, retain
overflow flags, and keep the counter and summary representations distinct.
IC Metrics 0.30.20 supplies `persistence::restore_counter` and
`persistence::restore_summary` for validating retained values. The historical
`ic-metrics-stable` one-map implementation is relevant prior art. A stable
adapter still needs an application-owned lease and an installed upgrade witness
under the current Storage contract.

The first integration registers timer counters and endpoint instruction
summaries as separate typed sources in Canic's per-canister heap store. The
composition root supplies the timer source to IC Timers at initialization.
Both readers project their existing reports from the shared store.

A disposable installed witness using the published IC Timers 0.46.13 recorded two
endpoint calls and one completed timer callback in the same canister. Repeated
queries preserved both counts, the anonymous performance query was refused,
and an upgrade reset both sources. Durable retention remains a separate
increment and must qualify continuity across an installed upgrade.
