# Packaged Canic and Generated Fleet Artifact Proof

The package proof verifies downstream Canic macros, the host-only testing
facade and host-generated Root, Coordinator and Store artifacts. It consumes
unpacked package archives through isolated tool and application workspaces.

Run the complete package-boundary proof with
`make test-packaged-downstream-wasm-store`. During Fleet build implementation,
select only the affected artifact proof:

```bash
scripts/ci/verify-packaged-downstream-wasm-store.sh fleet
```

## What It Proves

The script packages Canic and its required support crates, then builds the
three Fleet artifacts through the packaged host's `build_artifact` example.
It verifies each Wasm, gzip and Candid output, the generated package's exact
version, disabled publication, selected role features and exact packaged
Canic dependency path. Coordinator and Store outputs must match the canonical
Candid shipped inside the selected `canic` package.

Every role uses `.canic/generated/<package>/Cargo.toml` beside the selected
configuration. There is one source-generation path and one isolated package
set. Root selects configuration-owned capabilities; Coordinator has no App
configuration build script; Store compiles the selected configuration.

The `all` scope additionally compiles an application macro consumer and the
managed-App/standalone testing facade. The `root` scope selects only the
configured Root artifact. Each scope runs only its stated proof.

## Isolation and Limits

The generated manifests must reference unpacked package contents, with no
repository crate paths. Build execution isolates its home, target and scratch
directories. It reuses the caller's Cargo cache and Rust toolchains for offline
resolution and compilation. Scratch cleanup is owned by the invocation.

These are build and package-boundary checks. They do not install canisters or
qualify live readiness, interruption recovery or deployment performance.
Those behaviors retain their existing PocketIC and downstream owners.
