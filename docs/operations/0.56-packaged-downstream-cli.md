# Packaged Downstream CLI Qualification

This explicit package lane runs an installed CLI from extracted current packages
against a disposable downstream workspace and PocketIC. It covers build, review,
deployment, interrupted calls, resumption and terminal replay. It is separate from
ordinary tests and the larger opt-in CANIC-188 estate regression.

Run it from the repository root:

```bash
make test-packaged-downstream-cli
```

or directly:

```bash
scripts/ci/verify-packaged-downstream-cli.sh
```

## What It Proves

The script creates seven package archives, extracts them into a temporary tool
workspace and installs `canic` from those contents. Its generated consumer resolves
Canic exclusively from the extracted packages. App/role discovery and Ensure help
remain inexpensive smoke checks before the deployment journey.

The exact `packaged_consumer::installed_package_build_deploy_recover_and_replay`
PocketIC case then:

1. builds a real application through `canic build --json`, repeats it and checks
   complete-build reuse and unchanged release identity;
2. generates a small fresh Fleet with one Workload and one Ready pool canister;
3. consumes the public JSON next-action argument arrays, explicitly approves each
   new review and resumes interrupted approvals with the same arguments;
4. injects a pre-install failure and lost install/controller responses;
5. verifies the installed Coordinator, Root, Store and Workload hashes, then
   queries the application's typed endpoint; and
6. replays the completed approval with ICP unavailable, requiring completion,
   zero applied effects and unchanged Ledger/mutation observations.

The harness owns the disposable network and fault injection. The installed CLI
owns build, generation and deployment. Routing never reads internal journals and
never evaluates command strings.

## Guardrails

The proof fails if the packaged tool root contains repository crate paths such
as:

```text
<repo>/crates
target/debug/canic
```

The installed binary, build target, consumer, identities and scratch belong to
the proof. Passive probes use an isolated `HOME`; the PocketIC adapter supplies
an isolated ICP identity. The proof reuses the caller's Cargo/Rust caches for
offline resolution. The consumer does not inherit the repository's compiler
wrapper. Owned temporary files are removed on exit; complete test output is
retained under `target/test-runs/`.

## What It Does Not Do

This proof uses only disposable PocketIC canisters. It does not deploy to a live
IC environment, alter a downstream checkout, resume retained incidents or qualify
every import/reset scenario. It does not replace normal package verification or
claim complete workspace validation.

Successful output ends with:

```text
packaged downstream CLI probe passed
```
