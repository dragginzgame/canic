# Canic 0.108 Changelog

## 0.108.2 - 2026-08-23

### 📚 Documentation

- Reconciles the active design, status and working evidence with the tagged
  0.108.1 source and accepted closeout instead of describing an unpublished
  candidate.
- Clarifies that automatic authority never renews through time, restart,
  window rollover, direct top-up, policy reapplication or mutable
  configuration. CANIC-019 rotation is the only same-release path to one
  digest-bound successor generation; it retains predecessor usage and replay
  identity.

## 0.108.1 - 2026-08-22

### ➕ Added

- Introduces controller-gated Coordinator-to-Root runtime funding for the
  exact authenticated Registry Root. Durable Coordinator reservations and
  Root request journals provide accept-once grants, zero-accept replay,
  refund-safe rejection and recovery of uncertain calls.
- Binds every funding operation to immutable Fleet, Registry, caller, policy
  and sequence authority. Stable retention is bounded to one current plus one
  terminal Root result, a 32 KiB Root journal and a measured 32 MiB
  Coordinator ledger covering 4,096 Root/checkpoint entries.
- Adds finite single-Subnet, preview multi-Subnet and professional multi-Subnet
  profiles. Registry node counts scale standard values upward in 10 Tcycle
  increments; exact Fiduciary cost acknowledgement and non-renewing Root/Fleet
  grant caps are part of plan authority.
- Adds `canic scaffold fleet-input` to resolve Registry node counts, explain
  every scaling, cap, creation-fee and debit formula, support an explicit-count
  offline fallback and emit exact funding TOML without a funded identity.
- Adds the sole recovery-first Root funding timer, protected manual conversion
  and terminal emergency ICP refill. Ledger/CMC transfers use exact
  source/recipient binding, cumulative limits, retained ICP plus fees, optional
  rate floors and response-loss-safe replay.
- Adds exact-target `canic cycles topup` and `canic cycles convert`, protected
  funding status/metrics, `canic cycles funding <fleet> [--json]`, Medic
  checks and lifecycle/snapshot fences.
- Adds controller-reviewed funding-policy rotation for an exhausted long-lived
  Fleet. The no-effect plan binds the predecessor and maximum new exposure;
  apply retains application state, predecessor usage and bounded replayable
  checkpoints while advancing only successor-generation counters.

### 🩹 Fixed

- Accepts an exact terminal Root provisioning receipt even when an autonomous
  Root reaches `Provisioned` before the Coordinator observes intermediate
  counters. Progressed post-acceptance observations normalize to the accepted
  receipt, and scheduled retries retain bounded diagnostic context.
- Replaces self-declared funding evidence with one canonical operator
  Principal, active ICP identity verification, a derived Cycles Ledger account
  and live balance observation. Volatile balance evidence stays outside the
  plan digest and is rechecked immediately before paid effects.
- Makes fresh-Fleet infrastructure creation cycle-only and fee-complete. The
  maximum operator debit includes one Cycles Ledger fee for every host-created
  Coordinator, Root and Store; profile validation also uses the corrected
  standard values and canonical Candid variant names.
- Validates every Root profile and its Fleet window/lifetime capacity before
  activation. Bounded inter-canister calls, the shared Root recovery watchdog
  and low-balance refund handling return response loss to the durable replay
  owner without rejecting harmless unrelated refunds.
- Caps the ICP-refill journal at 4,096 lifetime identities while retaining
  terminal transfer replay. New work fails closed at capacity and manual and
  automatic refill cannot overlap.
- Makes rotation begin, stage, apply and status replay symmetric across later
  generations. Complete retained plans, prepared-journal-first activation,
  spend-floor validation and timer-safe prepare replay recover interrupted
  mixed authority without duplicating checkpoints or value.
- Completes replay-policy classification for every rotation command and keeps
  the economic decision in the DTO-free model layer. The public plan, hash and
  typed error contracts are unchanged.

### ⚠️ Breaking

- Fleet input now carries one top-level operator Principal rather than
  self-authored account/balance evidence; infrastructure creation accepts
  cycles only, and funding profiles use the canonical `single_subnet`,
  `preview_multi_subnet` and `multi_subnet` variants.
- The singular `root` recovery alias is removed. Top-up and conversion require
  an installed Fleet plus an explicit current Root where applicable; no
  pre-0.108 state or compatibility decoder is retained.

### 🧪 Testing

- Real single- and multi-Root PocketIC journeys prove exact grant accounting,
  non-renewing lifetime caps, uncertain-call suppression, direct top-up and
  interruption/replay behavior.
- PocketIC's production ICP Ledger and CMC prove duplicate-safe
  transfer/notification, reserve-denial fallback and no-spend outcomes for
  insufficient ICP or an exchange-rate denial.
- A governed rotation journey exhausts generation one, advances beyond its
  fixed window, rotates to one successor without losing application state and
  observes only the next monotonic grant.
- Fee-edge, ICP CLI 1.3 JSON and profile/scaffold coverage includes all three
  profiles and the 34/13-node 310 Tcycle Toko topology. Release qualification
  runs cheap checks first, executes all 22 internal PocketIC cases in one
  ordered process and reuses only reset-complete cached baselines.

## 0.108.0 - 2026-08-21

### 🔧 Changed

- Adds strict Coordinator and per-root funding policy to protected Fleet input
  schema 1, binds every decision field into canonical plan and Registry
  identity, and propagates the policy through Coordinator init and independent
  root activation authority.
- Hard-cuts the unreachable application-configured root ICP refill path. The
  existing manual refill workflow now reads only validated protected root
  authority; no alias or compatibility decoder remains.
- Freezes the conservative 16 KiB `canic_command` call envelope and the
  measured 42.2B-cycle normal-request and emergency-refill execution floors.
- Limits the 0.108.0 checkpoint to accepted M0 evidence and the complete M1
  protected-policy hard cut. Prematurely staged M2 grant policy, DTO, stable
  allocation and Coordinator operations do not ship in this release.

### 🩹 Fixed

- Derives a dedicated deterministic Root Component-provisioning operation ID
  so Fleet activation, Component provisioning, Store bootstrap/adoption and
  Registry synchronization have distinct stable identities. Root status
  routing establishes unique ownership before observer authorization, while
  duplicate ownership remains an invariant failure.
- Resolves infrastructure protocol bindings from finalized Candid sidecars
  beside the exact manifest-selected release Wasm for both local and IC build
  targets. Compatibility-tree Candid can no longer substitute for missing
  immutable infrastructure authority.
- Preserves the last correlated provisioning phase, accepted-Root count,
  in-flight Root and operation ID when the bounded host loop is exhausted.
- Heap-boxes the generated Root command dispatch future so downstream Root
  packages satisfy the warning-denied stack-frame lint without weakening the
  lint policy.

### 🧪 Testing

- The test-only M0 PocketIC probe distinguishes accept-and-trap rollback from
  post-commit caller loss, proves zero-accept replay/refund and balance
  semantics, exercises bounded current/last-result retention, and covers the
  complete emergency transfer/notify recovery journey.
- Focused policy, hashing, plan, activation, Registry and generated-Candid
  checks prove strict invalid-policy rejection, independent protected copies,
  decision-bearing digest changes and containment beneath existing role
  contracts.
- Focused host and control-plane checks prove distinct phase identities,
  finalized-sidecar resolution, duplicate-owner rejection and correlated
  bounded-loop diagnostics. A downstream fresh Toko installation remains the
  end-to-end confirmation.

### ⚠️ Breaking

- Fleet input containing roots now requires Coordinator and per-root funding
  policy. Root ICP refill policy is accepted only in protected Fleet input;
  the removed `canic.toml` authority is not migrated because 0.108 remains a
  pre-1.0 reinstall-only release boundary.
