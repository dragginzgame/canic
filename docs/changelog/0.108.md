# Canic 0.108 Changelog

## 0.108.2 - 2026-08-23

### 📚 Documentation

- Reconciles the active 0.108 design, status and working evidence with the
  actual tagged 0.108.1 source, successful complete gate and subsequent
  closeout audit instead of continuing to describe an unpublished dirty
  candidate.
- Clarifies the finite-authority rule: no timer, restart, fixed-window
  rollover, direct top-up, policy reapplication or mutable configuration can
  renew exhausted caps. The sole same-release exception is an explicit,
  controller-reviewed CANIC-019 rotation to one digest-bound successor
  generation that retains predecessor usage and never makes an old operation
  identity fresh; fresh reinstall remains the separate hard-cut path.

### 🧪 Testing

- The complete local `make validate` gate passes on the forward documentation
  correction, including warning-denied workspace Clippy, all ordinary tests,
  all 22 governed funding/recovery PocketIC cases and the remaining serial
  regression suites. The maintainer accepted the corrected closeout and
  authorized the 0.108.2 release on 2026-08-23.

## 0.108.1 - 2026-08-22

### 🔧 Changed

- Adds the Coordinator-owned runtime Root-funding command and controller kill
  switch. The target is always the exact authenticated Registry Root; callers
  cannot supply a recipient, Fleet or Coordinator identity.
- Persists each all-or-nothing grant reservation before the attached-cycles
  Root call. Fleet and per-Root fixed windows include outstanding
  reservations, accepted receipts convert one reservation into spent budget,
  definite Root rejection releases it, and uncertain calls retain it for
  reconciliation.
- Retains one current intent and one exact terminal result per registered Root.
  Exact current retry reconciles the same call, exact terminal retry returns
  the stored result, and only the monotonic successor may replace it.
- Stores the funding ledger in a dedicated Coordinator stable allocation and
  publishes its state-contract, replay-policy and generated Candid surfaces.
  Its 32 MiB bound covers both the measured 10,920,060-byte maximum-format live
  ledger and the 25,315,095-byte maximally fragmented completed-rotation
  history for all 4,096 Root slots/checkpoint entries.
- Binds funding operation IDs to the complete immutable Registry authority as
  well as revision, content, caller, sequence, balances and policy. Substituted
  authority rejects before retention; stale revision/content remains an exact
  typed terminal result.
- Adds the matching Root-owned request journal and Coordinator-only
  `AcceptFunding` command. A Root persists the request before any outbound
  call, requires exact attached cycles and rejects a grant when its live
  pre-acceptance balance has risen above the protected request threshold.
- Accepts a validated grant exactly once and commits the receipt in the same
  replicated message with no intervening await. Exact replay from either the
  current accepted operation or retained terminal result accepts zero and
  returns the original receipt so unaccepted attached cycles refund to the
  Coordinator.
- Gives the Root journal its own 32 KiB stable allocation at memory ID 63,
  shifts the remaining Canic-core upper reservation to IDs 64-99, initializes
  the journal during fresh Root installation and publishes the state manifest
  plus replay contract.
- Replaces illustrative funding values with topology-matched single-Subnet,
  bounded preview multi-Subnet and professional multi-Subnet profiles. The
  recommended two-Subnet preview starts the Coordinator with 140 Tcycles, its
  protected reserve at 80 Tcycles, the Root at 30 Tcycles and the Wasm Store at
  10 Tcycles for a 180 Tcycle initial debit. It uses a 10/30 Tcycle Root
  threshold/target, one 30 Tcycle grant per 90-day window and a recommended
  non-renewing two-grant/60 Tcycle lifetime cap with automatic ICP disabled.
  Standard 13-node values scale rationally by current Registry node count,
  round upward to 10 Tcycles and bind finite non-renewing Root/Fleet automatic
  grant counts and cycle ceilings into policy identity.
- Adds `canic scaffold fleet-input` as a funding-profile authoring aid. It
  resolves exact Coordinator/Root node counts from selected Subnet IDs and the
  validated Registry catalog, retains explicit counts as a fully offline
  fallback, explains every scaling, rounding, cap, creation-fee and debit
  formula, and emits exact integer TOML without reading a funded identity or
  weakening live `deploy plan` admission.
- Hard-cuts the Fiduciary-backed `recommended` selector. Every Fiduciary
  Coordinator and Root placement now requires an adjacent explicit cost
  acknowledgement; immutable plans retain catalog digest, specialization, node
  count, multiplier and warning evidence, which is rendered during planning
  and again immediately before the first paid install effect.
- Enables the sole Root `cycles:topup` timer owner. It restores and resumes the
  exact durable request before sampling or creating work, opens a normal
  request only below the protected threshold, records terminal responses,
  resamples before rescheduling and stops on Root/Fleet lifetime-cap denial.
  Non-Root parent funding behavior remains unchanged.
- Moves manual ICP conversion onto exact authenticated installed-Fleet Root
  authority and gives manual plus terminal automatic refill one durable
  operation owner. Both paths enforce per-call and cumulative ICP bounds,
  minimum retained ICP plus fee, optional exchange-rate floor, exact
  source/recipient binding and response-loss-safe Ledger/CMC replay.
- Allows automatic ICP refill only at the protected emergency threshold after
  the normal Coordinator path reaches a terminal result that cannot restore the
  Root. Cumulative rolling use and non-renewing automatic refill count/e8s caps
  are charged exactly once, and manual and automatic work cannot overlap.
- Hard-cuts the singular `root` recovery alias. `canic cycles topup` now accepts
  only the exact installed Fleet Coordinator or one explicit current Root
  Principal, while `canic cycles convert` requires the Fleet plus that explicit
  Root Principal and supports dry-run before either live recovery effect.
- Adds protected Coordinator/Root funding status and metrics, Medic funding
  profile checks and `canic cycles funding <fleet> [--json]`. The report joins
  authenticated installed authority with live reserve/window/cap, pending and
  terminal result, lifecycle eligibility, ICP fallback and Fiduciary cost
  evidence.
- Fences new funding during draining, unresolved refill snapshots and lifecycle
  restoration while preserving exact same-operation recovery. Root startup
  shares the canister-pool recovery watchdog instead of claiming a second
  timer identity, and the operator runbook documents observation, direct
  top-up, refill retry and escalation.
- Adds an explicit same-release funding-policy generation rotation for a long-
  lived Fleet whose finite automatic authority is exhausted. The no-effect CLI
  plan binds exact predecessor Registry/generation/policies, retained usage,
  placement evidence, proposed successor values, zero operator debit,
  Coordinator-treasury source and maximum new exposure. Controller-only apply
  uses one durable Coordinator fence plus idempotent Root prepare/activate
  receipts, retains application state and predecessor usage, and resets only
  the separately bounded successor-generation counters.
- Retains completed rotation checkpoints without eviction, bounded to 4,096
  total Root entries across all generations. Protected status and CLI planning
  expose remaining capacity and fail closed before beginning a rotation that
  cannot retain every affected Root checkpoint.

### 🩹 Fixed

- Completes the closed replay-policy manifests for the three Coordinator and
  two Root funding-policy rotation commands. Each command is now explicitly
  classified as operation-ID replay protected, matching its durable exact-
  request implementation and generated command union.
- Removes the obsolete test-only controller/operator admission helper and
  moves anonymous, mismatch and encrypted-identity evidence onto the live
  operator-funding observer used by fresh-Fleet planning and installation.
  Host fixtures publish fake ICP executables only after closing their staged
  writer, eliminating intermittent `ETXTBSY` failures under parallel tests.
- Makes ordinary unit and integration suites a hard barrier before serial
  PocketIC in the combined workspace runner. All ordinary failures are
  reported together, but an already-failed cheap tier no longer spends the
  expensive PocketIC qualification time.
- Reconciles an exact terminal Root provisioning receipt even when the
  autonomous Root reaches `Provisioned` before the Coordinator observes any
  intermediate counters. The Coordinator no longer treats its passive query
  start as Root completion authority, normalizes progressed status returned by
  the immediate post-acceptance query to the exact acceptance receipt, and
  emits the bounded operation, phase and diagnostic code when its scheduled
  retry fails.
- Hard-cuts self-declared operator funding evidence from Fleet input. The
  document now owns only one canonical top-level operator Principal; planning
  and installation verify the active ICP identity, derive its Cycles Ledger
  account and query its live balance. Volatile balance/source/time
  evidence no longer changes the canonical plan digest, while the Principal
  and derived account remain bound and installation rechecks sufficiency
  immediately before effects.
- Closes the creation-funding domain and fee gaps. Fresh-Fleet infrastructure
  creation now admits cycles only, rejects ICP amounts before profile
  validation and includes one exact Cycles Ledger fee per host-created
  Coordinator, Root and Store in the canonical maximum operator debit.
- Corrects the standard 13-node single-Subnet funding profile to the accepted
  100 Tcycle Coordinator creation and 30 Tcycle reserve/Root creation/Root
  target with a 10 Tcycle request threshold, rather than retaining earlier
  illustrative values. Rational scaling and 10 Tcycle upward rounding remain
  exact for larger Subnets.
- Publishes `single_subnet`, `preview_multi_subnet` and `multi_subnet` as the
  canonical Candid profile variant spellings so generated interfaces match the
  protected config contract.
- Validates every Root's exact profile, one-grant Fleet window capacity and
  Fleet lifetime cycle capacity during pre-activation join. A partially joined
  multi-Root Fleet no longer defers an individually impossible Root authority
  until aggregate activation validation.
- Prevents Root startup failure from duplicate recovery-watchdog ownership by
  routing both canister-pool and funding recovery through the canonical Root
  watchdog.
- Accepts harmless unrelated call-cost refunds while a Root remains within its
  protected low-balance range; only a balance above the request threshold
  invalidates a stale attached-cycles grant.
- Uses the bounded inter-canister call protocol for both Root-to-Coordinator
  requests and Coordinator-to-Root attached-cycle acceptance. Response loss
  therefore returns control to the durable current-operation replay owner
  instead of leaving an unbounded caller future.
- Bounds the Root-owned ICP-refill journal to 4,096 lifetime operation
  identities. New work fails closed at capacity while retained exact replay
  remains available; terminal transfer identities are never evicted and cannot
  be reinterpreted as fresh value transfers.
- Treats only nonterminal Fleet component provisioning and scale-out operations
  as rotation fences. A completed fresh-Fleet provisioning receipt no longer
  prevents the installed Fleet's first explicit policy rotation.
- Makes terminal staging replay symmetric with begin/apply replay: the exact
  completed `StageFundingPolicyRotationRoot` command returns its original
  receipt instead of reporting a state conflict, without adding another
  checkpoint or changing policy.
- Retains the complete immutable plan in every completed Coordinator rotation
  checkpoint. Exact begin, stage, apply and protected-status replay therefore
  remains available after later rotations, while any header, Root-plan,
  digest or predecessor-generation drift rejects without mutation.
- Recovers Root activation from the fenced prepared journal before consulting
  authority that can be temporarily split between the successor protected
  binding and predecessor Registry mirror. Interruption after either commit
  boundary now converges the exact operation instead of trapping the Root in
  an unrecoverable mixed state.
- Classifies exact active and terminal Root prepare replay before disarming the
  funding timer, so a delayed completed prepare command cannot cancel a
  correctly restored successor-generation timer.
- Rejects a successor Coordinator or Root fixed-window budget below the
  already retained spend in that same fixed window, preventing a validly
  published successor policy from making its durable ledger undecodable.
- Expands the Coordinator funding cell from 16 MiB to 32 MiB after the
  contract-valid worst case of 4,096 one-Root completed checkpoints measured
  25,315,095 bytes. The capacity proof now covers both that maximally
  fragmented history and one 4,096-Root checkpoint rather than assuming they
  encode to the same size.
- Restores the enforced model/DTO layering boundary for rotation validation.
  Ops converts the wire plan into one DTO-free named model input; the existing
  model-owned economic decision, public plan/hash surface and error semantics
  remain unchanged.

## 0.108.0 - 2026-08-21

### 🔧 Changed

- Adds strict Coordinator and per-root funding policy to protected Fleet input
  schema 1, binds every decision field into canonical plan and Registry
  identity, and propagates the policy through Coordinator init and independent
  root activation authority.
- Hard-cuts the unreachable application-configured root ICP refill path. The
  existing manual refill workflow now reads only validated protected root
  authority; no alias or compatibility decoder remains.
- Freezes the conservative 16 KiB `canic_command` call envelope and the
  measured 42.2B-cycle normal-request and emergency-refill execution floors.
- Limits the 0.108.0 checkpoint to accepted M0 evidence and the complete M1
  protected-policy hard cut. Prematurely staged M2 grant policy, DTO, stable
  allocation and Coordinator operations do not ship in this release.

### 🩹 Fixed

- Derives a dedicated deterministic Root Component-provisioning operation ID
  so Fleet activation, Component provisioning, Store bootstrap/adoption and
  Registry synchronization have distinct stable identities. Root status
  routing establishes unique ownership before observer authorization, while
  duplicate ownership remains an invariant failure.
- Resolves infrastructure protocol bindings from finalized Candid sidecars
  beside the exact manifest-selected release Wasm for both local and IC build
  targets. Compatibility-tree Candid can no longer substitute for missing
  immutable infrastructure authority.
- Preserves the last correlated provisioning phase, accepted-Root count,
  in-flight Root and operation ID when the bounded host loop is exhausted.
- Heap-boxes the generated Root command dispatch future so downstream Root
  packages satisfy the warning-denied stack-frame lint without weakening the
  lint policy.

### 🧪 Testing

- The test-only M0 PocketIC probe distinguishes accept-and-trap rollback from
  post-commit caller loss, proves zero-accept replay/refund and balance
  semantics, exercises bounded current/last-result retention, and covers the
  complete emergency transfer/notify recovery journey.
- Focused policy, hashing, plan, activation, Registry and generated-Candid
  checks prove strict invalid-policy rejection, independent protected copies,
  decision-bearing digest changes and containment beneath existing role
  contracts.
- Focused host and control-plane checks prove distinct phase identities,
  finalized-sidecar resolution, duplicate-owner rejection and correlated
  bounded-loop diagnostics. A downstream fresh Toko installation remains the
  end-to-end confirmation.

### ⚠️ Breaking

- Fleet input containing roots now requires Coordinator and per-root funding
  policy. Root ICP refill policy is accepted only in protected Fleet input;
  the removed `canic.toml` authority is not migrated because 0.108 remains a
  pre-1.0 reinstall-only release boundary.
