# Canic 0.110 Changelog

## 0.110.41 - 2026-09-24

### Fixed

- Capture release-validation fixture output and replay it only on failure.
  The deliberate missing-status rejection no longer appears as a real checkout
  error during a passing release-integrity check. Failed assertions retain the
  fixture diagnostics and nonzero exit status.

### Changed

- Keep interactive Fleet progress on one dedicated screen. Prerequisite,
  placement and failed-observation updates stay within that screen; resizing
  never switches to scrolling logs. Remove the effects percentage-style bar
  and redundant provisioning action line. Restore the terminal before final
  reports/errors, including generated desired-state output, and on Ctrl-C,
  SIGTERM or panic. Stop repainting before final output. Redirected/limited
  terminals and `NO_COLOR` retain plain milestones; JSON remains unchanged.
  Route receipt write failures through the live screen and preserve partial
  evidence in the final summary instead of printing over the current frame.
- Share successful Store catalog observations only within each independent
  upload reconciliation pass, keyed by exact Store Principal, Candid path/hash,
  template and version. Refresh after submission and on the next pass; retain
  per-chunk hash predicates, fresh cycle observations, durable individual
  receipts, partial-failure drainage and same-operation recovery. Existing
  observation timings count the reused reads.
- Reuse one HTTP connection pool and a single-worker Tokio runtime across a
  command's authenticated-query contexts. Build each Agent with freshly resolved
  network/root key and exported, verified signer. Preserve signature checking,
  response limits, typed transient retries and existing deadlines. Management,
  mint, debit and frontend Agent lifetimes retain their separate ownership.
  `reqwest` is now a normal host dependency; no dependency version changes.
  Query setup can report a typed HTTP client construction failure. CLI commands,
  progress output and receipt schemas are unchanged.

### Qualification

- Focused native regressions cover shared/fresh catalog observations, wrong
  chunk content, changed query authority, lost replies, restart and effect-free
  replay; HTTP fixtures prove connection reuse across fresh Agents, concurrent
  reads, fresh signer/root-key resolution and unchanged retry classification.
  These are request/setup reductions, not an end-to-end deployment speed claim
  or a new timing gate. Release-neutral compilation and final binding remain a
  [separate design proposal](../design/ideas/release-binding-finalization/design.md).

## 0.110.40 - 2026-09-24

### Fixed

- Attribute protected inspection and install-history timings to the child
  Principal as `request.subject`, separately from the Root transport `target`
  (CANIC-160). Inclusive `canister_inspection` and `canister_history` boundaries
  link nested requests through existing parent IDs and observation spans,
  including failed and interrupted reads. This extends the current v1 diagnostic
  contract; it adds no IC calls, cache authority or retry behavior.
- Keep build-lock waits on one compact terminal line, with sparse redirected
  events and final acquisition/failure/cancellation summaries (CANIC-176).
  Add `canic diagnostic build-lock --lock <path> [--json]` for read-only kernel
  holder, process identity, bounded child observations and advisory UTC phase
  diagnostics. Hidden or reused PIDs never authorize recovery. SIGINT/SIGTERM
  cancels only the waiter; acquisition failure no longer falls through to an
  unlocked build. Preserve the existing inode and exact artifact verification.
  The host progress callback now returns `io::Result<()>`; owner metadata gains
  current phase and process identity as a pre-1.0 diagnostic contract hard cut.
  Register the CLI build-lock inspection integration target in the ordinary
  parallel suite so inventory validation and complete test selection include it.
- Report Root native balances and exact floor shortfalls in Fleet readiness when
  ICP status returns underscore-grouped cycle counts (CANIC-182). Accept plain
  decimal counts and three-digit groups through the full `u128` range; reject
  malformed, oversized and overflowing input without changing identity,
  controller or funding checks. This changes populated readiness values, not
  the JSON schema or deployment effects.
- Preserve owner-reported retry deadlines through protected Coordinator status,
  Fleet progress JSON and timing receipts (CANIC-150). Human output displays the
  observed deadline in UTC; unknown deadlines remain unavailable, and stale
  observations never become a countdown or a claim of remote progress.
  The current `ProvisioningFailureOrigin` contract gains nullable `retry_at_ns`
  in Unix nanoseconds. This is a pre-1.0 schema hard cut under the reinstall-only
  release policy. Scheduling, polling and effect authority are unchanged.

### Qualification

- Qualify per-child timing propagation with 42 selected host/CLI checks and
  strict scoped lint. Retain the [Toko Miner Release matrix](../audits/reports/2026-09/2026-09-24/toko-performance-followup.md)
  for cold, warm, qualification-only, gameplay, dependency and relocation cases.
  All five warm pairs preserve exact release records and artifacts in 1.84–1.92
  seconds. Rebuilding cases expose runtime compilation costs; these shared-host
  published-.39 observations are not a .40 speedup or a new performance gate.
