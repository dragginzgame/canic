# Canic 0.110 Changelog

## 0.110.3 - Unreleased

### 🩹 Fixed

- Hard-cuts the obsolete temporary pool-Ledger recovery canister. The generated
  infrastructure role, standalone build, Store publication, Root command and
  status, durable recovery state, Fleet Ensure action and cycle projection,
  fixtures and dedicated CI lane are removed together. Current pool funding is
  native canister funding; Canic does not create Ledger-account balances on
  pool Principals or retain a hidden recovery fallback.
- `CANIC-121` closes the remaining production-adapter qualification seam. The
  Prepared-Root pool-controller journey now drives the concrete
  `IcpEnsurePlatform` through an isolated real ICP CLI identity, loses the first
  successful controller-update response, reconstructs the adapter, adopts the
  exact live result through `InspectCanister`, and proves terminal replay does
  not repeat either controller effect before continuing to Component
  provisioning.
- An explicit local-replica target now owns both ordinary ICP CLI calls and
  effective-ID management observations, so one adapter cannot accidentally
  split a local operation across differently resolved replica endpoints.
- The generated fresh-pool contract now retains a bounded 1T update-burn
  allowance in addition to its 1T first-observation allowance. The production
  controller-finalisation journey proved the former 100B ceiling insufficient;
  a 1.9T Ready floor is therefore funded with a reviewed 3.9T Create rather
  than reaching Root reset below its declared floor.

### 🧪 Testing

- The governed retained Root/Store PocketIC journey keeps the Root `Prepared`
  while the concrete production adapter finalises two pool-controller sets,
  crosses an actual lost response and fresh-process reconstruction, and then
  reaches exactly one Workload plus one Ready pool asset.
- Updates the test harness to `ic-testkit` 0.9.0 and PocketIC 16. All native
  PocketIC types now come through the testkit's upstream-crate re-export, so
  Canic no longer owns direct `pocket-ic` dependency edges or risks resolving a
  second client version during testkit upgrades. The upgrade also removes the
  unmaintained transitive `backoff` and `instant` packages from the governed
  dependency-risk inventory.
- Advances the isolated lifecycle-composition fixture to the exact published
  `icydb` and `icydb-model` 0.252.0 pair. The probe retains SQL-disabled runtime
  construction and its separate schema-only model boundary while adopting the
  current generated/runtime contract as one lockstep dependency family.

## 0.110.2 - 2026-09-02

### 🩹 Fixed

- `CANIC-122` permits the controller-authenticated, read-only
  `InspectCanister` Root command while the Root is `Prepared`. Pool-controller
  finalisation can therefore observe the exact temporary controller set and
  reconcile a lost controller response before Fleet activation; no other
  previously inactive Root command is widened.
- `CANIC-121` replaces the synthetic all-in-one qualification claim with two
  explicit production-boundary proofs. The host proof starts from a literal
  zero estate, applies the reviewed Fleet Ensure plan through PocketIC
  management effects, loses the first Create response, resumes the retained
  plan and journal through a reconstructed host adapter, converges and then
  replays with zero mutations. The separate control-plane proof inspects both
  sides of pool-controller finalisation through the real Prepared Root
  endpoint and reaches one Workload plus one Ready asset.
- `CANIC-123` seeds the generated pool-Ledger recovery helper from the exact
  consuming workspace lock before any infrastructure compilation. Cargo
  normalizes only that seeded graph offline; Canic reports every identity
  outside the workspace lock together and requires the result to resolve
  again under `--locked`. A compatible crate present only in a shared cache
  cannot silently enter the helper graph.

### 🧪 Testing

- Targeted ordinary tests cover exact helper-lock projection, a cache-free
  older-transitive seed and complete deterministic mismatch reporting.
- The governed host PocketIC proof covers literal-zero-estate plan, journal,
  lost-response, fresh-process resume, terminal conservation and immediate
  zero-effect replay. A separate governed control-plane proof covers the real
  Prepared Root and Component lifecycle, while the generated-helper proof
  retains exact withdrawal, replay and uninstall behavior.

## 0.110.0 - 2026-09-01

### 🩹 Fixed

- `CANIC-119` retains an applied fresh `Create` as exact nonterminal authority
  before later pool-controller finalization. The unchanged plan, journal and
  state bind the created Principal, live cycles and desired child topology;
  issued Creates cannot cross this boundary and exact replay cannot create or
  fund a second canister.
- `CANIC-120` separates a fresh pool's creation funding from its configured
  readiness floor. Generation includes the bounded first-observation and
  controller-effect burn ceilings, while immutable-plan policy and resume
  return exact requested, floor, burn, required and shortfall values before
  controller or protocol work when funding is insufficient.
- `CANIC-121` introduced the literal zero-estate Coordinator, Root, Store and
  two-pool journey. Its initial controller-finalisation fixture observed
  PocketIC directly after installing the Root; `0.110.2` replaces that
  incomplete boundary with the production Prepared-Root inspection ordering.

### 📊 Audit

- Freezes published `v0.109.35` as the reinstall-only predecessor for 0.110 and
  promotes `CANIC-WASM-001/v5`. The canonical audit binds optimizer metrics to
  one role-local build log rather than a disposable staged-artifact pathname.
- Two clean release builds and one debug build of every canonical role are
  retained with exact code-section, total-module, compressed, declared- and
  defined-function, export, table and optimizer metrics. Root remains the
  largest canonical role with 3,776,168 code-section bytes and 40,322 declared
  functions of headroom beneath the frozen IC limits.
- The exact downstream canary, controlled ablations, generated-surface
  inventory and generic-instantiation cohort remain B1 work for a later 0.110
  batch. This first release does not claim the complete 0.110 contraction or
  promote 0.111.

### ⚠️ Breaking

- 0.110 is a pre-1.0 reinstall-only hard cut. It does not import predecessor
  plans, journals, stable state, release authority or canister identity.
  Same-release interruption recovery, exact authority, bounded paid effects
  and cycle conservation remain mandatory.

### 🧪 Testing

- Targeted host regressions cover creation funding, exact pending topology,
  retained nonterminal balances, typed insufficient funding and effect-free
  replay.
- The initial targeted governed PocketIC journey covered the literal
  zero-estate Coordinator/Root/Store/two-pool path, terminal workload and Ready
  inventory, conservation and immediate replay. Prepared-Root controller
  observation is completed by the corrected `0.110.2` journey.
- The temporary pool-Ledger recovery helper resolves its standalone generated
  graph entirely within the governed workspace lock; the exact PocketIC
  withdrawal, replay and uninstall proof passes against that locked graph.
- The governed release flow owns the one complete workspace, feature, Candid,
  artifact and PocketIC validation pass for the immutable release candidate.
