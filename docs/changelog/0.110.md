# Canic 0.110 Changelog

## 0.110.7 - Unreleased

### 🩹 Fixed

- Validation now keeps ordinary successful libtest output captured, so expected
  panic fixtures and routine chatter cannot masquerade as live failures.
  The six-check fast internal tier no longer compiles the governed Fleet and
  PocketIC fixture catalogue; the serial PocketIC lane enables that catalogue
  explicitly. Brittle source-spelling, positional-effect and exact call-count
  assertions have been replaced by typed action identities, compiled protocol
  contracts and closed ownership checks.
  Documentation layout and transitive informational-advisory drift are reported
  for review without blocking an otherwise valid candidate; missing authority
  documents, vulnerabilities, yanked packages and direct unmaintained
  dependencies remain fail-closed.

- Canic-owned top-level control methods no longer reuse a method name for
  incompatible role contracts. Ordinary managed roles retain the single
  `canic_command`/`canic_status` contract, while Coordinator, Root and Wasm
  Store each expose explicitly named role-owned command and status pairs.
  Inter-canister calls, host inspection, readiness and metadata selection now
  derive the exact method from the protected role binding; there are no
  compatibility aliases.
- Fleet Ensure now treats every Root's Cycles Ledger account as a separate
  reviewed funding domain instead of reporting only operator debit. Planning
  forecasts pool creation for selected Component provisioning, recursive
  initial children and the configured post-provision Ready floor, subtracting
  reusable Ready assets and already-completed workloads. Apply re-reads the
  exact Root account before the first protocol effect and durably pauses with
  raw balance, creation count, amount, Ledger fee, maximum debit and shortfall
  when it is underfunded. The plan owns the exact `FundEstate` Ledger transfer,
  its durable idempotency identity and its receipt; apply proves both source
  debit and destination credit before protocol work. An unchanged balance
  causes no protocol call or journal rewrite.
- Coordinator reconciliation accepts a Root's later canonical monotonic
  provisioning cursor even when several reservation, claim, install or
  Registry steps completed between observations. A coalesced observation may
  carry the exact typed estate-funding pause without losing its durable
  progress. Regressed, unchanged and noncanonical cursors remain rejected. The
  governed five-Component proof now supplies the exact Root Ledger balance and
  funded creation results it exercises instead of relying on a transient
  conflict or unfunded synthetic canisters.
- Fleet Ensure records the freshly observed controlled balance when apply
  accepts bounded pre-effect balance movement, so terminal conservation reports
  the truthful operation start rather than the earlier reviewed-plan snapshot.
  Runtime pool-creation operation IDs must use canonical lowercase SHA-256 text;
  case-variant encodings cannot satisfy retained funding authority.
- Autonomous pool creation now requires a generated 1T execution margin above
  the retained readiness floor and management creation fee. Root retains the
  exact Ledger block, operation, requested amount, fees, readiness floor,
  margin and first live native balance for every created asset. Terminal
  conservation uses those actual receipts, rejects missing or duplicated
  evidence, and bounds the measured pre-ready burn instead of substituting the
  maximum forecast.
- Plan-time estate forecasting pages the complete protected Root pool,
  including dynamic Workload, Ready, Failed, Claimed, PendingReset, Recycling
  and HandingOff assets plus a pending creation. Every occupied slot counts
  once; capacity exhaustion fails before funding or protocol mutation and
  leaves retained Failed assets untouched for a separately reviewed repair.
- Terminal Fleet inventory now admits a Component only when Root management
  inspection proves it is running, controlled by that exact Root alone and
  running the current release module. Status, controller, management-module,
  Directory-module, Registry-principal, release-network, Fleet-admission,
  protocol-sidecar and generator Candid-sidecar conflicts retain typed values,
  digests and paths for exact matching instead of requiring error-message
  parsing.
- `canic info cycles` now selects observations from the role and its declared
  capabilities. Coordinator history is explicitly unavailable, unbound pool
  assets retain a live balance without pretending to expose history, Root and
  Store omit their unsupported top-up query, and automatic-top-up Components
  retain both history and top-up evidence.
- The workspace cryptographic graph uses the same `k256 0.13.4` family already
  selected by the IC client stack, removing the parallel 0.14 elliptic-curve
  family. Chain-key signing handles the 0.13 low-S normalization result
  explicitly, and its fixtures use that version's SEC1 encoding API.
- `canic toolchain install` now installs both checksum-verified `ic-wasm
  0.11.1` and Binaryen 132 and reports their absolute paths. Artifact builds
  preflight one pinned tool set before Cargo starts, prefer the canonical
  installation over PATH wrappers, reuse its absolute paths for every role and
  reject missing or mismatched tools with the exact selected or expected path.
  A root-level `HOME=/` installation is called out explicitly.

### 🔧 Changed

- Complete local validation now finishes cheap source and policy guards, then
  workspace checking and warning-denied Clippy, before starting the
  control-plane feature matrix. The full test graph remains the final barrier.
- GitHub ordinary tests, PocketIC tests and release builds now wait for the
  complete Rust checks job, rather than starting alongside Clippy.
- Host-produced Wasm code-section diagnostics use the same fixed scope and
  status columns as governed PocketIC progress output.
- The controlled Wasm-ablation runner reads exact optimizer metrics from a
  typed transform-metrics v1 record emitted by its method-owned build harness
  instead of parsing a human diagnostic line. The harness compiles against the
  immutable product worktree without requiring a new option in that historical
  source, retains its separately resolved offline Cargo lock and requires that
  lock unchanged throughout measurement. Retained runs also clear ambient
  compiler wrappers; development smoke uses only a repository wrapper that
  passes its exact compiler probe.
- The executable ablation experiment manifest owns each runnable patch's exact
  SHA-256. Catalog validation now rejects patch drift before qualification or
  measurement instead of duplicating mutable hashes in explanatory prose.
- A non-retainable qualification lane builds one specified patch across every
  selected artifact and validates its structured transform record, final Wasm,
  gzip, Candid and function count before that experiment can become runnable.
  Row 4 now passes all eleven canonical roles plus `runtime_probe`, while row 5
  also passes `blob_storage_probe`; these are build qualifications only, not
  measurements, determinism or behavior parity.
- Role-contract resolution requires Root chain-key signing only when the Fleet
  actually declares a delegated-token issuer and rejects unused Canic crypto
  features through a typed `SurplusCryptoFeature` finding. The canonical App,
  index, scaling and non-issuing Hub fixtures now enable no signature stack;
  only Root and the two roles that exercise token verification/issuance retain
  authentication cryptography.
- Packaged downstream qualification now begins with an existing
  `thiserror 2.0.20` lock, enables the public `canic/testing` facade through
  ordinary Cargo resolution, and requires the resulting graph to compile
  locked without a downstream transitive dependency override or lockfile edit.
- Governed PocketIC failure progress carries the stable
  `CANIC-TEST:E001` event code so the outer validation runner can surface a
  failure immediately without coupling to its human status wording.

### ⚠️ Breaking

- Current build provenance no longer accepts or emits the former
  `tool_unavailable` transform outcome. `ic-wasm` is a mandatory canonical
  build input; missing or incompatible tools now fail preflight before Cargo or
  provenance output. Pre-1.0 consumers should reinstall the current toolchain
  rather than retaining optional-tool handling.

## 0.110.6 - 2026-09-04

### 🩹 Fixed

- The locked elliptic-curve dependency graph now selects the maintained
  `wnaf 0.14.1` patch instead of the yanked `0.14.0` package, keeping the
  reviewed dependency-risk inventory free of newly yanked package identities.
- Active Component Child creation now completes through the existing durable
  lifecycle within the requesting capability call and returns the new canister
  ID. Detached completion remains limited to initial bootstrap, where the
  Prepared parent cannot yet serve Directory convergence.
- Fleet status discovers each selected environment from validated terminal
  Fleet Ensure snapshots instead of an orphaned host catalog. Backup reads the
  explicitly named last-converged inventory authority, which stays bound to the
  terminal journal operation across interrupted successor planning.
- Terminal Fleet inventory reconciles the complete protected Component tree,
  including nested sharding, scaling and index descendants. Each workload must
  match its exact Component, allocation operation, Root, parent, role and
  release module; only a verified Pool workload may adopt its terminal
  Component parent.
- Exact cycle balances, history, top-up amounts and runtime metrics now require
  controller authentication on managed, standalone-local, Root and Store
  status surfaces. Operator commands retain access through existing Root
  authority and management inspection without adding a human principal as a
  managed Component controller. Both observation command variants are
  explicitly classified as read-only in the replay-policy manifest.
- Fleet Coordinator inspect-message admission now decodes the command variant
  and applies the same command-specific ingress payload ceiling as endpoint
  execution. Subnet inspection also retains the caller-selected ICP executable
  and environment instead of silently falling back to local defaults.
- Terminal Fleet inventory reads exact top-level and descendant Root
  Component-provisioning owners through dedicated typed status selectors. A
  valid operation identity may also own adjacent durable records, so inventory
  no longer enters the heterogeneous operation catalogue's ambiguity failure
  or retries that permanent invariant.
- Terminal Component inventory distinguishes the raw Wasm identity retained by
  provisioning receipts from the gzip payload identity reported by live
  management status. Root inspection supplies the mandatory live module and
  cycle observation; an absent optional child Directory hash is accepted, while
  any conflicting Directory or management hash still fails closed. Component
  Registry traversal also enumerates each logical Component partition once
  instead of rediscovering the same allocation through its child records.

### ⚠️ Breaking

- The obsolete host Fleet catalog and direct public child cycle-query helper
  are hard-cut. Host integrations use terminal Fleet Ensure discovery and the
  topology-aware protected observability facade; no compatibility aliases or
  fallback authority remain.

### 📊 Audit

- A valid immutable eleven-role `v0.110.5` baseline retains deterministic
  release artifacts. The largest role has 3,826,016 code-section bytes and
  40,404 replica-limited defined functions of headroom; the defined `7/10`
  score is routing pressure, not a network-limit or correctness failure.
- Generated-surface and destroyed-state inventories separate immutable release
  evidence from the working overlay, classify all 39 Canic state allocations,
  and keep consumer discard or reseed policy outside Canic release authority.
  The removed temporary pool-Ledger recovery family remains absent.
- A machine-checked eighteen-row controlled-ablation harness covers the eleven
  canonical roles and four Canic-owned capability fixtures. Its first complete
  result retains the raw payload-limited adapter: removing the independent
  canister-origin bound saves only 967 optimized code bytes and no defined
  functions. The immutable all-role global storage-registration measurement
  removes 273,554 artifact-summed optimized code bytes and 662 defined
  functions, including 192,340 bytes and 166 functions in Fleet Coordinator.
  This material result supports role-selected storage wiring but the destructive
  switch makes no bootstrap or lifecycle-parity claim. The inclusive activation-
  persistence switch now has all-role release-build qualification and awaits
  immutable measurement without making an activation-parity claim.
- The function gate is frozen to the IC replica's local/defined-function
  quantity with an independent repository counter. A fixed-surface `Page<T>`
  cohort is ready for later measurement, and downstream application pressure
  remains non-binding evidence rather than Canic product logic.

### 🧪 Testing

- Long PocketIC journeys now render aligned, terminal-colored scope, status,
  phase and elapsed-time columns. Successful cache acquisition defaults to one
  compact line per artifact, Wasm-size reports omit disposable staging paths,
  and full cache keys, paths and lock timings remain available with
  `CANIC_TEST_OUTPUT=verbose`.
- Governed PocketIC test registries no longer duplicate incidental aggregate
  case counts; they derive membership from the registered cases and retain
  non-empty, unique-name, required-case and execution-order checks. The
  pre-commit integrity gate now proves partial-stage rejection, formatted-index
  refresh and preservation of unrelated local edits through executable Git
  fixtures instead of freezing the hook's internal shell statements.
- Current-document validation now owns current governance, architecture,
  operator guidance and active design shape. It no longer pins unrelated

  audit to fixed repository paths.
- Focused unit and protocol-surface checks cover terminal status authority,
  backup crash ordering, descendant identity, protected observability and
  environment routing. Governed PocketIC journeys prove non-controller
  rejection of exact observability, retain Root-authenticated role-attestation

- The literal-zero production-adapter proof now uses the minimum topology that
  exercises its actual contract: one Hub, one initial Shard and one remaining

  The focused governed run completes in under six minutes rather than taking

  catching invalid experiment switches before the full two-repetition all-role
  evidence run. Retained B1 evidence keeps the complete deterministic method
  unchanged.

## 0.110.5 - 2026-09-02

### ✨ Added

- `CANIC-124` adds `canic::testing::install_managed_component_group`, which
  constructs a complete configured Component Group and installs every Hub-
  created child with its exact `ComponentChild` authority, application init
  bytes, runtime Directory and Fleet-admission projection. The public fixture
  supports configured and on-demand sharding, scaling and index placement
  without exposing protected payload construction to downstream tests.

### 🩹 Fixed

- `CANIC-126` treats a delayed exact balance for a retained Root-owned pool
  asset as bounded passive observation. Planning and terminal replay re-observe
  the same operation without issuing a protocol, install, controller, creation
  or funding effect; terminal progress clears the stall count, while exhaustion
  retains a resumable journal and names the target plus last authoritative
  lifecycle.
- `CANIC-127` keeps managed Hubs unready until every configured initial child
  reaches exact Root-owned allocation, installation, Directory and membership
  completion. A Prepared Root admits only the exact registered Component's
  initial-child allocation request, the durable child operation advances from
  one detached idempotent driver, and only typed transient bootstrap failures
  retry within the bounded lifecycle budget.
- A Root-authenticated replay of the exact active runtime configuration now
  reclaims a managed non-Root bootstrap only after its finite transient retry
  budget was exhausted. The replay does not rerun the application install hook,
  while non-retryable failures, ready runtimes and in-flight bootstrap owners
  remain terminal or unchanged.
- Root Component activation now preserves the exact Directory authority hash
  under which a target became active separately from its newer current
  Directory. A configured initial child may therefore advance the Hub Directory
  before Root observes the activation response without causing an authority
  conflict; an already-active response is accepted only when its binding,
  deployment, operation and original activation receipt all match exactly.
- Root membership activation queries the target's compact readiness status and
  cannot publish an Active Component whose mandatory application bootstrap is
  still waiting or failed.
- Component retirement retains the exact committed runtime operation while a
  validated `Draining` Component is still runnable and has no quiescence intent.
  Its final Directory convergence can therefore complete before stop; the
  operation closes again as soon as quiescence starts and remains unavailable
  for removed Components.
- Terminal Fleet inventory now queries the Coordinator's exact retained
  Component-provisioning operation and distinguishes its source Registry from
  the published active Registry. Root top-level provisioning evidence must
  match the retained source Registry, plan hash and configuration digest, while
  Root publication and Coordinator publication must match the active Registry.
  A fresh revision-3 provisioning operation can therefore terminalize against
  its correctly published revision-4 Registry without weakening either
  authority check.

### 🔧 Changed

- Text-mode `canic fleet generate` and `canic fleet ensure` output now renders
  every cycle quantity with consistently rounded three-decimal `B`, `T` or `Q`
  units. This includes aggregate conservation bounds, per-canister balances,
  native top-up detail, conservation equations and terminal measured
  conservation.
- `canic fleet ensure --json` no longer expands each Store publication chunk
  into a decimal byte array. Each `publish_store_chunk` request instead exposes
  the workspace-relative content-addressed `bytes_path`, exact `bytes_sha256`
  and `bytes_size`; the referenced sidecar remains the hash-verified object used
  for interrupted apply and replay. All other complete plan metadata and exact
  machine-readable cycle values remain present.
- Obsolete repository-local residue is removed: the root-level 0.76.6
  `AUDIT_REPORT.md` snapshot, the retired `.cursor` skill and the stale root
  `nns/` subnet-catalog cache superseded by external `ic-query` ownership and
  network-specific `.ic-query/` state. The unreferenced disposable 0.100
  mainnet deployment proof, the obsolete `llms.txt` prompt file and an empty
  0.19 design placeholder are also removed, with the latter replaced by a link
  to its actual changelog. An empty npm lock and the completed, orphaned 0.33
  refactor tracker are removed too, while the maintained Fleet-funding runbook
  is restored to the operations index. Maintained audit guidance, current
  status, retained evidence and runtime NNS support remain in their canonical
  locations.

### 🧪 Testing
