# Canic 0.110 Changelog

## 0.110.5 - 2026-09-02

### ✨ Added

- `CANIC-124` adds `canic::testing::install_managed_component_group`, which
  constructs a complete configured Component Group and installs every Hub-
  created child with its exact `ComponentChild` authority, application init
  bytes, runtime Directory and Fleet-admission projection. The public fixture
  supports configured and on-demand sharding, scaling and index placement
  without exposing protected payload construction to downstream tests.

### 🩹 Fixed

- `CANIC-126` treats a delayed exact balance for a retained Root-owned pool
  asset as bounded passive observation. Planning and terminal replay re-observe
  the same operation without issuing a protocol, install, controller, creation
  or funding effect; terminal progress clears the stall count, while exhaustion
  retains a resumable journal and names the target plus last authoritative
  lifecycle.
- `CANIC-127` keeps managed Hubs unready until every configured initial child
  reaches exact Root-owned allocation, installation, Directory and membership
  completion. A Prepared Root admits only the exact registered Component's
  initial-child allocation request, the durable child operation advances from
  one detached idempotent driver, and only typed transient bootstrap failures
  retry within the bounded lifecycle budget.
- A Root-authenticated replay of the exact active runtime configuration now
  reclaims a managed non-Root bootstrap only after its finite transient retry
  budget was exhausted. The replay does not rerun the application install hook,
  while non-retryable failures, ready runtimes and in-flight bootstrap owners
  remain terminal or unchanged.
- Root Component activation now preserves the exact Directory authority hash
  under which a target became active separately from its newer current
  Directory. A configured initial child may therefore advance the Hub Directory
  before Root observes the activation response without causing an authority
  conflict; an already-active response is accepted only when its binding,
  deployment, operation and original activation receipt all match exactly.
- Root membership activation queries the target's compact readiness status and
  cannot publish an Active Component whose mandatory application bootstrap is
  still waiting or failed.
- Terminal Fleet inventory now queries the Coordinator's exact retained
  Component-provisioning operation and distinguishes its source Registry from
  the published active Registry. Root top-level provisioning evidence must
  match the retained source Registry, plan hash and configuration digest, while
  Root publication and Coordinator publication must match the active Registry.
  A fresh revision-3 provisioning operation can therefore terminalize against
  its correctly published revision-4 Registry without weakening either
  authority check.

### 🔧 Changed

- Text-mode `canic fleet generate` and `canic fleet ensure` output now renders
  every cycle quantity with consistently rounded three-decimal `B`, `T` or `Q`
  units. This includes aggregate conservation bounds, per-canister balances,
  native top-up detail, conservation equations and terminal measured
  conservation.
- `canic fleet ensure --json` no longer expands each Store publication chunk
  into a decimal byte array. Each `publish_store_chunk` request instead exposes
  the workspace-relative content-addressed `bytes_path`, exact `bytes_sha256`
  and `bytes_size`; the referenced sidecar remains the hash-verified object used
  for interrupted apply and replay. All other complete plan metadata and exact
  machine-readable cycle values remain present.
- Obsolete repository-local residue is removed: the root-level 0.76.6
  `AUDIT_REPORT.md` snapshot, the retired `.cursor` skill and the stale root
  `nns/` subnet-catalog cache superseded by external `ic-query` ownership and
  network-specific `.ic-query/` state. The unreferenced disposable 0.100
  mainnet deployment proof, the obsolete `llms.txt` prompt file and an empty
  0.19 design placeholder are also removed, with the latter replaced by a link
  to its actual changelog. An empty npm lock and the completed, orphaned 0.33
  refactor tracker are removed too, while the maintained Fleet-funding runbook
  is restored to the operations index. Maintained audit guidance, current
  status, retained evidence and runtime NNS support remain in their canonical
  locations.

### 🧪 Testing

- A governed Prepared-Root PocketIC journey proves three top-level Components,
  configured sharding and scaling children, terminal child membership, lost
  activation-response adoption and immediate effect-free replay. Focused host
  tests separately prove delayed Root-owned balance convergence and a bounded
  no-effect stall.
- A governed literal-zero-estate PocketIC journey uses the production Fleet
  Ensure plan, journal and `IcpEnsurePlatform`, crosses an actual lost
  controller-update response and fresh-process adapter reconstruction, then
  drives the real Coordinator/Root/Store protocol to one Workload plus one Ready
  pool asset. It proves terminal cycle conservation and an immediate second
  plan and apply with zero effects.
- Focused runtime tests prove that only a bounded transient init-bootstrap
  exhaustion is reclaimable from an exact active runtime-configuration replay.
  Application init is not repeated, ready and in-flight owners remain unchanged,
  and non-retryable failures remain terminal.
- A focused CLI rendering regression covers zero cycles, fractional and rounded
  billion and trillion values, quadrillion values, planned conservation,
  native top-up detail and measured conservation in one complete text report.
- A focused JSON projection regression proves a 64-KiB Store chunk produces a
  report below 10 KB with no inline `bytes`, while retaining its local path,
  exact hash, size, index and maximum `u128` cycle value.
- Focused terminal-inventory regressions model a source revision 3 and active
  publication revision 4, and separately reject a wrong source Registry, wrong
  publication Registry, mismatched Coordinator plan authority and non-active
  Coordinator publication.
- A governed public-fixture PocketIC journey covers initial Shard and scaling
  Replica creation, on-demand indexed and scaled children, exact parent and
  Component Group bindings, direct admitted and denied child ingress,
  same-release child upgrade, successor fencing and timer restoration.
- The packaged downstream consumer compiles the managed Component-tree fixture
  from the public `canic` package without private `canic-core` or `ic-testkit`
  lifecycle reconstruction.
- Frozen topology/release-set digests, the governed PocketIC inventory, lifecycle
  retry ownership, timed host-wait ownership and the canonical ICP test
  environment now include the managed sharding, scaling and index child surface.

## 0.110.4 - 2026-09-02

### 🩹 Fixed

- `CANIC-125` fixes GitHub issue 23 without changing retained Fleet plans or
  journals. The long-running `ProvisionComponents` action now uses bounded
  exponential polling backoff and a topology-derived unchanged-progress floor,
  capped at 64 observations. An explicitly reviewed larger configured limit is
  still honored. A silent status never authorizes another command;
  only the existing typed retryable-failure evidence can replay the exact
  operation identity.
- Stalled-operation diagnostics now name the exact action and include compact
  provisioning phase, Root counts, Component count, pending failure and full
  durable-status digest evidence. Genuine semantic progress still resets the
  global consecutive-stall budget.

### 🔧 Changed

- Advances the isolated lifecycle-composition fixture to `icydb` 0.252.1. Its
  schema now authors models through `icydb::model::prelude`, removing Canic's
  separate `icydb-model` dependency while retaining SQL-disabled runtime
  construction and one lockstep generated/runtime dependency family. The exact
  dependency guard rejects a future direct `icydb-model` edge anywhere in the
  maintained production manifests.

### 🧪 Testing

- Focused policy and workflow regressions prove that one Root with eleven
  Components derives a 39-observation floor, ten unchanged paced observations
  can reach terminal state after one issuance, and immediate replay performs no
  mutation.

## 0.110.3 - 2026-09-02

### 🔧 Changed

- `canic state audit --ci` now emits a bounded status-and-count summary on
  success and only actionable warning/failure rows otherwise. `canic medic
  --ci` reports consistent check, warning and failure counts and codes, exposes
  its included state-audit result, and treats an unselected Fleet environment
  as not evaluated during workspace-only diagnostics. Live drift remains
  explicit through `canic medic fleet <fleet> --ci`.

### 🩹 Fixed

- Hard-cuts the obsolete temporary pool-Ledger recovery canister. The generated
  infrastructure role, standalone build, Store publication, Root command and
  status, durable recovery state, Fleet Ensure action and cycle projection,
  fixtures and dedicated CI lane are removed together. Current pool funding is
  native canister funding; Canic does not create Ledger-account balances on
  pool Principals or retain a hidden recovery fallback.
- `CANIC-121` closes the remaining production-adapter qualification seam. The
  Prepared-Root pool-controller journey now drives the concrete
  `IcpEnsurePlatform` through an isolated real ICP CLI identity, loses the first
  successful controller-update response, reconstructs the adapter, adopts the
  exact live result through `InspectCanister`, and proves terminal replay does
  not repeat either controller effect before continuing to Component
  provisioning.
- An explicit local-replica target now owns both ordinary ICP CLI calls and
  effective-ID management observations, so one adapter cannot accidentally
  split a local operation across differently resolved replica endpoints.
- The generated fresh-pool contract now retains a bounded 1T update-burn
  allowance in addition to its 1T first-observation allowance. The production
  controller-finalisation journey proved the former 100B ceiling insufficient;
  a 1.9T Ready floor is therefore funded with a reviewed 3.9T Create rather
  than reaching Root reset below its declared floor.
- Removing the temporary pool-Ledger status field no longer weakens a retained
  Root-start operation's module fence. Where a sealed Start authority remains,
  generation accepts only its exact predecessor or requested successor module
  and rejects an unrelated live Root before protected status is consumed.

### 🧪 Testing

- The governed retained Root/Store PocketIC journey keeps the Root `Prepared`
  while the concrete production adapter finalises two pool-controller sets,
  crosses an actual lost response and fresh-process reconstruction, and then
  reaches exactly one Workload plus one Ready pool asset.
- Updates the test harness to `ic-testkit` 0.9.0 and PocketIC 16. All native
  PocketIC types now come through the testkit's upstream-crate re-export, so
  Canic no longer owns direct `pocket-ic` dependency edges or risks resolving a
  second client version during testkit upgrades. The upgrade also removes the
  unmaintained transitive `backoff` and `instant` packages from the governed
  dependency-risk inventory.
- Makes Fleet-admission PocketIC qualification insensitive to valid phase
  coalescing: targets are held before activation begins, every Root still
  crosses fenced/activating/opening restart boundaries, and Preparing must be
  interrupted without requiring every Root to expose that transient phase.
  Same-release upgrade proofs now retry only PocketIC's typed install-code rate
  limit under a bounded policy instead of assuming one fixed cooldown always
  replenishes the subnet budget.

## 0.110.2 - 2026-09-02

### 🩹 Fixed

- `CANIC-122` permits the controller-authenticated, read-only
  `InspectCanister` Root command while the Root is `Prepared`. Pool-controller
  finalisation can therefore observe the exact temporary controller set and
  reconcile a lost controller response before Fleet activation; no other
  previously inactive Root command is widened.
- `CANIC-121` replaces the synthetic all-in-one qualification claim with two
  explicit production-boundary proofs. The host proof starts from a literal
  zero estate, applies the reviewed Fleet Ensure plan through PocketIC
  management effects, loses the first Create response, resumes the retained
  plan and journal through a reconstructed host adapter, converges and then
  replays with zero mutations. The separate control-plane proof inspects both
  sides of pool-controller finalisation through the real Prepared Root
  endpoint and reaches one Workload plus one Ready asset.
- `CANIC-123` seeds the generated pool-Ledger recovery helper from the exact
  consuming workspace lock before any infrastructure compilation. Cargo
  normalizes only that seeded graph offline; Canic reports every identity
  outside the workspace lock together and requires the result to resolve
  again under `--locked`. A compatible crate present only in a shared cache
  cannot silently enter the helper graph.

### 🧪 Testing

- Targeted ordinary tests cover exact helper-lock projection, a cache-free
  older-transitive seed and complete deterministic mismatch reporting.
- The governed host PocketIC proof covers literal-zero-estate plan, journal,
  lost-response, fresh-process resume, terminal conservation and immediate
  zero-effect replay. A separate governed control-plane proof covers the real
  Prepared Root and Component lifecycle, while the generated-helper proof
  retains exact withdrawal, replay and uninstall behavior.

## 0.110.0 - 2026-09-01

### 🩹 Fixed

- `CANIC-119` retains an applied fresh `Create` as exact nonterminal authority
  before later pool-controller finalization. The unchanged plan, journal and
  state bind the created Principal, live cycles and desired child topology;
  issued Creates cannot cross this boundary and exact replay cannot create or
  fund a second canister.
- `CANIC-120` separates a fresh pool's creation funding from its configured
  readiness floor. Generation includes the bounded first-observation and
  controller-effect burn ceilings, while immutable-plan policy and resume
  return exact requested, floor, burn, required and shortfall values before
  controller or protocol work when funding is insufficient.
- `CANIC-121` introduced the literal zero-estate Coordinator, Root, Store and
  two-pool journey. Its initial controller-finalisation fixture observed
  PocketIC directly after installing the Root; `0.110.2` replaces that
  incomplete boundary with the production Prepared-Root inspection ordering.

### 📊 Audit

- Freezes published `v0.109.35` as the reinstall-only predecessor for 0.110 and
  promotes `CANIC-WASM-001/v5`. The canonical audit binds optimizer metrics to
  one role-local build log rather than a disposable staged-artifact pathname.
- Two clean release builds and one debug build of every canonical role are
  retained with exact code-section, total-module, compressed, declared- and
  defined-function, export, table and optimizer metrics. Root remains the
  largest canonical role with 3,776,168 code-section bytes and 40,322 declared
  functions of headroom beneath the frozen IC limits.
- The exact downstream canary, controlled ablations, generated-surface
  inventory and generic-instantiation cohort remain B1 work for a later 0.110
  batch. This first release does not claim the complete 0.110 contraction or
  promote 0.111.

### ⚠️ Breaking

- 0.110 is a pre-1.0 reinstall-only hard cut. It does not import predecessor
  plans, journals, stable state, release authority or canister identity.
  Same-release interruption recovery, exact authority, bounded paid effects
  and cycle conservation remain mandatory.

### 🧪 Testing

- Targeted host regressions cover creation funding, exact pending topology,
  retained nonterminal balances, typed insufficient funding and effect-free
  replay.
- The initial targeted governed PocketIC journey covered the literal
  zero-estate Coordinator/Root/Store/two-pool path, terminal workload and Ready
  inventory, conservation and immediate replay. Prepared-Root controller
  observation is completed by the corrected `0.110.2` journey.
- The temporary pool-Ledger recovery helper resolves its standalone generated
  graph entirely within the governed workspace lock; the exact PocketIC
  withdrawal, replay and uninstall proof passes against that locked graph.
- The governed release flow owns the one complete workspace, feature, Candid,
  artifact and PocketIC validation pass for the immutable release candidate.
