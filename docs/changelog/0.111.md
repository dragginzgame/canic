# Canic 0.111 Changelog

## [0.111.0] - 2026-10-10

### ⚠️ Breaking contracts and upgrade actions

- **Memory pools:** Adopt Memory 0.35's key-only declarations and opens, using one
  artifact-owned pool with explicit framework/component namespace grants rather than
  numeric partitions. Retain key/ID bindings, composed admission and same-release
  recovery. ([#510 — Adopt host-wide allocation pools](https://github.com/dragginzgame/canic/issues/510))

- **Memory diagnostics:** Report the current pool and eligibility; state inventories
  carry permanent keys and resolve IDs from the protected ledger. Replace numeric range
  declarations with `memory_allocation_pool!`, rebuild diagnostic clients and cleanly
  reinstall across releases. ([#510 — Adopt host-wide allocation pools](https://github.com/dragginzgame/canic/issues/510))

- **Shared contracts:** Move canonical wire unions, bounded transport projections,
  passive DTOs, IDs, diagnostic codes and byte codecs to `canic-contracts`. Endpoint
  generation and fixtures share asynchronous acceptance, operation, funding, inventory
  and lifecycle declarations with explicit schema/decoding bounds. ([#354 — Extract canonical wire contracts](https://github.com/dragginzgame/canic/issues/354))

- **Storage boundaries:** Keep policy, compiled configuration, lifecycle, state, storage
  registration and effects with Core/Control Plane. Preserve fixed-width cycle bytes and
  CBOR template-key storage through owner-local records; passive values no longer
  implement stable-storage traits. ([#354 — Extract canonical wire contracts](https://github.com/dragginzgame/canic/issues/354))

- **Contract regeneration:** Publish Contracts before consumers, regenerate role Candid
  and refresh independent Blob locks and the embedded peer. Retire boxing-only mirrors
  and empty projection modules; the borrowed Store chunk encoder preserves the owned
  request without copying chunks. ([#354 — Extract canonical wire contracts](https://github.com/dragginzgame/canic/issues/354))

- **Contract upgrade:** Move direct DTO/ID/diagnostic/protocol imports from Core/Control
  Plane to Contracts and rebuild consumers. The maintainer selected 0.111 for the
  complete hard cut; clean reinstall preserves cycle custody and same-release recovery.
  ([#459 — Resolve the Memory ledger release boundary](https://github.com/dragginzgame/canic/issues/459))

- **Blob capacity:** Capacity replies distinguish tenant logical, global physical and
  global billing-liability headroom, with `remaining_bytes` as their minimum. Rebuild
  clients against canonical 0.21 contracts and reinstall across releases. ([#444 — Compose Blob as an App Component](https://github.com/dragginzgame/canic/issues/444))

- **Capacity coverage:** Dedicated and embedded cases cover distinct limits, tenant-only
  inspection, enrollment refusal and two-byte reservations. Retained observations
  survive same-release restoration and resumption. ([#33 — Qualify the shared timer dependency graph](https://github.com/dragginzgame/canic/issues/33))

- **Blob composition:** Adopt Blob runtime/contracts 0.22.1: `mount!()` registers
  permanent requests and the artifact grants the Blob namespace explicitly. Dedicated
  `canister!()` selects its pool; embedded hosts compose their application grant, remove
  numeric partitions and open committed keys. ([#444 — Compose Blob as an App Component](https://github.com/dragginzgame/canic/issues/444))

- **Blob contracts:** Import passive DTOs, upload context, completion authority,
  download scope and installation preflight from Contracts while runtime owns
  storage/workflow. Gate template chunk-set Store APIs with their existing Store/test
  methods for warning-denied Root declarations. ([#444 — Compose Blob as an App Component](https://github.com/dragginzgame/canic/issues/444))

- **Managed Blob artifacts:** Refresh all three locks with Memory 0.35 and the current
  runtime, including the pin exception. Build complete Apps; the embedded recipe omits
  the backend-only selector so artifacts include release identity and manifest. ([#444 — Compose Blob as an App Component](https://github.com/dragginzgame/canic/issues/444))

- **Blob uploader coverage:** Replace the installed single-uploader field with
  tenant-approved per-upload permissions and qualify two identities plus retained
  permissions after restoration. Both managed compositions borrow the caller-owned
  server; formatting covers their workspace-first manifests without provider uploads or
  a second process owner. ([#444 — Compose Blob as an App Component](https://github.com/dragginzgame/canic/issues/444))

- **Artifact publication:** IC Backup owns verified directory publication and lost-reply
  recovery, bound to the retained journal checksum. Conflicting destinations or changed
  staging bytes refuse; Canic retains process-death barriers before dispatch and after
  durable publication without advancing the journal. ([#394 — Live backup creation remains unavailable](https://github.com/dragginzgame/canic/issues/394))

- **Backup errors:** Directory publication failures expose the upstream cause through
  `PersistenceError::ArtifactCommit`; rebuild direct error matches. Filesystem fault
  injection stays upstream, and live Fleet capture still requires authority and
  consistency integration. ([#394 — Live backup creation remains unavailable](https://github.com/dragginzgame/canic/issues/394))

- **Upgrade action:** update contract imports, allocation-pool providers, Blob clients
  and error matches, then rebuild the complete family and cleanly reinstall across
  releases. Retain cycle custody and same-release recovery.

### 🔧 Startup, authentication and host behavior

- **Child startup:** Continue a known pending active-parent child startup through its
  retained operation without another create request. Preserve the child, original
  publication and request identity, retained retry time and authority expiry.
  Deduplicate automatic drivers and stop after sixteen consecutive failures or a
  permanent conflict/refusal; exact same-operation recovery remains available. Separate
  startup-pending diagnostics from publication, directory and readiness failures.
  Qualify actual asynchronous startup, changed-input refusal, automatic completion,
  same-release restart and terminal replay ([#505 — Resume child startup until readiness](https://github.com/dragginzgame/canic/issues/505)).

- **Auth contracts:** Adopt published IC Auth and protocol-types 0.3.6 for canonical
  certificate, token-claim, complete-proof, issuer-binding, role, batch-header,
  issuer-leaf and derivation-path identities. Replace eleven duplicate passive
  declarations with their canonical library owner. Project Fleet IDs byte-for-byte and
  validate roles without sorting or normalizing signed grants. Propagate fallible hashes
  through configuration, issuance, signing and verification instead of asserting vector
  lengths. Retain Canic's registry/key-policy framing and existing verification,
  certification and durable-session engines for their separate host adoption ([#491 — Extract shared authentication machinery](https://github.com/dragginzgame/canic/issues/491)).

- **Delegation installation:** Delegate issuer-local delegation installation to IC
  Auth's bounded standalone root-proof verifier, replacing the injectable verification
  callback. Supply protected issuer/key enrollment, clock and finite material/witness
  limits; retain network/key-name admission and strict installation not-before checks.
  Cap stored proof validity and refresh timing at the enrolled root-key deadline, and
  pass that deadline into token preparation without changing the signed certificate or
  its hash. Preserve typed endpoint refusal codes. Use real ECDSA signatures and
  Root-produced Merkle batches in the owning regressions; complete token
  verification/cache, certification and durable sessions retain their separate adoption
  boundary ([#491 — Extract shared authentication machinery](https://github.com/dragginzgame/canic/issues/491), [Auth #10 — Expose bounded delegation-proof verification before issuer token creation](https://github.com/dragginzgame/ic-auth/issues/10)).

- **Crypto inventory:** Include IC Auth's canister-signature verification dependencies
  in the chain-key Root crypto inventory: its bounded proof verifier currently selects
  the combined `token-verification` feature. Keep exact dependency identity,
  duplicate-version and zero-auth role checks in force ([#491 — Extract shared authentication machinery](https://github.com/dragginzgame/canic/issues/491)).

- **Merkle batches:** Delegate Root batch Merkle construction to IC Auth's bounded
  constructor. Keep authorized canonical leaves, deterministic issuer ordering,
  duplicate rejection, the 64-issuer budget, batch identity, signing and persistence in
  Canic. Odd-sized batches retain the existing signed proof format and pass the shared
  issuer installation verifier; over-budget construction refuses before tree allocation
  ([#491 — Extract shared authentication machinery](https://github.com/dragginzgame/canic/issues/491)).

- **Local Fleet capture:** Delegate local Fleet checkpoint response collection to Host's
  bounded reader. Preserve the 64 KiB ceiling, typed capacity refusal, original I/O
  causes, JSON/Deleted acknowledgement and existing timeout/server cleanup. Allocation
  failure is reported through the shared reader instead of an infallible buffer growth
  path. No lifecycle owner or dependency selection changes ([#458 — Adopt shared Host mechanics](https://github.com/dragginzgame/canic/issues/458)).

- **File observations:** Share build-input, frontend-file and local executable no-follow
  streaming hashes through Host's descriptor reader. Retain each caller's byte limits,
  exact-length checks, aggregate framing and typed early/streamed refusals; reject FIFOs
  without waiting for a writer. Use the upstream descriptor APIs ([#458 — Adopt shared Host mechanics](https://github.com/dragginzgame/canic/issues/458)).

- **Replica process ownership:** Replace foreground replica startup's private stderr
  reader/thread with Host communication and direct-child ownership. Preserve inherited
  or explicitly configured process groups, live diagnostics, unsuccessful-exit
  rendering, executable-busy retries and the existing absence of a deadline or
  output-based termination. Host 0.11 forwards every chunk while retaining only the
  first 64 KiB of stderr; failure messages identify truncated retained diagnostics.
  Terminal-write failure now terminates and reaps the direct child while retaining its
  native I/O cause and independent cleanup evidence. Descendant lifetime and paid-effect
  lock custody remain separate caller obligations ([#458 — Adopt shared Host mechanics](https://github.com/dragginzgame/canic/issues/458)).

- **JSON publication:** Delegate Backup's ordinary JSON create/replace publication to
  Host's durable engine. Retain serialization before filesystem effects, create-only
  conflicts, the existing umask-governed file mode and synchronized process-loss
  barriers. Keep `PersistenceError::Io` and its I/O kind; its source carries the shared
  typed before/after-publication failure, original native error and independent
  staging-cleanup evidence. Backup layouts and same-operation recovery remain
  Canic-owned; record reading retains its current contract ([#458 — Adopt shared Host mechanics](https://github.com/dragginzgame/canic/issues/458)).

- **Process output:** Use Host 0.12.1's per-stream output policies and optional
  deadlines; parser captures retain hard byte limits and finite deadlines and require
  complete evidence. Read secondary execution failures through the shared cleanup
  record, preserving the original failure independently ([#458 — Adopt shared Host mechanics](https://github.com/dragginzgame/canic/issues/458)).

- **Backup paths:** Resolve operator-selected Backup directory aliases through Host
  before durable JSON publication, preserving no-follow admission for the output leaf
  and snapshot artifacts. Retain native path errors and serialization-before-effect
  behavior ([#394 — Live backup creation remains unavailable](https://github.com/dragginzgame/canic/issues/394)).

### 🔧 Blob packaging and release inputs

- **Consumer locks:** Prepare and roll back root-owned package versions in both private
  Blob consumer locks with the root release transaction. Keep fixture versions and
  external dependency selections unchanged; release-content admission verifies the exact
  projected lock bytes before publication ([#33 — Qualify the shared timer dependency graph](https://github.com/dragginzgame/canic/issues/33), [#444 — Compose Blob as an App Component](https://github.com/dragginzgame/canic/issues/444)).

- **Runtime graph:** Propagate the owner-selected Blob 0.22 and applicable runtime
  patches into the root and two consumer locks; align the adapter's required
  Host/Testkit tooling. Use Host's current typed write API in Host, Backup and CLI,
  retaining publication-phase, native-cause and cleanup evidence. Host/CLI producer and
  visible-publication failures cannot masquerade as ordinary create conflicts ([#33 — Qualify the shared timer dependency graph](https://github.com/dragginzgame/canic/issues/33), [#444 — Compose Blob as an App Component](https://github.com/dragginzgame/canic/issues/444)).

- **Adapter publication:** Join the thin Blob adapter to the main workspace. Inherit
  service dependencies, Canic requirements and package version from the root catalog;
  include the adapter in dependency-ordered family publication after the facade. Keep
  both application consumers independent and provider/service tests upstream. Users opt
  into the published adapter and its dedicated or embedded composition APIs ([#444 — Compose Blob as an App Component](https://github.com/dragginzgame/canic/issues/444)).

- **Consumer MSRV:** Lower the independent Blob adapter, dedicated consumer and embedded
  consumer Rust declarations from 1.99 to Canic's 1.91.0 floor. Retain their independent
  catalogs and reconcile local Canic lock entries with the current 0.110.54 workspace
  ([#495 — Qualify Blob consumer MSRV](https://github.com/dragginzgame/canic/issues/495)).

- **Composition guidance:** Correct the composition guide's selected dependency graph
  and describe current browser-uploader, gateway callback, verifier, controller
  initialization and provider-funding boundaries for per-project consumers ([#444 — Compose Blob as an App Component](https://github.com/dragginzgame/canic/issues/444)).

### 🔧 Contributor tools and validation

- **Selected Testkit:** Select the framework's published Testkit runner directly from
  the root Cargo lock, keeping setup and offline admission on the same exact version
  without a second tool pin. Refuse missing, ambiguous or unpublished selections before
  installer dispatch. Keep setup explicit and offline checks free of downloads ([#33 — Qualify the shared timer dependency graph](https://github.com/dragginzgame/canic/issues/33)).

- **PocketIC runner:** Testkit replaces Canic's binary pins, admission, launcher, port
  polling and process-scanning teardown. Its CLI owns serial commands and worker
  attempts; Canic retains compile/fixture barriers, ordered cases, complete server files
  and successful scratch cleanup. ([#498 — Unify PocketIC client/server ownership](https://github.com/dragginzgame/canic/issues/498))

- **Borrowed servers:** Managed fixtures consume only `IC_TESTKIT_POCKET_IC_URL` and use
  the shared startup error. Prepare explicitly with `make install-ic-tools
  install-testkit-server`; offline checks never install, and old bundles/receipts remain
  retained. ([#501 — Use the Testkit runner server URL](https://github.com/dragginzgame/canic/issues/501))

- **Hooks and exceptions:** The isolated-index hook selects original-checkout tools, and
  dependency exceptions require one JSON document. These contributor changes preserve
  selected file/hook authority. ([#454 — Isolate pre-commit formatting](https://github.com/dragginzgame/canic/issues/454)) ([#503 — Validate dependency-exception catalogs](https://github.com/dragginzgame/canic/issues/503))

- **Shared setup:** Adopt Shared Tooling 0.3.8 and Host 0.12.7, with standard release
  recipes and ordered host/IC/Cargo setup. Canic runs its Testkit extension after common
  sets even under parallel Make, retiring duplicated aggregate prerequisites and
  optional selections. ([#461 — Adopt common setup and verification](https://github.com/dragginzgame/canic/issues/461))

- **Setup admission:** Admit platform and Rust/Cargo prerequisites before downloads,
  preserve the jobserver and require explicit fixture/validation completion. Reject
  unsafe Make execution modes even if callers replace flags. ([#461 — Adopt common setup and verification](https://github.com/dragginzgame/canic/issues/461))

- **Formatting output:** Wrap Canic's workspace formatter sequence in the shared
  reporter, retaining failure logs and concise output. Ordinary checks perform no
  implicit installation. ([#461 — Adopt common setup and verification](https://github.com/dragginzgame/canic/issues/461))

- **CI diagnostics:** Report unavailable failed-step logs instead of treating incomplete
  observations as successful inspection. ([Shared #97 — Report unavailable failed-step CI logs](https://github.com/dragginzgame/shared-tooling/issues/97))

- **Release tool preparation:** After locked cache preparation, release preflight
  prepares the selected tools and checks them offline; standalone complete validation
  begins with offline checks. The shared Cargo installer owns lock-selected Testkit
  admission and installation drift. ([Shared #96 — Prepare selected Cargo CLIs before validation](https://github.com/dragginzgame/shared-tooling/issues/96)) ([Shared #109 — Qualify current workspace archives](https://github.com/dragginzgame/shared-tooling/issues/109))

- **Hook failures:** Carry failed Git-tree observations through Canic's isolated-index
  hook before any refresh or staging. Bash 3.2 installer, custom hook and Make-recipe
  assertions fail explicitly and retain evidence. ([Shared #107 — Fail portable assertions explicitly](https://github.com/dragginzgame/shared-tooling/issues/107))

- **Binaryen bundles:** Align Canic's Binaryen executable/library admission with the
  shared 133 archive catalog on Linux and both macOS architectures. Preserve earlier
  prepared bundles. ([#461 — Adopt common setup and verification](https://github.com/dragginzgame/canic/issues/461))

- **Macro hygiene:** Preserve `$crate` hygiene in exported Root and managed wire derives
  across formatting. Exclude only those macro definitions from the pinned derive
  sorter's unsafe rewrite; ordinary formatting remains enabled ([Shared #113 — Preserve $crate in derive formatting](https://github.com/dragginzgame/shared-tooling/issues/113)).

- **Report checksums:** Delegate ordinary file SHA-256 in capability, footprint and
  ablation reports to the reviewed Shared Tooling checksum helper. Keep decoded-stream,
  composite, Git-diff and execution-path identities under their existing owners. The
  capability report accepts the helper's `shasum` backend; footprint and ablation still
  require `sha256sum` for their distinct stream hashes. Include the helper in footprint
  method identity and retained ablation method files ([#471 — Delegate Wasm report file digests to the shared checksum helper](https://github.com/dragginzgame/canic/issues/471)).

- **CI time limits:** Let CI builds, test jobs and Cargo-based tool setup use GitHub
  Actions' default job limit instead of short per-job caps. Keep validation
  dependencies, credentials, pinned actions and failure evidence collection unchanged.

- **CI supersession:** Keep only the newest CI run per workflow and branch or PR,
  cancelling older queued and running checks while retaining the existing host matrix
  and gates ([Shared #108 — Keep only the newest CI run](https://github.com/dragginzgame/shared-tooling/issues/108)).

- **Qualification fixtures:** Prepare generated audit packages before parallel PocketIC
  artifact acquisition, drive bounded charging rounds when qualifying stopped-canister
  rent, and admit the fixture invocation's prepared optimizer against the production
  tool pins ([#511 — Remove fixture nondeterminism from governed PocketIC release qualification](https://github.com/dragginzgame/canic/issues/511)).

### 🩹 Registry, observations and interrupted workers

- **Registry admission:** Use Shared Tooling's exact present/absent/unavailable registry
  observer for publication admission, propagation and final completeness checks. Attempt
  an upload only after definite absence; an unavailable lookup stops the flow with
  retained stage logs. Explicit Cargo offline policy refuses registry admission.
  Preserve package order, dry runs and predecessor checks for resumed publication ([#462 — Stop publication when registry version lookup is unavailable](https://github.com/dragginzgame/canic/issues/462)).

- **Observation capabilities:** Use the retained protocol binding's separate Metrics and
  History capabilities before Observatory dispatch. Unsupported selectors return the
  existing typed `Unsupported` observation without a metric query or version probe.
  Coordinator collection skips its application-metric request and all four cost
  requests; its protected Funding status remains independent. Configured Components use
  their declared capabilities rather than a copied role list ([#439 — Use declared Coordinator observation capabilities](https://github.com/dragginzgame/canic/issues/439)).

- **Worker interruption:** On worker interruption, let the Testkit owner finish
  command/server cleanup before releasing scratch; retain unsuccessful attempts and
  complete output. Recognize Canic's configured compiler wrapper in cache-delta
  reporting ([#498 — Unify PocketIC client/server ownership](https://github.com/dragginzgame/canic/issues/498)).

- **Embedded fixture:** Refresh the embedded allocation peer and its provenance together
  for the newly selected root runtime graph. Keep ordinary verification read-only and
  retain its stale-byte refusal before managed installation qualification ([#444 — Compose Blob as an App Component](https://github.com/dragginzgame/canic/issues/444)).

- **Feature boundaries:** Compile Fleet-admission snapshot descriptors only for
  Root/Store, their actual consumers. Remove stale Coordinator-only dead-code
  expectations that reject the generated Coordinator at Rust 1.91 with warnings denied.
  Retain the stable admission record, state-contract names and runtime schema unchanged.
  Gate Root-only registry imports to prevent Store-only warning-denied build failure and
  scope the registry enum size expectation to native 64-bit targets, where that lint
  actually fires ([#495 — Qualify Blob consumer MSRV](https://github.com/dragginzgame/canic/issues/495)).
