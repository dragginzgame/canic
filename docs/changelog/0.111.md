# Canic 0.111 Changelog

## [0.111.0]

### Changed

- Prepare and roll back root-owned package versions in both private Blob consumer
  locks with the root release transaction. Keep fixture versions and external
  dependency selections unchanged; release-content admission verifies the exact
  projected lock bytes before publication
  ([#33](https://github.com/dragginzgame/canic/issues/33),
  [#444](https://github.com/dragginzgame/canic/issues/444)).

- Continue a known pending active-parent child startup through its retained
  operation without another create request. Preserve the child, original
  publication and request identity, retained retry time and authority expiry.
  Deduplicate automatic drivers and stop after sixteen consecutive failures
  or a permanent conflict/refusal; exact same-operation recovery remains
  available. Separate startup-pending diagnostics from publication, directory
  and readiness failures. Qualify actual asynchronous startup, changed-input
  refusal, automatic completion, same-release restart and terminal replay
  ([#505](https://github.com/dragginzgame/canic/issues/505)).

- Adopt published Memory 0.35's key-only declarations and opens. Select one
  artifact-owned allocation pool with explicit framework and component namespace
  grants; share physical allocation eligibility instead of numeric owner
  partitions. Preserve retained key/ID bindings, composed admission and
  same-release recovery. Diagnostics report the current pool and eligibility;
  static state inventories carry permanent keys and resolve observed IDs from
  the protected ledger. **Breaking:** replace numeric range declarations with
  `memory_allocation_pool!` and rebuild diagnostic clients for the current
  contracts. Cross-release deployment requires clean reinstall
  ([#510](https://github.com/dragginzgame/canic/issues/510)).

- Extract canonical wire unions, bounded transport projections, passive DTOs,
  shared IDs, diagnostic codes and byte codecs into `canic-contracts`. Endpoint
  generation and in-repository callers share the declarations; retained narrow
  transports have explicit schema/decoding bounds and compatibility coverage.
  Remove repeated production and fixture projections, including boxing-only
  mirrors; share asynchronous acceptance, operation reads, funding, inventory
  and lifecycle selectors directly. Move remaining unique fixture transports
  to the same owner and retire empty projection modules.
  Keep policy, compiled configuration, lifecycle, state, storage registration
  and platform effects with Core and Control Plane. Preserve fixed-width cycle
  bytes and CBOR template-key storage through owner-local records. Passive
  values no longer implement stable-storage traits; storage owners provide records. Publish the
  contract package before its consumers. Refresh generated role Candid,
  independent Blob locks and the embedded allocation peer; qualify the borrowed
  Store chunk encoder against the owned request without copying chunk bytes.
  **Breaking direct Rust paths:** shared
  DTO/ID/diagnostic/protocol imports move from Core/Control Plane to Contracts;
  rebuild consumers against the shared owner. The maintainer selected 0.111
  for the complete hard-cut batch; clean reinstall is required across releases,
  preserving cycle custody and same-release recovery
  ([#354](https://github.com/dragginzgame/canic/issues/354),
  [#459](https://github.com/dragginzgame/canic/issues/459)).

- Delegate local Fleet checkpoint response collection to Host's bounded reader.
  Preserve the 64 KiB ceiling, typed capacity refusal, original I/O causes,
  JSON/Deleted acknowledgement and existing timeout/server cleanup. Allocation
  failure is reported through the shared reader instead of an infallible buffer
  growth path. No lifecycle owner or dependency selection changes
  ([#458](https://github.com/dragginzgame/canic/issues/458)).

- Adopt published IC Auth and protocol-types 0.3.5 for canonical certificate,
  token-claim, complete-proof, issuer-binding, role, batch-header, issuer-leaf and
  derivation-path identities. Replace eleven duplicate passive declarations with
  their canonical library owner. Project Fleet IDs byte-for-byte and validate
  roles without sorting or normalizing signed grants. Propagate fallible hashes
  through configuration, issuance, signing and verification instead of asserting
  vector lengths. Retain Canic's registry/key-policy framing and existing
  verification, certification and durable-session engines for their separate
  host adoption ([#491](https://github.com/dragginzgame/canic/issues/491)).
- Delegate issuer-local delegation installation to IC Auth's bounded standalone
  root-proof verifier, replacing the injectable verification callback. Supply
  protected issuer/key enrollment, clock and finite material/witness limits;
  retain network/key-name admission and strict installation not-before checks.
  Cap stored proof validity and refresh timing at the enrolled root-key deadline,
  and pass that deadline into token preparation without changing the signed
  certificate or its hash. Preserve typed endpoint refusal codes. Use real
  ECDSA signatures and Root-produced Merkle batches in the owning regressions;
  complete token verification/cache, certification and durable sessions retain
  their separate adoption boundary
  ([#491](https://github.com/dragginzgame/canic/issues/491),
  [IC Auth #10](https://github.com/dragginzgame/ic-auth/issues/10)).
- Delegate Root batch Merkle construction to IC Auth's bounded constructor.
  Keep authorized canonical leaves, deterministic issuer ordering, duplicate
  rejection, the 64-issuer budget, batch identity, signing and persistence in
  Canic. Odd-sized batches retain the existing signed proof format and pass
  the shared issuer installation verifier; over-budget construction refuses
  before tree allocation ([#491](https://github.com/dragginzgame/canic/issues/491)).
- Select the framework's published Testkit runner directly from the root Cargo
  lock, keeping setup and offline admission on the same exact version without
  a second tool pin. Refuse missing, ambiguous or unpublished selections before
  installer dispatch.
  Keep setup explicit and offline checks free of downloads
  ([#33](https://github.com/dragginzgame/canic/issues/33)).
- Share build-input, frontend-file and local executable no-follow streaming
  hashes through Host's descriptor reader. Retain each caller's byte limits,
  exact-length checks, aggregate framing and typed early/streamed refusals;
  reject FIFOs without waiting for a writer. Use the upstream descriptor APIs
  ([#458](https://github.com/dragginzgame/canic/issues/458)).
- Replace foreground replica startup's private stderr reader/thread with Host
  communication and direct-child ownership. Preserve inherited or explicitly
  configured process groups, live diagnostics, unsuccessful-exit rendering,
  executable-busy retries and the existing absence of a deadline or output-based
  termination. Host 0.11 forwards every chunk while retaining only the first
  64 KiB of stderr; failure messages identify truncated retained diagnostics.
  Terminal-write failure now terminates and reaps the direct child while
  retaining its native I/O cause and independent cleanup evidence. Descendant
  lifetime and paid-effect lock custody remain separate caller obligations
  ([#458](https://github.com/dragginzgame/canic/issues/458)).
- Delegate Backup's ordinary JSON create/replace publication to Host's durable
  engine. Retain serialization before filesystem effects, create-only conflicts,
  the existing umask-governed file mode and synchronized process-loss barriers.
  Keep `PersistenceError::Io` and its I/O kind; its source carries the shared
  typed before/after-publication failure, original native error and independent
  staging-cleanup evidence. Backup layouts and same-operation recovery remain
  Canic-owned; record reading retains its current contract
  ([#458](https://github.com/dragginzgame/canic/issues/458)).
- Delegate verified artifact-directory publication and lost-reply recovery to
  IC Backup's public owner. Keep the canonical tree bound to the retained
  journal checksum, refuse conflicting destinations and changed staging bytes,
  and retain Canic's process-death proofs before dispatch and after durable
  publication without advancing the journal. Low-level filesystem fault
  injection belongs to IC Backup. **Breaking Rust error matching:** directory
  publication failures now carry IC Backup's typed cause through
  `PersistenceError::ArtifactCommit`; rebuild matches against that owner.
  Live Fleet capture still requires the authority and consistency adapter
  ([#394](https://github.com/dragginzgame/canic/issues/394)).
- Delegate ordinary file SHA-256 in capability, footprint and ablation reports
  to the reviewed Shared Tooling checksum helper. Keep decoded-stream,
  composite, Git-diff and execution-path identities under their existing owners.
  The capability report accepts the helper's `shasum` backend; footprint and
  ablation still require `sha256sum` for their distinct stream hashes. Include
  the helper in footprint method identity and retained ablation method files
  ([#471](https://github.com/dragginzgame/canic/issues/471)).
- Let CI builds, test jobs and Cargo-based tool setup use GitHub Actions' default
  job limit instead of short per-job caps. Keep validation dependencies,
  credentials, pinned actions and failure evidence collection unchanged.
- Adopt Shared Tooling 0.3.8 through its committed snapshot and select the published
  IC Host 0.12.7 family. Share standard release
  recipes and ordered complete host/IC/Cargo-tool setup. Run Canic’s Testkit
  extension after the common sets, including under parallel Make; remove
  duplicated aggregate prerequisites and optional host-tool selections. Admit
  platform and Rust/Cargo prerequisites before downloads, preserve the Cargo
  jobserver and require explicit fixture/validation completion. Share
  Make admission, rejecting unsafe execution modes even when callers
  replace flags. Wrap Canic's workspace formatter sequence in the
  shared reporter, retaining failure logs and concise output. Report unavailable
  failed-step CI logs instead of silently accepting incomplete observations.
  After locked cache preparation, release preflight prepares the selected tools
  and checks them offline before validation; standalone complete validation starts
  with offline checks. Delegate lock-selected Testkit admission and installation
  drift checks to the shared Cargo installer. Carry failed Git tree observations
  through Canic's isolated-index hook before any file refresh or staging. Align
  Canic's exact Binaryen executable/library admission with the shared 133 archive
  catalog on Linux and both macOS architectures; retain earlier prepared bundles.
  Stop mandatory installer and fixture assertions explicitly on Bash 3.2, including
  Canic's custom hook and Make-recipe fixtures; retain failed-check evidence.
  Keep ordinary checks free of implicit installation
  ([#461](https://github.com/dragginzgame/canic/issues/461),
  [Shared #96](https://github.com/dragginzgame/shared-tooling/issues/96),
  [Shared #97](https://github.com/dragginzgame/shared-tooling/issues/97),
  [Shared #107](https://github.com/dragginzgame/shared-tooling/issues/107),
  [Shared #108](https://github.com/dragginzgame/shared-tooling/issues/108),
  [Shared #109](https://github.com/dragginzgame/shared-tooling/issues/109)).
- Use Host 0.12.1's per-stream output policies and optional deadlines; parser captures
  retain hard byte limits and finite deadlines and require complete evidence.
  Read secondary execution failures through the shared cleanup record, preserving
  the original failure independently
  ([#458](https://github.com/dragginzgame/canic/issues/458)).
- Propagate the owner-selected Blob 0.22
  and applicable runtime patches into the root and two consumer locks; align
  the adapter's required Host/Testkit tooling. Use Host's
  current typed write API in Host, Backup and CLI, retaining publication-phase,

### Fixed

- Use Shared Tooling's exact present/absent/unavailable registry observer for
  publication admission, propagation and final completeness checks. Attempt an
  upload only after definite absence; an unavailable lookup stops the flow with
  retained stage logs. Explicit Cargo offline policy refuses registry admission.
  Preserve package order, dry runs and predecessor checks for resumed publication
  ([#462](https://github.com/dragginzgame/canic/issues/462)).
- Use the retained protocol binding's separate Metrics and History capabilities
  before Observatory dispatch. Unsupported selectors return the existing typed
  `Unsupported` observation without a metric query or version probe. Coordinator
  collection skips its application-metric request and all four cost requests;
  its protected Funding status remains independent. Configured Components use
  their declared capabilities rather than a copied role list
  ([#439](https://github.com/dragginzgame/canic/issues/439)).
- On worker interruption, let the Testkit owner finish command/server cleanup
  before releasing scratch; retain unsuccessful attempts and complete output.
  Recognize Canic's configured compiler wrapper in cache-delta reporting
  ([#498](https://github.com/dragginzgame/canic/issues/498)).
- Refresh the embedded allocation peer and its provenance together for the
  newly selected root runtime graph. Keep ordinary verification read-only and
  retain its stale-byte refusal before managed installation qualification
  ([#444](https://github.com/dragginzgame/canic/issues/444)).
- Compile Fleet-admission snapshot descriptors only for Root/Store, their actual
  consumers. Remove stale Coordinator-only dead-code expectations that reject
  the generated Coordinator at Rust 1.91 with warnings denied. Retain the stable
  admission record, state-contract names and runtime schema unchanged. Gate
  Root-only registry imports to prevent Store-only warning-denied build failure
  and scope the registry enum size expectation to native 64-bit targets, where
  that lint actually fires
  ([#495](https://github.com/dragginzgame/canic/issues/495)).
