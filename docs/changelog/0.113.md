# Canic 0.113 Changelog

## [0.113.0]

### Added

- Canic-owned metrics storage policy defaults to heap and permits explicit stable
  overrides per registered provider in each component/child metrics table. One
  governed map per canister uses published Persistence codecs; heap-only roles
  allocate no metrics store. Fixed rosters, units and overflow quality survive
  reporting, with missing retained records refused instead of reset.
- The Blob adapter observes admission/reference RPC attempts, outcomes, exact
  replays, bytes and workflow instructions. Existing authoritative gauges and
  public Application family publication remain with their current owners.

### Changed

- Potentially breaking: metrics configuration, runtime construction and deployment
  authority include storage policy. Rebuild all managed artifacts and follow the
  pre-1.0 clean-reinstall release boundary. Same-release reopen retains stable
  observations and resets heap observations, with a new platform comparison
  window. Snapshot rollback is not a promise of lifetime continuity. No runtime
  storage switch or automatic migration is introduced.

### Testing

- Add native mixed-provider, bounded-roster, overflow, malformed/missing retained
  data and storage-refusal checks. Dedicated and embedded managed Blob builds
  qualify heap/stable upgrade behavior and replay-aware public observations.
