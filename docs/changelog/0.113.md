# Canic 0.113 Changelog

## [0.113.0]

### 🩹 Fixed

- Ordinary CI prepares and admits the existing pinned release metadata editor
  before release-flow fixtures, independently of other jobs' tool installations.
  The workflow regression executes the actual setup body and checks installation
  failure propagation. Tool-store ownership and physical-path admission stay strict.
- Manifest validation creates its FIFO with the portable host command already
  used by other filesystem tests. Keep directory/FIFO refusal and explicit alias
  assertions; avoid the unavailable macOS `rustix::fs::mkfifoat` test API.
- Regenerate the embedded allocation peer and structured provenance through the
  existing generator after source/dependency adoption. Ordinary verification stays
  read-only and rejects mismatched executable bytes; no fixture gate is bypassed.

### 🔧 Changed

- Standardize adapter endpoint composition on `mount!`; rename IcyDB’s
  `endpoints!` without a compatibility alias. Add an unpublished `canic-auth`
  scaffold with compile-time mounting refusal and explicit integration obligations.
  The IcyDB public macro rename requires the selected minor release boundary.

- Remove Canic’s ten ICRC-21 consent DTO mirrors and use published Platform
  identities directly in the dispatcher, generated endpoint and consumer tests.
  Remove `canic::dto::icrc21`; consumers import
  `ic_platform::icrc_ledger_types::icrc21`. Required external Candid encoding
  and consent dispatch behavior remain unchanged.

- Move the Blob adapter to `crates/canic-blob-service`, alongside `canic-icydb`.
  Keep independent consumer fixtures under `integrations/blob-service` and update
  their package paths; standardize adapter placement in AGENTS.md.

- Share cycle-report columns, alignment and the seven-cell row prefix between
  normal and verbose tables. Preserve spacing, missing-value markers and
  verbose-only history/top-up/net fields
  ([#693](https://github.com/dragginzgame/canic/issues/693)).

- Delegate generic call request custody, execution and cost calculation to
  published `ic-call` 0.7.3 through Platform's existing runtime. Remove Canic's
  duplicated transport fields, wait enum and cost formula. Preserve owned method
  names, borrowed/owned raw payloads, external Candid helpers, the explicit
  300-second bounded default, attachment replacement and typed transport errors.
  Metrics, authentication, spending authority and uncertain-effect recovery stay
  with Canic. Align both private consumer locks with required Platform 0.7.3 and
  Wire 0.7.19; no second executor or automatic retry is introduced.

- Add `canic-icydb` as a publishable Canic adapter without an IcyDB runtime
  dependency. It owns fixed Wire endpoint identities, endpoint authorization,
  Platform-backed entropy and provider-owned timer scheduling. Explicit managed
  mounts reuse Canic admission; standalone mounts retain native exports.
- Managed participant configuration supplies the host, memory composition and
  committed runtime together, automatically wiring both lifecycle hooks. Canic
  shares its exact committed Memory instance and uses the provider’s verification
  for repeated bootstrap. Package admission allows only the matching adapter
  release to share the facade’s exact procedural-macro package; other protected
  paths and duplicate runtime identities remain rejected.


- Adopt published Auth 0.19.5, Backup 0.48.2, Blob/contracts 0.53.0, Timers 0.31.16,
  Wire/derive 0.7.20, Query 0.75.5 and Host/Build/Testkit 0.69.7. The latest
  Auth/Wire/Timers patches preserve runtime source and protocol contracts; Auth's
  qualification-only Memory 0.53 dependency does not enter Canic's graph.
  Refresh the embedded allocation peer and provenance for the selected graph.
  Align both private consumer lockfiles and
  select the 0.69.7 release metadata editor through its existing installer. Tooling
  includes the upstream macOS mode-type fix and build-input observation reuse;
  Canic retains its source invalidation and artifact admission checks. Blob
  0.52 removes journaled read configuration/status and changes storage layout;
  fixtures use the current Wire contracts and supplier-owned installation grants.
  Retain authorization, funding/gateway fences and same-release recovery. This
  dependency hard cut requires retirement/reinstall at the selected release
  boundary, preserving controlled cycles and uncertain provider obligations.
- Adopt Memory/Storage 0.53.0 together with Blob 0.53.0, preserving one
  runtime identity and exclusive backing custody. Custom fixture backings delegate
  their physical identity; retained handles prevent reopening until the final lease
  is released. Full validation occurs at construction, bootstrap, lease opening
  and growth; ordinary reads and writes do not rescan manager metadata.
- Refresh Shared Tooling 0.27.3 from reviewed upstream revision
  `7ee5c83744aa822ecd070703dbf0a7d95076d5f6` through the canonical exporter.
  Verify its independently selected source and use its companion-closure owner
  in Canic’s formatter fixture, including the new RustSource helper. Remove the
  duplicated Canic sccache pin: Make, preparation, installers and developer setup
  consume the shared catalog’s 0.19.0 pin and archive checksum. Existing wrapper,
  runtime isolation, managed destination and explicit override admission remain.

- Extend timer ownership inventory to maintained integration sources and manifests,
  excluding generated build output and tool directories. Confirm timer and Blob
  engine ownership with focused managed runtime checks; correct Blob adapter
  documentation to describe the completed schema producer and release hash binding.

- **Breaking:** replace `canic_query`, `canic_update`, `canic_raw_query` and
  `canic_raw_update` with `query`, `update`, `raw_query` and `raw_update`.
  Update consumer imports and attributes; no aliases remain. `query` and
  `update` require `wire(id = ID, request = LIMITS, response = LIMITS)` and
  use IC Wire codecs and schema registration. Existing Wire IDs, budgets,
  framing and access behavior remain unchanged. Required external Candid
  protocols use explicit `candid_query`/`candid_update` adapters; raw adapters
  retain their codec owner and explicit IO bounds. Framework emitters, Blob
  adapters, consumer fixtures, package generators and active examples use the
  new names. This public API hard cut is grouped into the 0.113.0 minor release.

- Core management calls use IC Platform's settings, status, installation and
  signing contracts. ICP refill and Cycles Ledger creation/transfer consume the
  supplier's request and result types, and frontend upload readback uses its
  certified-asset contracts. Remove the replaced local Candid DTOs and route
  pool-refill result classification directly through the upstream types.
  Canic retains controller selection, exact retry identities, spending permits,
  refund/uncertainty decisions and its own settings/report projections. Newly
  available optional settings remain unset; external protocols remain Candid.
  Extend this adoption to host/local Cycles Ledger creation and withdrawal,
  controller handoff and uninstall, NNS subnet lookup, ICP mint transfers and
  CMC replies, certified ledger/archive receipts and management-history evidence.
  Remove the replaced local contract modules; retain Canic receipt verification
  and exact actor/controller/version/hash checks. Generic codec extraction remains
  tracked by [Platform #78](https://github.com/dragginzgame/ic-platform/issues/78),
  [#79](https://github.com/dragginzgame/ic-platform/issues/79) and the
  [ICC owner #75](https://github.com/dragginzgame/ic-platform/issues/75); the owned
  retirement-drain Wire migration remains under
  [Canic #613](https://github.com/dragginzgame/canic/issues/613).
  This is not Candid-free completion.
- Withhold the Shared release runner's source/destination/version/phase variables
  from both compiler children and artifact input fingerprints through the existing
  Host environment owner, also consumed by internal PocketIC artifact preparation.
  Explicit artifact identity, source, package versions, configuration, compiler
  settings and unknown build inputs remain bound. The regression exercises actual
  Cargo/build scripts and artifact admission; qualification and test results are
  never cached by this change. Per-call launcher IDs and verified helper-only
  PATH directories are also removed from children and fingerprints; normal,
  unknown and symlinked tool directories stay effective inputs. The real-Cargo
  regression varies helper directories and verifies that build scripts cannot
  observe them, while retaining source/configuration/dependency invalidation.
  Default PocketIC tool selection uses the verified managed ICP directory instead
  of generating a new PATH alias per invocation. Explicit binary overrides retain
  private single-tool isolation and exact native/version checks.
- Compile and verify each serial test inventory with one Cargo `--list` command
  in the existing complete/PocketIC preparation barrier. Remove the redundant
  preceding `--no-run` invocation; preserve exact selectors, nonempty admission,
  complete failure logs and the all-suites-before-server ordering. Narrow lanes
  retain their existing coverage.
