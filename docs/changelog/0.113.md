# Canic 0.113 Changelog

## [0.113.0] - 2026-10-30

- **Breaking — Wire storage hard cut:** replace the owned stable-record and
  checkpoint CBOR encoder, custom `u128` serializer and intermediate decoding tree
  with bounded native IC Wire. Admit the `CSW\x01` storage identity before record
  decoding; retain narrower per-record ceilings under a 64 MiB value ceiling,
  1 GiB traversal allocation allowance, 64 Mi nodes and depth 128.
  Store observed arbitrary-precision ICP-refill amounts with upstream `BigUint`
  Serde, preserving exact overflow evidence and the existing checked `u128` admission.
  Persist replayed refill replies through the existing lossless Wire funding projection.
  Checkpoint authority/unit, caller publication/census and completed-subtree receipt
  commitments use `protocol::authority` native bytes and explicit `.wire.v1` domains.
  Update their producers and validators together, independently of storage framing.
  Dedicated Fleet activation commitments and release-build CBOR evidence retain
  their formats. Deploy by clean reinstall; same-release restoration and uncertain
  operation recovery retain the current records.

- Complete IC Build staging adoption for configured and infrastructure artifacts,
  removing the private staging allocator and Wasm copy helper. Retain one upstream
  capture through transforms, contract checks and qualified publication. Bind the
  actual shared Cargo library recipe into complete-build and export identities;
  observe external workspace catalogs and Cargo configuration includes through
  IC Build before granting reuse, preserving typed missing/invalid refusals and
  late-input rejection. Existing cache records remain retained without fallback
  readers or pruning. Canic retains source custody, transform policy and release
  manifest admission ([#529](https://github.com/dragginzgame/canic/issues/529),
  [#530](https://github.com/dragginzgame/canic/issues/530)).

- Integrate #708's provider metrics API with published Metrics Stable 0.56.0 and
  the current Blob adapter location. Default to heap; compile explicit stable
  overrides into role authority and admit one shared governed map before use.
  Register fixed provider rosters synchronously, reopen retained counters before
  deferred work and expose replay-aware Blob observations through the existing
  application cache. Keep publication and controller-only diagnostics independent
  of storage selection. Cross-release deployment remains clean reinstall.

- **Breaking — Backup hard cut:** remove `canic-backup` and the old backup/restore
  CLI, including private plans, manifests, journals and command runner. Remove
  workspace, package and CI wiring; retain the Host adapter over IC Backup 0.50.2.
  Live backup and restore are unavailable until the thin production integration
  is qualified. Retained operation data and historical evidence are untouched.

- Adopt published IC Backup/Agent 0.50.2 operator composition. Use upstream
  bounded advancement and original-journal inspection in checkpoint qualification,
  preserving mandatory admission, lost-reply recovery and effect-free replay.
  Live operations remain unavailable after the approved CLI hard cut.

- Bind Root checkpoint begin to the intended complete unit and reject mismatch
  before state mutation. Use Backup's opaque payload digest and original typed
  mutation/observation requests, preserving workflow/context and original budgets.
  Add a Host Agent adapter over the published single-submit owner with mandatory
  fresh admission and ingress/reply retention callbacks. Retention refusal leaves
  original spending pending and cannot authorize another send. Remove unused
  Backup discovery errors from list, metrics and cycles CLI commands.

- **Breaking — runtime logs:** use published IC Logging for bounded heap history,
  filtering and retention. Remove the private stable log store and its memory/state
  declarations. Log history resets on upgrade or reinstall; Canic retains query
  authorization, Wire response shapes, configuration and retention scheduling.

- Adopt published IC Backup 0.50.2 through the root dependency catalog and lock.
  Keep original attempt accounting and lost-update reconciliation unchanged.
  Match the upstream observation mode with controller-protected read-only status
  updates, their replay classification, Host commitment and installed callers.
  Observation spending remains separate from mutation spending; repeated status
  reads do not advance the checkpoint or participants. Production transport
  integration and live capture remain separate unfinished work.

- Move original checkpoint lost-update reconciliation into the Host adapter.
  Bind status observations to their original workflow/update/attempt and retain
  IC Backup's finite observation allowance. Missing, stale, foreign or
  unqualified replies preserve pending uncertainty without mutation redispatch.

- Integrate original Root checkpoint preparation under `canic-host::backup`,
  using IC Backup's workflow/stage/attempt coordinator. Share checkpoint identity
  hashing through Contracts; retain bounded create-only intents with no-follow
  reads. Preserve lost-reply spending, cold continuation and terminal replay.
  Live capture and production restore integration remain unfinished.

- Correct optional ICRC-21 consent mounting to the required public Candid update;
  retain ICRC-10 discovery as a query and use canonical standard document URLs.
  Compare the complete generated service against the pinned external contract.

- Select the latest published stable IC cohort across the root catalog and both
  independent Blob consumer catalogs/locks: Blob/contracts 0.58.0,
  Memory/Storage/Metrics Stable 0.56.0, Build/Host/Testkit 0.70.3,
  Auth/protocol 0.23.0, Backup/Agent 0.50.2, Query 0.76.2,
  Platform/Call 0.8.2, Logging 0.17.2, Metrics 0.17.5, Timers 0.32.1 and
  Wire 0.7.23. Remove the older private-consumer runtime selections and the
  second Platform identity. Retain the Rust 1.91 floor and workspace boundaries.
  Prepare the exact 0.70.3 Testkit server and release-metadata editor, and refresh
  the embedded allocation peer with structured source/tool/lock evidence.

- Use Auth's checked borrowed/owned session reader and authorization projection.
  The stable-backed reader returns owned decoded sessions; logout validates its
  session within the read callback. Construct immutable upstream
  `ValidatedGrants` in the real shared-session fixtures, preserving record,
  replay, generation, revocation and allocation/custody assertions. Consume admitted
  session/replay pairs, construct protected `SessionLimits` and `RequiredScopes`
  through upstream admission, and treat `SessionReceipt` as a result only. Full
  session records remain in the host store and each authorization consults current
  authority.

- Adopt Memory 0.56's bounded native Wire allocation ledger (`ICML` / `ICMWIRE1`)
  and the aligned Storage/Metrics Stable cohort. Metrics rows retain `ICMW`;
  Canic-owned values retain `CSW\x01`. Release transitions require clean reinstall,

- Keep Platform's bounded external-Candid decoder and empty lifecycle input
  normalization, rejecting excessive constructed nesting before decoding.
  Metrics and Timers share the public measurement types; validated Serde
  transport and native Wire metadata are standard in Metrics, without a
  transitional feature. Framework-owned adapter reports compose shared
  counter/aggregate types and preserve wide values, overflow quality, schema
  validity and bounded decode refusal through the real endpoints.
- Adopt reviewed Shared Tooling 0.27.6 through its exporter and verify payloads
  against commit `5a72359b5be19d5221334cf2c9b3204621d3f3f6`.
- Complete the second Root fixture owner's stop/drain-before-capture/restore and
  restart-after-success lifecycle, preserving controllers, current simulated time
  and restore funding with the published Tooling owner.

- Remove the IcyDB recording-feature wrapper from the three metrics exports.
  Applications still select public or controller reads explicitly; reset remains
  controller-only. The adapter gains no database engine dependency or recorder.
- Cover both metrics read policies and reset with framework-owned consumer types,
  linked native exports and typed Wire envelope checks. Register both targets in
  ordinary qualification; retain storage-backend policy with the upstream owner.
- Make `observability.metrics = false` suppress managed IcyDB read/reset exports,
  metadata and update-limit registration through the shared entrypoint owner.
  Explicit declarations and controller checks remain required when enabled;
  standalone mounts and independent history/recording policy remain unchanged.
  Qualify omitted config defaults and enabled-but-unmounted endpoints for both
  read policies. Name the macro classification explicitly and document its single
  ownership chain from config through the build and endpoint expansion.
