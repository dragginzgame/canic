# Canic 0.101 Changelog

## [0.101.3] - 2026-08-05 - Fleet Service Targets

### ➕ Added

- Adds strict `services.fleet.targets` declarations that bind each logical
  Fleet service to one exact Component role, Component Spec, typed mode and
  service-wide density/spread envelope.
- Compiles canonical raw service-ID-ordered targets against every exact
  flattened deployment occurrence.

### 🔧 Changed

- Requires every service-bearing occurrence and target to form one complete
  relationship with an exact matching Component Spec and direct role.
- Requires `AuthorityReplica` services to contain exactly one selected
  singleton Authority, zero or more Replicas and no PoolMembers.
- Requires `ActivePool` services to contain one or more initially materialized
  PoolMembers and no Authority or Replica occurrences.
- Keeps service-wide member policy independent of per-deployment placement
  policy, bounds both positive values by maximum concurrent demand and rejects
  policies that cannot fit indivisible same-placement service members or
  spread them beyond the contributing placement count.
- Preserves distinct service identities even when they intentionally reuse the
  same Component role and Spec.

### 🩹 Fixed

- Heap-indirects retained core configuration failures at the host App-config
  boundary, keeping their typed causes while preventing large-error layout
  from cascading through host and CLI commands under Rust 1.97.

### 🧪 Testing

- Adds focused positive, canonical, decoded-projection and adversarial proofs
  for orphan relationships, identity mismatch, incompatible purpose, bad
  Authority selection, empty pools, invalid policy and retired scalar input.

### 🧭 Migration Notes

- 0.101 remains reinstall-only. Labels, member-limit reductions, protected
  deployment context, root selection, persistence and network effects remain
  unavailable and their partial source fields reject.

## [0.101.2] - 2026-08-05 - Independent Group Deployments

### ➕ Added

- Adds strict independent Component Group deployments with mandatory initial
  and maximum counts plus bounded per-root density and minimum spread.
- Completely flattens every deployment before planning, preserving separate
  inclusion and deployment occurrences with exact Component Spec hashes.
- Rejects aggregate maximum-placement demand beyond each Component Spec's
  Fleet ceiling.
- Adds strict service-bearing Component Group leaves and typed Authority,
  Replica and PoolMember assignments at deployment, inclusion or leaf scope.
- Resolves each flattened occurrence to `Ordinary` or one exact Fleet-service
  member purpose and rejects missing, duplicate or unused assignments.

### 🔧 Changed

- Advances the host-only Subnet Catalog boundary from `ic-query 0.28.4` to
  `0.29.3`, retaining only validated authority-bearing catalogs and selecting
  the missing-or-invalid refresh policy explicitly.
- Freezes the embedded source as an explicit single-endpoint uncertified query
  and requires at least `UncertifiedQuery` assurance instead of relying on
  dependency defaults. The stronger bounded multi-endpoint agreement remains
  outside this batch until Canic owns an exact trusted endpoint set.
- Confines the embedded Subnet Catalog to an owner-only cache root beneath
  Canic state and binds Canister routing evidence to the exact Registry
  version, catalog digest and provenance that established it.
- Consumes the matched validated Subnet classification carried by each
  resolved Canister route directly, removing the former second catalog lookup
  and its impossible missing-Subnet error branch.
- Keeps internal PocketIC behavior journeys in the full test lane while the
  fast lane still compiles their harness and runs its pure embedded-config
  proof.
- Batches identical Component fixture Wasm packages into one Cargo build and
  reuses one shared target across the receipt, timer and lifecycle
  PocketIC suites.
- Advances the unified test runtime from `ic-testkit 0.3.2` to `0.3.4`, so
  internal Cargo Wasm builds reuse exact content-addressed artifacts under a
  cross-process lock instead of relying on Canic's audit and standalone-build
  mutexes.
- Publishes exact watched-input stamps after successful external ICP builds so
  root baseline artifacts remain reusable without trusting file timestamps.
- Retains exact PocketIC Wasm caches between local full-suite runs while CI
  still clears them for bounded runner disk use, and makes `make clean-wasm`
  cover every named Canic test-Wasm target.
- Reports exact cache reuse plus lock, input-resolution and Cargo timings for
  each internal test-Wasm build so slow suites distinguish build work from
  PocketIC runtime work.
- Hard-cuts the Component Group graph encoding to schema v2 so leaf kind,
  Fleet service ID and edge-local purpose assignments are canonical evidence.

### 🩹 Fixed

- Pins the PocketIC 15 executable required by the resolved Rust client and
  fails before dependency fetch or download when those versions drift.
- Makes instruction-audit executable discovery follow the repository's
  PocketIC version pin instead of a stale literal.
- Heap-indirects large nested CLI command errors at command-group boundaries,
  preserving typed causes and operator diagnostics while satisfying the Rust
  1.97 error-size lint.

### 🧪 Testing

- Adds focused coverage for independent nested selections, canonical order,
  exact demand, invalid placement envelopes and decoded projection drift.
- Adds nested Authority/Replica reuse, mixed-purpose leaf, exact-assignment,
  unused-assignment and schema-v2 golden-vector coverage.
- Requalifies mainnet placement, funding, imported-Canister routing and cached
  root-Subnet evidence against `ic-query 0.29.3`'s validated catalog contract,
  including its grouped single-endpoint collection provenance and positive
  Registry query-call count.
- Extends release-integrity validation to cover the PocketIC alignment guard.

### 🧭 Migration Notes

- 0.101 remains reinstall-only. Fleet-service targets, labels, member limits,
  root selection, persistence and network effects remain unavailable and
  their partial source fields reject.
- Component Group schema v1 is not decoded or migrated.
- The former permissive and schema-1 Subnet Catalog caches are not migrated.
  The first authorized mainnet read creates or refreshes the schema-2,
  owner-only cache under Canic state.

## [0.101.1] - 2026-08-05 - Component Group Compilation

### ➕ Added

- Adds strict checked-in Component Group declarations for direct Component
  occurrences and configuration-only nested group inclusion.
- Compiles declarations into a bounded canonical acyclic graph and flattens
  each selected group by exact member path without deduplicating equal Specs.

### 🧪 Testing

- Adds focused rejection coverage for missing references, duplicate names,
  inclusion cycles, excessive depth and unknown fields, plus an exact schema
  version 1 canonical-byte vector.

### 🧭 Migration Notes

- 0.101 remains reinstall-only. Deployment selection, service purpose,
  labels, member limits, placement, persistence and network effects are not
  accepted by this slice and remain fail-closed until their compiler stages.

## [0.101.0] - 2026-08-05 - Component Deployment Identity

### ➕ Added

- Adds bounded canonical identities for Component Group Specs, independent
  deployments, group members and Fleet services.
- Adds one durable placement identity that binds an exact deployment to a
  monotonically allocated ordinal without becoming runtime parentage.
- Adds bounded canonical member paths that preserve every nested inclusion
  occurrence and reject empty, excessive-depth and invalid decoded values.

### 🧪 Testing

- Focused ID tests cover source parsing, Serde and Candid rejection, stable
  bounds, occurrence order and placement identity round trips.

### 🧭 Migration Notes

- 0.101 remains reinstall-only. This first contract slice adds no group
  configuration grammar, planner, persistence, runtime authority or network
  effect and retains the finite scale-envelope gate before those surfaces.
