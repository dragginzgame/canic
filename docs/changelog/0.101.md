# Canic 0.101 Changelog

## [0.101.12] - 2026-08-06 - Group Member Installation and Complete Test Inventory

### ➕ Added

- Advances each fully claimed root batch through one canonical Store-backed
  Component install at a time. A third independently domain-separated,
  hash-bound O(1) cursor and caller-supplied installed count reconcile an
  interrupted or response-lost install without advancing another member.
- Installs the exact accepted-plan `GroupMember` context through the ordinary
  top-level Component install journal, then independently observes the exact
  operation, binding and retained deployment context while the runtime remains
  behind an empty `AwaitingDirectory` fence.

### 🔧 Changed

- Requires every batch member to finish identity reservation and prepaid-
  Canister claim before any member installs. The shared install path retains
  the ordinary cost guard, exact sibling-Store module source, durable intent,
  uncertain-result observation, controller/module verification and terminal
  `Verified` boundary; Registry commitment remains separate and unavailable.
- Applies a grouped member's reduction-only Registry-byte ceiling to its
  install-capacity check instead of silently restoring the Component Spec
  ceiling. Ordinary Components continue using the Spec ceiling.
- Hard-cuts aggregate advance/status Candid and stable state to carry the
  installed-member count and install cursor; no earlier 0.101 shape is read.
- Corrects the stable operation-key and placement-owner bounds to cover their
  maximum valid CBOR encodings. The former undersized declarations trapped a
  real root during first batch acceptance even though small-byte unit fixtures
  fit.
- Advances the internal harness from `ic-testkit` 0.7.0 to 0.7.2 and adopts
  interval-limited cross-process maintenance for each network-qualified shared
  Cargo target. Retention evaluates at most hourly, clears a target after seven
  unused days or above four GiB, and keeps maintenance failure nonfatal to the
  exact immutable Wasm acquisition.
- Runs ordinary library, binary and integration tests with libtest's default
  parallelism while retaining single-thread execution for the mixed internal
  PocketIC library and every PocketIC integration suite. The existing runtime
  fixture group continues sharing transient build freshness before isolated
  blob-storage, payload-limit and instruction-audit groups.
- Makes one guarded inventory authoritative for all 35 top-level integration
  targets: 29 are parallel-safe and six are serial PocketIC suites. The full
  release lane now includes every entry, including the previously omitted
  blob-storage and ingress-payload suites; the fast lane retains its three
  release-surface targets.
- Extends explicit Wasm cleanup to the complete test-artifact cache tree. New
  integration targets fail the inventory gate until assigned a release lane,
  execution class and suite.

### 🧪 Testing

- Covers canonical multi-placement install order, exact install replay,
  restart retention, independently corrupted install-cursor rejection,
  claim-before-install ordering and rejection of a substituted grouped
  context or prematurely Directory-prepared runtime.
- A focused PocketIC journey compiles one real grouped Project Hub placement,
  persists its canonical plan under the Coordinator caller, reserves its
  identity, claims one imported prepaid Canister and installs the Store-backed
  module. It independently observes the exact `GroupMember` runtime context,
  root-only controller and module while `AwaitingDirectory`, proves no
  Component Registry partition exists, and replays the terminal install step
  without another effect. A maximum-byte unit fixture covers both corrected
  stable acceptance bounds.
- The inventory guard, fast and full plan resolution, shell syntax and lint,
  formatting, release-integrity contract and focused shared-target retention
  tests pass. A focused local journey built cold in 37.42 seconds, evaluated
  retention over 404,508,285 bytes in 8.30 milliseconds, reused exact Wasm in
  425 milliseconds and then took the scheduled-maintenance skip path in 25
  microseconds. The newly restored inventory targets now account for current
  lifecycle, authority-restore and canister-pool timer owners and independently
  guard the application install hook for ordinary Components, sibling Wasm
  Stores and roots. The broad release suite remains maintainer-owned and will
  execute through the now-complete release path.

### 🧭 Migration Notes

- 0.101 remains reinstall-only. This slice stops each grouped allocation at
  the verified install boundary and leaves the aggregate phase `Accepted`;
  Component Registry partitions, Directories and activation are not yet
  published.

## [0.101.11] - 2026-08-06 - Group Member Prepaid-Canister Claim

  prepaid-Canister claim at a time. A separate hash-bound placement/member

  effective limits before committing aggregate claim progress.

  exact response-loss retry reports the last committed step without selecting
  a second asset.
- Retries one transient `cargo clean` failure during release cleanup while
  preserving a persistent failure. Release publication now explicitly names
  the exact branch and version tag in one atomic push, including when the
  branch commit already exists remotely.
- Uses the complete workspace test lane for version-bump validation and makes
  network-aware core builds rerun when `ICP_ENVIRONMENT` changes.

### 🧪 Testing

  replay, terminal progress, plan-derived runtime context, contradictory
  cursor rejection and independent corruption of both cursor hashes.
- Extends the release-integrity fixture across successful, transient and

  refspecs. Focused provisioning, Candid boundary, protocol and strict package
  Clippy checks pass.

### 🧭 Migration Notes

  batched per-package cached Wasm builds with heartbeat diagnostics and
  bounded maintenance cadence, binds external caches to exact resolved Cargo
  inputs and restores captured snapshots with their retained per-Canister
  senders.
- Runs one shared local cleanup after patch, minor and major release gates on
  success, failure and handled interruption, before version mutation. It
  confines temporary files to the repository-owned test scratch tree, clears
  that tree and Cargo artifacts without sweeping unrelated global temporary
  files, and repeats the cleanup before the final atomic network effect.

### 🧪 Testing

  harness and journey crates also pass all-target, all-feature Clippy.
