# Canic 0.105 Detailed Changelog

## [0.105.0] - 2026-08-20 - Framework-Neutral Local Application Authorization

### ⚠️ Breaking

- Removes the old caller-selected delegated-session subject API, storage
  records and test-canister endpoints without an alias, fallback decoder or
  compatibility lane.
- Replaces memory ID 34's subject-only session and bootstrap binding vectors
  with one current caller-bound scoped application-session record, one replay
  tombstone record and one independent local authority generation.
- Removes the subject-identity fallback and its duplicate access-context field
  from managed, Root and Wasm Store endpoint generation; endpoint predicates
  now receive only the exact transport caller.

### 🔧 Changed

- Adds one explicit protected `local_application_authorization` role table.
  Presence derives a build-time capability only when delegated-token
  verification is enabled; infrastructure roles and verifier-only managed
  roles compile no application-session surface.
- Adds `ApplicationSession::{Establish, Clear}` beneath the existing
  `canic_command` method and caller-self `ApplicationSession` beneath the
  existing `canic_status` method. A separately Root-authorized, paginated
  `ApplicationSessionAudit` status variant reports protected policy and
  retained sessions without proof material. No session-specific method
  identity is introduced.
- Public token preparation admits a canonical application scope only when the
  exact target role declares it and Root issuer policy grants it. Undeclared,
  cross-role and noncanonical scopes remain denied.
- Establishment derives caller, subject, issuer, Fleet, role and generation
  from ambient or verified authority, narrows scopes against the protected
  allowlist, applies the protected 1,800-second ceiling and returns the exact
  active receipt on byte-identical retry.
- Caller clear is idempotent and caller-scoped, while status reports the
  frozen missing/expired/Fleet/role/generation/subject precedence without
  exposing another caller's state.
- Retains caller, subject, issuer, Fleet, role, canonical scope subset,
  authority generation, independent session lifetime, proof fingerprint and
  establishment-request hash in one bounded active record.
- Retains consumed proof identity through strict proof expiry independently of
  session expiry, replacement, clear or generation invalidation. When an
  active session outlives the proof, cleanup removes the replay on its own
  clock while the session's retained proof/request identity preserves exact
  retry and same-release reconstruction without extending tombstone lifetime.
- Reconstructs exact-caller, proof-fingerprint and per-subject count indexes
  synchronously during Canic lifecycle restoration before application work.
- Commits session replacement and its new replay tombstone through one stable
  cell update, while capacity or corruption rejection leaves prior authority
  unchanged.
- Resolves byte-identical exact retry before proof eligibility, so the same
  active current-generation receipt remains available after proof expiry
  without extending session expiry.
- Adds one synchronous
  `canic::access::auth::authorize_local_application` Rust facade. It reads
  caller/time once, closes mismatches before state lookup, projects one
  protected authority, reads one exact-caller session and delegates to the
  existing pure decision without mutation, await, logging or remote work.
- Converges session establishment and local authorization on the same protected
  authority projection, while the proof-bearing guard delegates presenter and
  scope validation to the one native verifier without a second scope check.
- Routes literal authenticated endpoint scopes through the compile-time
  `application_scope!` grammar; no alternate parser or compatibility spelling
  is introduced.
- Reconciles one durable local authority binding during lifecycle restore and
  advances generation exactly for the frozen Fleet, role, verifier-policy,
  scope-removal and reduced-maximum transitions. Aggregate metrics use only
  closed non-secret dimensions.

### 📊 Audit

- The current representative active-session record encodes to 519 CBOR bytes
  and one replay record to 198 bytes.
- Maximum admitted sessions with maximum-size scope sets plus maximum replay
  records encode to 4,025,450 bytes with the maximum authority binding, below
  the 8 MiB ceiling. The maximum restore fixture is 4,025,139 bytes and the
  conservative derived-index estimate is 2,039,808 bytes, below 4 MiB.
- One cleanup call removes at most 128 strictly expired session/replay records;
  authorization performs no cleanup or mutation.
- PocketIC observes allowed local authorization at 180,797 instructions with
  one active session, 186,749 at 1,024 and 187,112 at the 2,048-session
  maximum, all with 16 maximum-width scopes and below the 1,000,000 ceiling.
  The nine closed denial branches range from 58,742 to 62,931 instructions.
- Warm establishment observes 4,584,113 instructions. Cold establishment
  observes 476,135,709, of which 471,154,912 are the embedded-proof
  verification component. Maximum synchronous restore observes 1,168,165,228
  instructions and maximum 128-record cleanup observes 1,483,321,373.
- The maximum injected state occupies 3,995,192 auth-state bytes. Physical
  stable memory remains 218,169,344 bytes (3,329 pages) before and at maximum,
  and remains unchanged by bounded cleanup.
- A controlled equal-path `fast` build of exact `v0.104.2` and the current tree
  measures 19,054,678 -> 19,236,127 raw bytes across Component, Root,
  Coordinator and Store: +181,449 bytes, leaving 80,695 bytes below the 256 KiB
  ceiling. The final builder gzip observation is 4,940,882 -> 4,988,056. All
  four product Candid hashes and lifecycle export sets are unchanged.

### 🧪 Testing

- Canonical enabled and verifier-only role builds prove variant and referenced
  type pruning while preserving the existing role method identities.
- One PEM-backed native-agent PocketIC journey establishes, reads, exactly
  retries and clears the configured session, then proves that the retained
  proof tombstone prevents resurrection. The same journey proves a token-free
  generic application query denies before establishment, returns the exact
  caller while authorized and denies immediately after clear.
- Focused facade, macro-expansion, compile-fail and public-owner tests prove the
  synchronous bounded read path, one public module owner, canonical literal
  scope validation and complete removal of the old identity fallback.
- Focused state evidence covers proof/session clock separation, exact retry,
  conflicting replay, tombstoned clear, atomic replacement, generation
  invalidation, capacity rejection without state loss, corrupt/over-limit
  restore, bounded cleanup and same-release reconstruction.
- Focused operator evidence proves independent Root authorization, bounded
  caller ordering, active/inactive classification and absence of tokens,
  proofs, fingerprints and request hashes. Focused semantic timer ownership
  remains 16/16 passing.
- A second PEM-backed journey consumes one proof independently on two managed
  targets, denies their common Root controller, preserves both target-local
  sessions and exact receipts after proof expiry and same-release upgrade,
  rejects duplicate reconstruction, isolates one-target clear, then proves
  strict expiry, bounded cleanup and zero-row non-resurrection on both targets.
- Warning-denied `canic-core` Clippy and the directly affected test-canister
  package checks pass. Full release validation remains maintainer-owned.

### 📝 Summary

- The presenter-bearing token, canonical scope and pure policy work entered
  the immutable 0.104.2 predecessor early. This draft continues that exact
  source with the 0.105 state, cfg-pruned role surface and synchronous generic
  authorization facade. Operator/security/resource qualification and the
  Canic-only security, recovery and residue closeout are complete.
