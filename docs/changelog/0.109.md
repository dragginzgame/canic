# Canic 0.109 Changelog

## 0.109.20 - 2026-08-29

### 🔧 Changed

- High-confidence compiler, panic, test and Make failure lines now receive red,
  target-owned `[ERR:<target>]` prefixes while they stream. Validation also
  finishes with that prefix on every repeated diagnostic line. The runner
  retains the raw complete command output and a separate aggregated
  `latest-errors.log`, so a failure remains visible and directly shareable
  without scrolling back through a long deployment or release transcript.
- Each validation-runner invocation now syntax-checks and executes an immutable
  private copy of itself. Editing the workspace runner while a long PocketIC
  tier is active can no longer produce a late shell parse failure after the
  tests have passed.
- Root initialization now retains a separate Store child activation authority.
  It binds the exact Fleet, Root and Store Principals, Store installation
  operation, release build, topology, manifest and the exact Root plus protected
  installation-controller set. Root-local state continues to use the Root
  installation identity; every initial and post-provisioning Store prepare,
  status, reconciliation and activation call uses the Store identity.
- Fleet Ensure starts a stopped retained Coordinator, Root or Store under its
  existing Principal before compiling protected role protocol actions. An
  issued Component-provisioning action is replayable only when the exact
  protected Coordinator status retains a current typed Root-failure record;
  replay reuses the reviewed request, operation receipt and idempotency identity
  and cannot create, fund, replace or reinstall a canister.
- Fresh Fleet generation can create a durable no-effect seed with a random
  Fleet ID, exact Cycles Ledger and creation-fee authority, and logical
  Coordinator, Root, Store, treasury and initial-pool roles. Dependent
  controller and treasury Principals resolve only from journaled creation
  results inside the existing reviewed Fleet Ensure plan/apply owner.

### 🩹 Fixed

- Make-selected `sccache` now runs through a repository wrapper whose server
  socket and temporary directory outlive invocation-owned test scratch.
  Cleaning `test-runtime.*` can no longer leave the persistent compiler-cache
  server pointing at a deleted `TMPDIR` and break later feature builds.
- Root no longer addresses its independently installed Store with the Root
  installation operation ID. Exact Store authority is checked before retention
  and again from stable state, including rejection of missing, colliding,
  substituted or controller-widened child authority.
- Repeated timestamps for the same typed pending Root failure no longer count as
  provisioning progress. One invocation may reissue the exact idempotent
  Component command once, then resumes bounded observation until terminal proof
  or the consecutive-stall limit.

### 🧪 Testing

- The release-integrity fixture launches a fake cache client from disposable
  test scratch, proves the wrapper gives it the stable socket and `TMPDIR`,
  then proves cleanup retains that runtime. The complete control-plane feature
  matrix passes after real scratch cleanup against the same persistent server.
- Focused model, stable-state, host workflow and init-argument tests cover exact
  Root/Store identities, widened-authority rejection, stopped same-Principal
  startup, typed issued-command replay and zero changes to identities, cycles or
  operator debit.
- The governed five-Component PocketIC journey stops and restarts retained
  infrastructure, observes a typed Store-unavailable failure for one issued
  operation, restarts the same Store, replays that exact operation, reaches
  runtime activation and Fleet catalog publication, and proves the immediate
  successor protocol has no update action.

## 0.109.19 - 2026-08-28

### 🔧 Changed

- Each new schema-`v1` Fleet Ensure plan now retains the normalized desired
  authority inside its own plan digest. Planning returns an existing
  in-progress operation before considering newer desired bytes, and apply
  rebinds every platform observation, limit, artifact resolution and terminal
  check to that retained authority. The CLI can therefore reopen the reviewed
  operation even when its working desired TOML is missing; current desired
  state is considered by a separately reviewed successor plan only after the
  retained journal closes.
- Canic-owned generic protocol steps are retained inside that reviewed
  authority without becoming fields accepted from the public desired document.
  Resumption therefore restores the exact observation graph as well as the
  public Fleet configuration.

### 🩹 Fixed

- The public `canic toolchain install` path now closes and synchronizes its
  staged `wasm-opt` writer before executing the checksum-admitted candidate for
  version inspection. Linux no longer rejects the freshly written optimizer
  with `ETXTBSY`; archive, executable-digest and version checks are unchanged.
- A current schema-`v1` plan written before desired-input retention can close
  the exact zero-debit, all-reused estate shape already observed downstream:
  every preceding action must be applied, the final issued action must be the
  typed Component-provisioning operation, and the supplied current document
  must retain every exact canister name and Principal. Canic only observes that
  issued action; it never reissues it. Terminal protected inventory and cycle
  conservation must still pass before closure, after which newer desired state
  requires its own plan digest.
- A verified in-progress plan that still contains inline Store chunk bytes is
  rewritten to the maintained content-addressed projection before the first
  resumed platform observation or effect. The logical plan digest, operation
  identity and journal bytes do not change; an interrupted rewrite leaves
  either the complete inline file or the complete compact file usable.

### 🧪 Testing

- A Linux regression drives the real staged publication path and proves the
  installed executable can be admitted immediately with its exact version and
  SHA-256.
- Fleet regressions prove retained desired authority round-trips through the
  production plan writer, a changed input cannot alter or duplicate an issued
  operation, a missing working TOML is recovered from the exact retained plan,
  and the bounded pre-retention final-action case rejects a changed Principal
  while completing through observation with one command total.
- The focused Fleet Ensure suite proves internal protocol observations survive
  retained-desired round-trip. Content projection coverage starts from an
  inline plan, compacts it by more than half, preserves its exact logical plan
  and becomes a no-op on the canonical second pass. The isolated downstream
  evidence regression compacts the 37,131,114-byte retained copy below one
  tenth while leaving its journal and original evidence unchanged.
- The version-rollback fixture now proves exact restored file bytes and a clean
  Git state instead of depending on one explanatory console sentence.

  staged input. Fast and debug builds do not request the transform.

  `wasm-opt` executable as well as the official archive and version identity.
  A same-version executable with different bytes fails before execution and
  names both its selected path and `canic toolchain install`; that published
  hard-cut installer works without a sibling Canic checkout. Build provenance
  records the exact optimizer executable SHA-256.
- Release optimization derives the feature flags required by each input under

  embedded public Candid or required features. Build provenance carries exact
  before/after raw, deterministic-gzip, code-section, data-section and defined-

  instantiations when constructing already ordered Component-topology maps.
  Chain-key batch selectors share one comparator and use unstable sorting only
  under the retained batch ID's unique total order; runtime metrics and other
  one-off sorts keep their existing tie semantics.
- `canic build <app> <role> --standalone-local` now owns the supported
  declaration/runtime sequence for `start_local!` consumers. Caller-selected
  `--features` and `--no-default-features` apply identically to both Cargo
  passes; the declaration Wasm is discarded, while the final runtime retains
  Candid only as its adjacent `.did`. The builder rejects a remaining
  `get_candid_pointer`, embedded public Candid, or a method-inventory mismatch
  before copying the runtime to `ICP_WASM_OUTPUT_PATH`.

## 0.109.13 - 2026-08-27

### 🗑️ Removed

- Hard-cuts fresh-install, deployment-plan, historical-plan, adoption,
  retained-recovery, retained-Root repair, recovery-bundle, installed-catalog,
  and autonomous Root-deletion host owners. Their CLI modes, aliases,
  diagnostics, fixtures, examples, and compatibility-only tests are removed.
- Historical evidence remains only in immutable release notes and archived
  audits; the maintained source does not decode, migrate, import, or infer
  authority from it.

### 🔧 Changed

- `canic fleet ensure <fleet>` is the sole Fleet convergence workflow. Its
  plan-only form binds current desired TOML, resolved Wasm/init/Candid bytes,
  exact live authority, one current `v1` journal, and a reviewed digest;
  `--apply <plan_sha256>` resumes only that operation.
- `canic fleet generate <fleet>` compiles the low-level current desired
  document from protected Fleet policy, one finalized complete release set and
  one explicit estate identity seed. Release authority supplies exact Wasm,
  Candid and typed infrastructure init contracts; the exact live Fleet ID and
  retained Coordinator, Root, Store, pool and treasury Principals must be
  seeded and verified against live controllers, placement, role relationships
  and cycle evidence. Fleet identity is never synthesized from an environment,
  name or operator. Missing or unseeded authority rejects rather than being
  inferred from project metadata or removed install state. Both release-set
  child manifests and no-follow Candid sidecars are verified; duplicate
  identities, unexpected co-controllers and mismatched Fleet/Coordinator/Root
  identity authority reject before create-once output. An old init-only Root
  policy is accepted as desired-state drift only when the reviewed current Root
  artifact will be reinstalled; an already-current Root cannot retain different
  policy. The maintained treasury policy is deterministic adoption of an
  already-controlled canister, not invention or global discovery for an empty
  estate.
- Multi-Root generation joins protected policy, retained identities and
  compiled topology by exact parsed `SubnetId`. It no longer relies on
  positional agreement between Principal text order and canonical typed
  Principal order, so Root-local admission, placement, limits and funding
  cannot cross-bind.
- Generated retained state includes every explicitly seeded paid Root-owned
  asset, derives the exact current Cycles Ledger fee, and carries zero
  canister-creation fee authority. A missing seeded Coordinator, Root, Store,
  treasury or pool/workload identity rejects instead of creating a substitute.
  An exact seeded asset remains conserved through `Idle`, `Claimed` and
  `Workload` lifecycle observations; active assets do not receive idle-pool
  minimum funding, and terminal Component inventory cannot count the same
  Principal a second time. Observation and update burn remain explicit
  conservative ceilings validated by terminal measured conservation.
- Every creation, funding, transfer, install/reinstall, controller update,
  start, stop, and deletion records intent before the effect. Ambiguous
  results reconcile exact live state or repeat the same Ledger/drain identity,
  while consecutive-stall bounds reset only after durable progress.
- Planning reports each create/reuse/reinstall/replace/delete disposition and
  separates observed cycles, retained cycles, scheduled transfers, Ledger and
  creation fees, bounded observation/update burn, new funding, maximum debit,
  and the post-operation conservation equation. Apply refuses source,
  artifact, authority, balance, funding, fee, or debit drift outside the
  reviewed bounds.
- Material retirement requires one exact treasury-bound idempotent drain
  contract. Canic retains both pre-transfer balances and requires a bounded
  source debit plus the exact controlled-treasury credit from fresh live
  observations. A call response alone cannot unlock stop or deletion.
- Protocol update responses now retain only `issued` state. Later actions stay
  fenced until the exact status query proves terminal application; repeated
  unchanged observations consume the consecutive-stall budget and genuine
  progress resets it.
- Current Store publication/bootstrap, Coordinator Registry joins and
  activation, Root Registry synchronization/mirror activation, exact local
  Component Registry preparation, and Component provisioning are compiled from
  the checked-in App topology, qualified
  release-set artifacts, exact declared Root placements and protected live
