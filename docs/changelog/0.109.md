# Canic 0.109 Changelog

## 0.109.5 - 2026-08-25

### 🩹 Fixed

- Fresh-Fleet planning now rejects a Root whose configured pool-asset cycles
  are below the largest `initial_cycles` requirement among Components placed
  on that Root. The first-excess decision remains before plan persistence,
  builds and paid effects.
- Root batch acceptance now matches distinct Ready assets against every exact
  Component cycle demand instead of treating equal Ready counts as fungible.
  An impossible full pool returns typed `CAPACITY_INSUFFICIENT` evidence
  through the existing Root/Coordinator retry path.
- Reissuing the protected `ImportPoolCanister` command for an existing
  undersized imported Ready asset now fences that stale row, revalidates its
  Root ownership and Subnet placement, observes its controller/module/balance
  state without repeating uninstall effects and publishes the refreshed
  amount. `RetryPoolReset` provides the same idempotent queued transition;
  exact retry after a sufficient refresh performs no second reset.
- Import/reset validation is bound to the larger of the configured pool floor
  and every still-unclaimed demand in the one retained Root batch. A 4.5T row
  therefore cannot satisfy or remain silently Ready for a retained 5T claim.
- The narrow retained-install host contract admits 0.109.5 for the exact
  0.109.1 recovery session and continues to reject later patches, other
  predecessors and reversed pairs.

### ⚠️ Breaking

- This is a pre-1.0 hard cut, not a general cross-release migration contract.
  The live retained recovery may temporarily upgrade its Root to the exact
  corrected artifact so the existing stable pool and provisioning owners can
  reconcile; reinstalling that Root would discard the required journal and is
  not the supported recovery path.

### 🧪 Testing

- Covers heterogeneous Ready-asset matching, first-excess plan rejection,
  idempotent undersized-Ready reinspection and the exact 0.109.1-to-0.109.5
  host recovery pair while retaining rejection of 0.109.6. A governed
  PocketIC journey proves that the same topped-up principal reaches Ready at
  5T and an exact protected replay neither resets nor debits it again; the
  ordered governed inventory is now 31 cases.

## 0.109.4 - 2026-08-24

### 🩹 Fixed

- Fresh-install host recovery no longer requires the first exact Coordinator
  Component-provisioning status observed after command acceptance to remain
  `Planned`. It durably retains any authority-bound nonterminal phase and
  derives the next request from that observation.
- A first `RuntimesActivated` observation must pass the existing complete
  terminal-evidence validation and then advances directly to Fleet-catalog
  publication without creating another provisioning request.
- The narrow host-only retained-install contract now explicitly permits an
  exact 0.109.1 release-build session under 0.109.4. Same-version recovery and
  the prior 0.109.2/0.109.3 successors remain admitted; 0.109.5, other
  predecessors and reversed pairs remain rejected.

### 🧪 Testing

- Covers lost prepare-response restart followed by every Coordinator
  nonterminal phase, exact next-request derivation, complete terminal
  reconciliation, incomplete-terminal rejection and immutable-authority or
  cardinality mismatch rejection.
- Rechecks the complete host install-root subsystem and warning-denied host
  library/test surface.

## 0.109.3 - 2026-08-24

### 🩹 Fixed

- Finalized install recovery now selects a distinct read-only snapshot instead
  of resolving the retained consumer workspace through the successor host's
  ordinary current-version build specification. The exact supported 0.109.1
  session can therefore reach journal replay under 0.109.3 without running
  Cargo or rebuilding/re-emitting artifacts.
- The retained snapshot rechecks the current App topology and exact declared
  role/package identities against the immutable application union and
  infrastructure manifest, binds every infrastructure artifact to the
  retained builder, reconciles the Root release-set with the application union
  and verifies its finalized digest through a regular no-follow read.
- Reuse re-materializes both raw and gzip representations through the existing
  application and infrastructure validators before and after deployment-truth
  preparation. Unsupported host/build pairs, changed topology or package
  identity, noncanonical manifests and changed artifact bytes remain blocked
  before an IC effect. Fresh builds retain their exact current Canic-version
  role-contract validation unchanged.

  ICP build/environment configuration, Fleet-input tests, timer-provider

### 🧪 Testing

  session. It crosses finalized manifest reuse into exact session-journal
  replay with the complete fixture tree unchanged and rejects package,

### 📚 Documentation

  controller mutation, funding or any other external effect.

## 0.109.2 - 2026-08-24

### 🐛 Fixed

- Fresh Root acceptance now advances the sole Root-owned pool journal toward
  the exact accepted Component-batch demand rather than only its background
  minimum. The target remains bounded by the immutable standby maximum, and
  every retry revalidates the same Registry, Store and batch authority before
  acceptance.
- Fresh-install host polling now waits one second after an unchanged durable
  Coordinator status. Unchanged reads still consume the existing finite poll
  bound, while real progress is observed immediately; the host can no longer
  exhaust its allowance in a tight loop before the Coordinator's scheduled
  retry becomes eligible.
- Registry restart validation now has one shared owner used by the earliest
  join gate, the subsequent Root-synchronization gate and activation. It
  accepts exact Joining or all-Active replay, plus only the revision-4 initial
  service successor proven by the exact fresh-install operation, plan hash,
  predecessor, publication receipt and service-published-or-later phase.
- Fresh-install recovery now derives the operator debit that can still be
  issued from the exact retained session, immutable install plan and validated
  Coordinator/Root creation journals. A creation intent permanently fences its
  amount and one Cycles Ledger fee; a settled result is never charged again,
  while an uncertain in-flight result remains observation-only and cannot be
  reissued.
- Protected Root operation verification retries only diagnostic `E140
  STATE_UNAVAILABLE`, at most five total exact-operation queries with one
  second between attempts. That query loop never resends the Store-bootstrap
  update; later process recovery can only replay its same retained, Root-
  journalled operation identity.
- One narrow host-only rescue contract lets 0.109.2 resume an interrupted
  0.109.1 session with its retained release build, operation identity, plan
  digest and artifact hashes. Workspace-origin decisions retain the original
  0.109.1 builder identity during exact recompilation; this does not upgrade,
  migrate or replace an installed Wasm.

### ✨ Operator surfaces

- `canic deploy plan` now emits `install_recovery` in its version-1 JSON report
  and a matching text section when an exact retained session exists. It names
  the install operation, retained release build/builder, original maximum and
  remaining debit, fenced creation count, uncertain outcomes and next replay
  phase. The section survives a later identity or decision blocker, and
  `no_effects_started` remains false after a paid creation intent. Once effects
  exist, the report suppresses generic fresh-install proposal labels and points
  only to review and explicit resume of the retained session.

### 🧪 Testing

- Replaces the one-asset bootstrap journey with an IC-profile PocketIC proof
  that starts at zero, obtains five sequential Cycles Ledger creations,
  provisions five workloads without manual supply and retains then clears the
  typed Root retry diagnostic.
- Adds direct join-boundary replay coverage and a source-order guard requiring
  join, synchronization and activation to use the same successor authority;
  missing, premature, wrong-plan and later-revision evidence remains rejected.
- Adds progress-aware host-poll and demand-target unit coverage while retaining
  the existing terminal runtime-activation PocketIC journey.
- Registers the deliberate host wait in the governed blocking-wait inventory
  and keeps background/watchdog pool recovery visibly bound to a fresh read of
  the configured minimum while batch-driven maintenance retains exact demand.
- Adds direct remaining-debit/digest, exact cross-patch gate, read-only journal
  inspection, bounded `STATE_UNAVAILABLE` retry and CLI recovery-report tests.
  A disposable read-only probe against the retained Toko Miner session
  validated three fenced creations, zero remaining operator debit and
  `store_bootstrap_verification` as the next phase; the probe was removed and
  no downstream file or IC state was changed.

## 0.109.0 - 2026-08-23

### ➕ Added

- Adds required protected `[admission]` Fleet input with one bounded canonical
  Fleet Principal set plus optional Component-Spec and Fleet-Subnet-Root
  narrowing rules. Anonymous, duplicate, noncanonical, widening, unknown and
  first-excess authority rejects before effects.
- Binds the validated generation-one template and every derived Root/Component
  projection digest into the no-effect plan, then binds the installed policy
  to the exact allocated Fleet identity.
- Carries that same installed policy through the immutable install plan,
  Coordinator install journal and init payload, canonical Fleet Registry hash
  and generated Coordinator Candid contract.
- Renders only policy and projection counts plus digests in ordinary plan text;
  protected policy members remain in the explicit plan document.
- Adds one Coordinator-owned generation-one authority at memory ID 64 with
  controller-only `MutateAdmission`, protected paged `Admission` status and
  operation lookup. Exact current/last replay is bounded; idempotent requests
  are terminal without generation change, while effective requests retain one
  exact successor and stop at `Planned` until the convergence batch owns
  participant effects.
- Reserves memory IDs 64 and 65 for the accepted Coordinator and Root admission
  owners and moves the generic core range above them. The canonical memory
  policy admits only the exact Coordinator/Root admission keys at those IDs.
- Adds the named managed `FleetAdmissionProjection` role capability and reuses
  memory ID 61 for one exact target-bound active projection, optional prepared
  successor and retained receipt under a measured 32 KiB bound. Declared Roots
  and built-in Coordinator/Store roles do not receive that capability.
- Adds explicit `[roles.<role>] fleet_admission = true` enrollment. The role
  contract selects projection storage and generated admission surfaces only
  for enrolled non-Root roles; omission is a fail-closed non-enrollment and
  Roots reject the flag. Protected plans bind the canonical enrolled-role list
  for each participating Component Spec.
- Carries the Root-derived effective projection only in enrolled
  Component/child init payloads, rejects projection-presence disagreement with
  the compiled role, retains it fenced and opens it only after the existing
  Root-owned activation reaches `Active`. Same-release restart restores the
  exact generation/digests without reseeding.
- Adds protected bounded managed `Admission` status and
  `caller::is_fleet_admitted()`. The guard reads only the observed caller and
  one local open projection; missing, invalid or fenced state denies.
- Adds synchronous `canic::fleet_admission::require_caller()` for an IcyDB,
  IC-CDK or other endpoint framework composed inside the same managed
  canister. The facade acquires `msg_caller()` itself and returns that exact
  Principal or one typed access error from the existing local projection; it
  accepts no caller argument and owns no storage, lifecycle work, timer or
  remote lookup.
- Adds replay-safe live `canic admission plan`, `apply` and `status` mutation
  over the sole Coordinator authority. The read-only plan retains exact sorted
  per-Root participant catalogs; the bounded role request carries their digest
  and count, and the Coordinator rejects a mismatched aggregate before
  Registry publication.
- Advances each effective add/remove through durable Coordinator and Root
  prepare, perimeter-fence, activate and open journals. Managed targets retain
  one complete successor projection, exact receipts replay without another
  effect, and terminal status replaces current state monotonically.
- Keeps a Root with zero enrolled targets in the exact Fleet catalog under a
  nonzero empty-catalog digest. Its existing Root journal advances no-effect
  aggregate receipts, so explicit enrollment does not make a backend-only Root
  block convergence or create a second authority.
- Fences Component allocation while admission convergence is active and gives
  a newly provisioned Component the current converged projection before its
  protected ingress opens. Medic reports the protected policy and operation
  state without becoming another owner.

- Deletes the runtime-whitelist DTO, model, policy, ops, workflow, API, stable
  store, command/status variants, replay-manifest entry and
  `caller::is_whitelisted()` predicate. No alias, decoder or fallback remains.

### 🐛 Fixed

- Removes the fresh-install zero-Ready-pool deadlock without adding another
  creation owner. Root acceptance advances one bounded pass of the existing
  Root-owned Canister-pool journal, revalidates the exact Registry and Store

- Allows host restart after initial Fleet services legitimately advance the

  immutable-authority successor bound to the exact compiled fresh-install
  operation, plan hash, source Registry, published Registry and retained

- Retains one bounded typed per-Root provisioning failure in the Coordinator
  journal and exposes it only while it matches the current durable retry Root

- Reconciles the complete ordinary release gate with the maintained admission
