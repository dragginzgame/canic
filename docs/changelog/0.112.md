# Canic 0.112 Changelog

## [0.112.0]

- **Performance projection:** bounded public and protected diagnostic reports
  consume the same full aggregate state. Public rows carry source overflow and
  timer registration directly, retaining existing public shapes, row budgets and
  history policy. Host timer comparison trusts that quality and admits wide
  instruction totals. No registration is reconstructed from display labels.

- **Public operation ownership:** project lifecycle, canister-operation,
  aggregate funding and top-up counters directly from typed bounded owners.
  Assign units and history kinds at their producers, removing the diagnostic-row
  round-trip and name-based classification. Public funding selects only fixed
  global groups without walking child rows. Per-child funding and per-target
  refill amounts remain protected; public clients needing them must move to the
  protected Core query. Public Candid shapes and authorization are unchanged
  ([#104 — Keep principal-scoped funding out of public operations](https://github.com/dragginzgame/canic/issues/104)).

- **Refill metric identity:** derive status counts by trigger kind, phase and
  status before index selection. Automatic sequence numbers and folded error
  codes no longer create duplicate labels or starve manual counts. Protected and
  public projections share these dimensions; retained-record counts remain
  gauges. The internal status-count view carries `trigger_label` and `phase`
  instead of the sequence-bearing trigger/error pair. Rebuild and replacement
  use the same normalization. Durable records, policy usage, paid-effect recovery
  and protected target amounts are unchanged
  ([#97 — Aggregate refill metric identities before selection](https://github.com/dragginzgame/canic/issues/97)).

- **Protected measurement contract:** replace `MetricValue::CountAndU64` with
  `Measurement { count: u64, total: u128, count_overflowed: bool,
  total_overflowed: bool }`. Exact wide rows remain present. `PerfEntry` carries
  `aggregate` rather than flattened count/total fields, removing the parallel
  quality-losing projection. Update direct Rust callers and Candid/JSON clients
  together; JSON uses the `measurement` tag and exact numeric literals. The
  runtime instruction probe reads aggregate state and admits exact totals only
  when representable in its existing `u64` test report.
  Current generated payloads derive from the Contracts DTO; Coordinator/Store
  canonical Candid services do not expose this metric payload and are unchanged.

- **Timer diagnostics:** append `work_started` and `latest_armed_delay_ms` metric
  suffixes to the existing timer identity labels. Starts are a scalar count;
  latest delay is a scalar millisecond value, not a sum. Absent delay emits no
  row, while measured zero remains visible. More diagnostic rows can require
  another protected page. CLI means apply only to measurements; overflowed
  fields display lower bounds and unavailable means. Existing nearest-half-up
  rounding remains, using shared exact ratio arithmetic. Bounded instruction
  audit helpers check quality and narrow explicitly at their own report boundary.
  Public/protected endpoint permissions and exclusive/async attribution remain
  unchanged. Related: [#518 — Wide totals at report boundaries](https://github.com/dragginzgame/canic/issues/518),
  [#523 — Preserve tracked metric quality in reports](https://github.com/dragginzgame/canic/issues/523),
  [#600 — Separate timer delay from measurement averages](https://github.com/dragginzgame/canic/issues/600).

- **Scalar recording evidence:** the existing runtime-probe sampling fixture
  brackets its public Wasm-store recorder with the IC instruction counter and
  returns `scalar_record_instructions` separately from `sample_instructions`.
  The owning timer-authority case reports first-use and warm observations and
  rejects missing/zero evidence. It adds no production endpoint or cost budget;
  sampling/history measurements do not stand in for recorder instructions
  ([#535 — Shared scalar diagnostic counters](https://github.com/dragginzgame/canic/issues/535)).

### ⚠️ Breaking and required actions

- **Scalar counter ownership:** Canic-owned runtime event and diagnostic cycle
  accumulators use IC Metrics `MeasurementCounter`, retaining their existing
  keys, labels, attribution, reset and lifecycle owners. Protected payloads become
  `Count { count: u128, exact: bool }` and `U128 { value: u128, exact: bool }`.
  Update Rust patterns and Candid/JSON clients together; JSON retains the `count`
  and `u128` tags. `exact: false` admits only a lower bound, including forwarded
  untracked readings at their numeric cap. Canic-owned exact caps remain exact
  until an actual overflow; grouping preserves source quality. CLI displays
  lower bounds with `>=`, supplies no scalar means, and `--nonzero` retains
  inexact zero. Public process/operation counters carry actual overflow into
  existing history admission without changing public Candid shapes or coverage
  identity. Authoritative balances, quotas, budgets, durable records and policy
  arithmetic remain with their existing owners. No stable adapter or dependency
  upgrade is introduced ([#535 — Shared scalar diagnostic counters](https://github.com/dragginzgame/canic/issues/535)).

- **Memory runtime:** adopt Memory 0.44 with one Canic-owned runtime and injected
  component handles. Allocation reports derive byte totals from measured pages
  and buckets; the storage-format hard cut requires a clean reinstall. Bootstrap
  now returns `MemoryBootstrapError` for construction, runtime access and commit
  failures; update exhaustive error matches.

- **Host filesystem APIs:** adopt Host 0.23's explicit publication, path-resolution
  and lock-acquisition APIs, preserving write permissions and operation exclusion.
  Candid normalization uses Host Text directly.

- **Application Auth hard cut:** remove delegated-token issuance/retrieval,
  `auth::authenticated(...)` guards, and delegated-token session commands/status.
  Root proof provisioning and role attestations remain supported. Portable Auth
  enrollment and endpoint integration remain unfinished; application session
  admission is unavailable ([#491](https://github.com/dragginzgame/canic/issues/491)).

- **Public Rust identities:** Auth DTOs use protocol-types 0.7; Backup errors and
  custody expose IC Backup 0.24 and Host dependency types. Align direct dependencies,
  update matches and struct literals, and rebuild against the canonical owners
  ([#517 — Resolve exposed upstream type changes](https://github.com/dragginzgame/canic/issues/517)).
- **Memory composition:** pass an explicit provider to
  `canic::start!(memory = application_memory(), ...)`, extend
  `canic::memory::framework()` requests, and select the checked pool and admission.
  Replace retired declaration/admission macros and the no-argument runtime facade
  ([#527 — Explicit memory requests and host bootstrap](https://github.com/dragginzgame/canic/issues/527)).
- **Synchronous access:** custom predicates implement synchronous
  `canic::access::AccessCheck::eval`; remove `AsyncAccessPredicate`, async-trait
  attributes and local authentication awaits. External issuance, provisioning and
  renewal retain their asynchronous calls ([#531 — Synchronous endpoint access plans](https://github.com/dragginzgame/canic/issues/531)).
- **Wide counters:** instruction aggregate totals are `u128`, and timer instruction
  totals use Candid `nat` instead of `nat64`. Update bindings; bounded u64 test
  views omit unrepresentable totals while raw timer JSON retains the exact integer.
- **Journals and deployment:** current backup/restore journals require original
  `command_custody`; session records use a generation/binding header and separate
  bounded vectors. Rebuild the complete family and cleanly reinstall across
  releases; same-release interruption recovery and cycle custody remain required.
- **Backup documents:** manifests, plans, mappings and journals have a 64 MiB
  encoded JSON limit, separate from snapshot artifact limits. Writers refuse
  oversized documents before publication; readers retain complete-file decoding
  and existing schema/receipt validation
  ([#562 — Bound Backup record acquisition](https://github.com/dragginzgame/canic/issues/562)).

- **Auth status capability:** generate the managed Auth status endpoint and its
  request/response types only with delegation-proof issuer capability. Local
  application authorization alone no longer emits empty Candid enums.

- **Auth verification callbacks:** session fixtures consume Auth 0.7's decoded
  claims through the shared verifier callback, avoiding duplicate decoding while
  retaining real signature verification and the protected admission budget.

### 🔧 Build inputs, declarations and retained artifacts

- **Storage visibility checks:** keep storage crate-private while allowing internal
  Auth record reexports to use the visibility required by Clippy. The layering
  guard checks that boundary explicitly and retains record-export checks elsewhere.

- **Host caller alignment:** explicitly retain the existing missing-path depth
  policy in Backup publication and build output resolution. Open regular lock
  files, then acquire exclusive locks before build materialization, component
  operations or Fleet recovery. Keep the descriptor alive through the operation.
  Candid extraction retains bounded normalization and typed UTF-8 failures through
  the direct Host Text dependency.

- **Shared build and restore contracts:** derive artifact output directories from
  IC Build's selected Cargo profile, and use Testkit's successful restoration
  receipt directly instead of reconstructing one from baseline metadata.

- **Cargo observations:** use published IC Build 0.9 and Cargo's canonical
  metadata schema; remove Canic's private schema, feature-argument builder and
  unbounded metadata/tree capture. Keep role interpretation, selected export
  authority, command environments and bounded sanitized diagnostics in Canic.
  Embedded-fixture normalization also uses canonical metadata with explicit
  output bounds while retaining locked/offline resolution and exact local-version
  rewriting; external package selections remain unchanged
  ([Build #33 — Share Cargo observations](https://github.com/dragginzgame/ic-build/issues/33)).

- **Build-script exports:** retain Canic include paths from Cargo's current
  compiler-artifact and build-script messages. Verify the selected package ID,
  canonical manifest and config/profile/network/target/environment recipe before
  observing them. Unrelated producers cannot add inputs or poison decoding;
  first-seen and changed selected external inputs still refuse the current build
  ([#553 — Scope retained build-script exports](https://github.com/dragginzgame/canic/issues/553)).
- **Selected inputs:** IC Build 0.3 owns bounded inventories, input digests,
  before/after guards and Cargo depfile parsing. Select the current App/dependency
  graph and generated Fleet targets, retain external input custody, and refuse
  newly observed or changed inputs ([#530 — Converge build-input reuse on IC Build](https://github.com/dragginzgame/canic/issues/530)).
- **Declarations:** use IC Build artifact transactions and retained records instead
  of private JSON caching. Preserve four-worker input-order batches, extractor
  admission, normalized output, the 4 MiB cache budget and fresh extraction after
  cache I/O failure ([#528 — Replace the private declaration cache](https://github.com/dragginzgame/canic/issues/528)).
- **Transform publication:** supply Host's explicit replace and staging-permission
  policy for Wasm shrink and optimization, preserving qualification before
  publication and the existing umask-controlled artifact permissions.
- **Artifact custody:** IC Build retains completed Cargo outputs and temporary
  staging across later compilations. Canic keeps transform order, source/output
  admission, exact release binding and qualification before durable publication
  ([#529 — Share artifact staging and retention](https://github.com/dragginzgame/canic/issues/529)).
- **Cargo grouping:** select published IC Build rather than a sibling-path engine.
  Duplicate or empty package names refuse before effects, empty plans are
  effect-free, and failures retain status, bounded diagnostics and truncation
  ([Build #1 — Extract the generic build and artifact engine](https://github.com/dragginzgame/ic-build/issues/1)).
- **Reuse boundaries:** preserve complete-release namespaces, lock/cancellation,
  environment/tool identity and optional rejection diagnostics. Old private cache
  files are no longer consumed; adoption performs no implicit artifact cleanup.

### 🔧 Backup custody and bounded restore

- **Locks and references:** use IC Backup's journal, command and layout guards;
  persist exact original custody before dispatch and hold guards through durable
  reference release. Missing or replaced custody refuses; fresh complete terminal
  bytes and exact quiescence govern effect-free replay
  ([#513 — Converge on the IC Backup engine](https://github.com/dragginzgame/canic/issues/513)).
- **Processes:** remove raw descriptor handles and transfer the custody-spawned
  child into Host's bounded capture and cleanup owner. Keep explicit output limits
  and deadlines, one spawn, descendant exclusion and cancellation cleanup
  ([Host #64 — Share private regular sidecar admission](https://github.com/dragginzgame/ic-host-tooling/issues/64)).
- **Checksums:** use upstream checked digest records for artifact, plan, journal,
  manifest and restore-plan validation. Equivalent hex case agrees without
  rewriting retained records; malformed or different digests and bytes refuse.
- **Authority:** Canic retains Fleet topology, paid-effect admission, original
  restore authority and product journal ordering. Generic engine convergence and
  live creation remain separate from adopting the shared guards.
- **Record acquisition:** use Host's descriptor admission and bounded stream
  reader for layout records, restore execution and CLI manifest/mapping/status
  reads. Refuse special files before reading, preserve native missing-file and
  JSON failures, and keep explicit path aliases under existing layout custody
  ([#562 — Bound Backup record acquisition](https://github.com/dragginzgame/canic/issues/562)).

- **Record helpers:** Fleet and build-lock records use Contracts' required-nullable
  decoder directly; omitted fields still reject while explicit null remains valid.
  Backup owns one pure Unix-seconds marker parser for preflight validation, runner
  expiry calculation and CLI sorting/display. Each caller retains its explicit
  rejection, skip, display or clock-fallback policy.

- **Private staging:** download and restore staging use published Host's
  create-new private-directory primitive, including final no-follow admission and
  parent synchronization. Preserve native error kinds and creation-phase evidence;
  Canic retains stale-stage reconciliation, permissions checks and cleanup policy.
  Broader held-directory publication follows the owning
  [Host directory work](https://github.com/dragginzgame/ic-host-tooling/pull/118).

### 🔧 Authentication and runtime accounting

- **Proof verification:** IC Auth owns Root/issuer canister-signature, DER,
  certificate, Merkle, time-window and secp256k1 verification. Canic retains exact
  signed bytes, protected network/key selection, clock bounds and refusal codes
  ([#491 — Extract shared authentication, token and session machinery](https://github.com/dragginzgame/canic/issues/491)).
- **Token issuance:** use upstream immutable preparation and finishing, retaining
  Canic's 16-grant/32-scope bounds, authority deadlines and signing/retrieval
  custody. Project existing wire fields without changing session/replay clocks
  ([Auth #25 — Expose pure token preparation](https://github.com/dragginzgame/ic-auth/issues/25)).
- **Certificates and requests:** delegate lifetime/grant rules and canonical
  session request hashes to their pure upstream owners. Invalid Canic role
  projection refuses before shared callbacks, while configured scope/TTL and
  replay checks remain local ([Auth #30 — Share certificate issuance validation](https://github.com/dragginzgame/ic-auth/issues/30))
  ([Auth #32 — Share canonical session requests](https://github.com/dragginzgame/ic-auth/issues/32)).
- **Sessions:** share admission, live authorization, signatures and certification
  publication; keep synchronous atomic storage, bounded indexes and exact retry
  leases. Status/audit reads recheck current authority, and every delegated proof
  presentation verifies against current Root policy rather than a positive cache.
- **Enrollment contract:** add passive Root-managed request/snapshot types binding
  exact Fleet and receiver installations, a fresh challenge, monotonic revision
  and generation, approved issuer keys/scopes and revoked key IDs. Root delivery,
  receiver refresh and the Auth 0.6 endpoint integration remain unfinished;
  these types alone do not enable portable credential admission
  ([#491 — Complete session integration](https://github.com/dragginzgame/canic/issues/491)).
- **Session identities:** keep transport caller separate from issuer/account
  identity. Replay storage and capacity belong to the caller; remove the account
  field from replay records. This storage cut joins the required clean reinstall,
  and persist canonical login denial with session admission/logout atomically.
  Logout retains the original login binding and replay custody; mismatched
  repeated logout refuses without changing storage. Restoration checks bounded
  login-pool occupancy and rejects conflicting session/login bindings or a
  revoked login with a retained session.
  Runtime clock restoration, cleanup and endpoint integration remain unfinished.
- **Session diagnostics:** preserve capacity and clock refusals through both
  portable credential verifiers; distinguish revoked credentials from storage
  failures. The endpoint workflow remains under integration.
- **Scope and allocation:** local sessions require the role's explicit
  `auth.allowed_token_scopes` ceiling; omission grants no scope. Model separate
  session/replay allocations and gate optional projections on their actual
  consuming capabilities.
- **Async accounting:** share non-generic measurement state while preserving lazy
  initialization, per-poll/nested attribution, cancellation, unwind cleanup and
  completed-handler destruction inside its measured scope
  ([#526 — Share async performance instrumentation](https://github.com/dragginzgame/canic/issues/526)).
- **Metrics and timers:** use upstream wide aggregates and typed initial-schedule
  policies. Create lifecycle one-shots with their schedule atomically; retained
  registrations stay inactive until their owner starts them.

  keeping malformed input separate and in-range unknown codes successful
  ([#547 — Distinguish diagnostic range errors](https://github.com/dragginzgame/canic/issues/547)).

  authentication and block-budget/hash-chain validation. Canic retains mint

  ([Host #71 — Qualify shared Candid and interface contracts](https://github.com/dragginzgame/ic-host-tooling/issues/71)).

  Host owns fallible output-observer cleanup and bounded foreground diagnostics.

  ([Host #66 — Share process completion and fallible observers](https://github.com/dragginzgame/ic-host-tooling/issues/66)).
- **Local replica queries:** IC Agent owns envelopes and response decoding; Canic
  retains anonymous selected-origin HTTP, no proxies/redirects, a 30-second
  deadline and one request on HTTP refusal ([#458 — Share Host mechanisms](https://github.com/dragginzgame/canic/issues/458)).
- **Funding replies:** decode the canonical Registry response and unwrap its
  endpoint result once, retaining typed remote rejection
  ([#436 — Fix Registry reply decoding in cycles funding](https://github.com/dragginzgame/canic/issues/436)).
- **Provisioning evidence:** retain the first failed target, method, substep, raw

- **Operator recovery:** Fleet ensure JSON reports `provisioning_failure` and a
  `resume` action retaining the approved digest, signer, environment and inputs.
  Resume never combines `--apply` with review-only `--reinstall` or grants new

- **Failure contract:** provisioning records require nullable `dependency`;
  evidence-bearing values are `Clone`, and Host errors/progress box that evidence.
  Update direct rejection callers and consumer bindings; deterministic Store
  refusal requires review while transport failure backs off.
- **Configuration reads:** refuse `icp.yaml` beyond its existing 1 MiB bound before
  gateway/network inspection. Preserve missing-file, symlink and UTF-8 behavior
  ([#509 — Reject oversized ICP configuration](https://github.com/dragginzgame/canic/issues/509)).
- **Fleet observations:** share retained balance/completion updates without losing
  earlier observations when a balance is missing. Keep workflow authority,
  persistence ordering and retries ([#452 — One resumable Fleet Ensure workflow](https://github.com/dragginzgame/canic/issues/452)).

  ([Shared #121 — Retain evidence after shared-store refusal](https://github.com/dragginzgame/shared-tooling/issues/121)).

### ➕ Checkpoint participant SDK

- **Participant state:** provide durable application-owned records with one
  canonical phase enum, exact Root/receiver/unit bindings, original restore-source
  retention and a release sequence high-water mark. Exact replay survives
  serialization and delayed preparation cannot refreeze a released participant.
- **Installed participant coverage:** exercise durable business freeze across
  lifecycle restoration, delayed prepare/release ordering, snapshot restoration
  with fresh authority and repeated acknowledgements without duplicate hooks.
  The driver retains restore authority; this does not qualify Root orchestration.
- **Root journal foundation:** retain exact unit membership, issuance sequence
  and participant acknowledgements across serialization. Stale or changed requests
  refuse; all participants must acknowledge before preparation or release completes.
  Stable Root orchestration and snapshot execution remain unfinished.
- **Public binding:** expose the canonical checkpoint binding through the Canic
  SDK so application endpoints can use its Root authentication predicate.
- **Endpoint predicate:** authenticate the issuing Root against independently
  installed receiver authority; controller/subject substitution and changed
  installation, Registry or policy bindings refuse.
- **Limitation:** applications still own durable business freeze and hook ordering;
  these local transitions do not enable live capture. Coordinated Root capture,
  membership exclusion and same-release restore/release remain under
  ([#550 — Coordinated Fleet backup checkpoints](https://github.com/dragginzgame/canic/issues/550)).

- **Delivery scope:** 0.112 ships the completed integrations and participant SDK;
  coordinated live-backup implementation has resumed, but remains unavailable.
- **Live creation:** `canic backup create` remains unavailable until its Fleet
  authority and consistency adapter is complete
  ([#394 — Live backup creation remains unavailable](https://github.com/dragginzgame/canic/issues/394)).
