## [0.112.0]

- Use crates.io IC Build 0.1.1 for generic feature-safe Cargo grouping and
  build/cache consumers, retiring the incubation sibling-path exception;
  keep release admission and PocketIC lifecycle at their existing owners
  ([IC Build #1](https://github.com/dragginzgame/ic-build/issues/1)). Grouping
  retains typed Cargo failure status, bounded diagnostics and truncation evidence;

  remain effect-free empty plans.

### Breaking

- The coordinated family requires a minor release: Auth protocol-types 0.3,
  Backup 0.15 and Host 0.12 values cannot cross the maintained 0.5, 0.21 and 0.15
  public boundaries. Direct Rust consumers must align dependencies and rebuild.
  The maintained public family uses protocol-types 0.5, Backup 0.21 and
  Host FS 0.15. Use the Canic-exported Auth/Backup types when an independent
  upstream type is unnecessary. No compatibility adapter is supplied
  ([#517](https://github.com/dragginzgame/canic/issues/517)).

- Protected provisioning failure records and DTOs add an explicit nullable
  `dependency` field; failure values containing owned evidence are `Clone`
  rather than `Copy`. Host errors box optional dependency evidence, and host
  progress boxes its optional Root failure so ordinary errors/events stay small.
  JSON retains the same object shape. Direct control-plane error callers pass
  the raw rejection code and text to `InternalError::with_platform_rejection`.
  Current serialized records require field
  presence. Update struct literals and use borrowing, cloning and boxing as
  appropriate, rebuild the complete deployed
  family, and cleanly reinstall across releases. An old frozen operation must
  retain its issued authority and cycle-safe disposition; a new CLI does not
  replace its installed Root. Same-release interruption recovery remains exact
  ([#516](https://github.com/dragginzgame/canic/issues/516),
  [#517](https://github.com/dragginzgame/canic/issues/517)).

- Local application sessions now require the role's explicit
  `auth.allowed_token_scopes` ceiling; omission accepts no grant. Session scopes
  must be a subset. The durable contract uses a generation/binding header and
  separate bounded session/replay vectors carrying canonical SDK session bytes. Rebuild
  consumers with the configured ceilings and cleanly reinstall across releases;
  no predecessor reader or migration is provided
  ([#491](https://github.com/dragginzgame/canic/issues/491)).

### Blob installation refusal qualification

The managed qualification fixture retains each node's exact original installation
bytes for bounded test assertions. It does not grant reset or recovery authority.
Dedicated/embedded cases vary only nested application arguments and reject unknown
fields and extra Candid arguments. A refused reinstall preserves stable bytes and
configuration while retaining Blob's recovery fence; only the existing operator
same-instance recovery workflow activates the original installation. Older locks
and failed attempts remain separate evidence under #524. Fixture locks align with
the already selected published Blob/Auth and Timers 0.21 APIs. Package versions and
release effects remain unchanged by this scoped qualification.
