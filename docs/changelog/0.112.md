### 🔧 Backup custody and bounded restore

- **Locks and references:** use IC Backup's journal, command and layout guards;
  persist exact original custody before dispatch and hold guards through durable
  reference release. Missing or replaced custody refuses; fresh complete terminal
  bytes and exact quiescence govern effect-free replay
  ([#513 — Converge on the IC Backup engine](https://github.com/dragginzgame/canic/issues/513)).
- **Processes:** remove raw descriptor handles and transfer the custody-spawned
  child into Host's bounded capture and cleanup owner. Keep explicit output limits
  and deadlines, one spawn, descendant exclusion and cancellation cleanup
  ([Host #64 — Share private regular sidecar admission](https://github.com/dragginzgame/ic-host-tooling/issues/64)).
- **Checksums:** use upstream checked digest records for artifact, plan, journal,
  manifest and restore-plan validation. Equivalent hex case agrees without
  rewriting retained records; malformed or different digests and bytes refuse.
- **Authority:** Canic retains Fleet topology, paid-effect admission, original
  restore authority and product journal ordering. Generic engine convergence and
  live creation remain separate from adopting the shared guards.
- **Record acquisition:** use Host's descriptor admission and bounded stream
  reader for layout records, restore execution and CLI manifest/mapping/status
  reads. Refuse special files before reading, preserve native missing-file and
  JSON failures, and keep explicit path aliases under existing layout custody
  ([#562 — Bound Backup record acquisition](https://github.com/dragginzgame/canic/issues/562)).

- **Record helpers:** Fleet and build-lock records use Contracts' required-nullable
  decoder directly; omitted fields still reject while explicit null remains valid.
  Backup owns one pure Unix-seconds marker parser for preflight validation, runner
  expiry calculation and CLI sorting/display. Each caller retains its explicit
  rejection, skip, display or clock-fallback policy.

- **Private staging:** download and restore staging use published Host's
  create-new private-directory primitive, including final no-follow admission and
  parent synchronization. Preserve native error kinds and creation-phase evidence;
  Canic retains stale-stage reconciliation, permissions checks and cleanup policy.
  Broader held-directory publication follows the owning
  [Host directory work](https://github.com/dragginzgame/ic-host-tooling/pull/118).

### ➕ Checkpoint participant SDK

- **Participant state:** provide durable application-owned records with one
  canonical phase enum, exact Root/receiver/unit bindings, original restore-source
  retention and a release sequence high-water mark. Exact replay survives
  serialization and delayed preparation cannot refreeze a released participant.

  lifecycle restoration, delayed prepare/release ordering, snapshot restoration
  with fresh authority and repeated acknowledgements without duplicate hooks.
  The driver retains restore authority; this does not qualify Root orchestration.
- **Root journal foundation:** retain exact unit membership, issuance sequence
  and participant acknowledgements across serialization. Stale or changed requests
  refuse; all participants must acknowledge before preparation or release completes.
  Stable Root orchestration and snapshot execution remain unfinished.

  SDK so application endpoints can use its Root authentication predicate.
- **Endpoint predicate:** authenticate the issuing Root against independently
  installed receiver authority; controller/subject substitution and changed
  installation, Registry or policy bindings refuse.

  these local transitions do not enable live capture. Coordinated Root capture,
  membership exclusion and same-release restore/release remain under
  ([#550 — Coordinated Fleet backup checkpoints](https://github.com/dragginzgame/canic/issues/550)).
