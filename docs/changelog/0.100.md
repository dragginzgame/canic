# Canic 0.100 Changelog

## [0.100.91] - 2026-08-02 - Root Store Recovery and Host Protocol Consolidation

### 🔧 Changed

- Moves bootstrap and publication Wasm Store creation onto one root-owned
  durable operation. The root freezes exact artifact, controller, cycles and
  cost-guard authority before creation, journals the returned principal before
  installation, and records installation before activation and inventory
  publication.
- Recovers uncertain install outcomes from exact live controller and module
  evidence. An unresolved creation intent remains fail-closed and never
  repeats the paid create; an absent module permits a fresh journalled install
  attempt, while the expected module resumes activation and any drift fails.
- Cascades a newly installed Store as an explicit direct root leaf and commits
  its principal-derived binding to runtime inventory atomically after
  activation. Prepared roots retain prepared Stores; active roots advance
  Stores to their current credential generation.

### 🧹 Cleanup

- Deletes the Store Registry importer and the matching terminal-deletion row
  cleanup. Bootstrap, publication and garbage collection now share only the
  canonical root-owned Store inventory and durable lifecycle records.
- Routes terminal Coordinator Registry and Fleet Subnet Root summary queries
  through the canonical typed no-argument Canister protocol operation. Fleet
  catalog closeout retains parallel root collection and its worker-panic
  boundary while deleting its private ICP JSON mode, invocation/response
  adapters and generic query decoder.
- Removes the one-call install command runner left after fresh-install effect
  consolidation. The shared installation operation now invokes the maintained
  ICP status runner directly and retains the same post-command reconciliation.

### 📊 Audit

- Removes 44 net host source lines, one duplicate typed-query stack and one
  stranded command wrapper.

### 🧪 Testing

- Focused stable-state coverage proves invalid creation observations and
  noncanonical bindings cannot advance the journal, while terminal commit adds
  inventory and clears progress in one mutation. The focused Fleet PocketIC
  journey exercises Store bootstrap, direct activation and subsequent
  Component/child creation.
- Focused install-truth ordering tests cover validation, summary collection and
  publication order; strict host-library lint compilation covers terminal
  Registry/summary queries and fresh-install command reconciliation.
