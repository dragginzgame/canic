# Canic 0.100 Changelog

## [0.100.45] - 2026-07-29 - Bounded Component Directory Pages

### ➕ Added

- Adds a public internal Component Directory page query authenticated inside
  workflow against the caller's exact active top-level Component or
  registered descendant binding. A caller may query only its own Component
  tree under the exact current Directory head.
- Adds bounded optional parent, child-role and lifecycle-status filters. Each
  entry reconstructs the complete protected `ComponentChildBinding` from the
  normalized partition and child row and includes child kind, installed
  artifact hash and lifecycle status.

### 🔧 Changed

- Reads normalized child traversal indexes in canonical
  `(parent_canister_id, role, canister_id)` order without materializing a full
  descendant vector. Parent and parent-role filters use exact stable-key
  ranges; every page examines at most 100 canonical rows, so sparse residual
  filters remain bounded and continue through the returned cursor.
- Makes continuation cursors opaque and limits them to 2 KiB. Each cursor
  carries the exact Component Directory head, filters and last canonical key;
  malformed, stale or cross-filter reuse fails instead of mixing Registry
  revisions.
- Admits the read-only page query through the Prepared-root recovery fence and
  replay-policy inventory. Initial root activation still seals only its exact
  top-level Component inventory; later dynamic descendants remain outside
  that immutable initial seal.

### 🧪 Testing

- Covers canonical multi-parent traversal pages, exact parent-role ranges,
  active child projection, parent/role/status filtering, end-of-directory
  continuation, opaque cursor round-trip and stale-filter rejection.
- Covers the Candid DTO boundary, protocol constant/facade alignment, public
  workflow-authenticated endpoint guard, replay-policy classification and
  Prepared-root fence.

## [0.100.43] - 2026-07-29 - Active Child Registry Membership

### ➕ Added

- Adds a public internal child-membership endpoint authenticated by the exact
  immediate parent. It accepts only a child with terminal Directory and
  runtime receipts, independently verifies the active target and then
  atomically changes its normalized Registry row from `Prepared` to `Active`.
- Freezes a child-specific membership receipt containing the exact active
  Component head, descendant digest, reserved and committed counts, encoded
  bytes, Directory observation and authority hash. This richer evidence
  reconstructs the original response even when unrelated reservations or
  commits later advance the owning partition.

### 🔧 Changed

- Advances the owning Component partition by one revision using an O(1)
  status-transition descendant digest, replaces exact root and Component byte
  accounting and derives the following current Component Directory in the
  same root-local transaction.
- Reuses one top-level/child convergence workflow to synchronize that
  Directory to the already-active runtime, reconcile an uncertain response
  by status and independently re-query it. A later valid current head covers
  an exact retry while the returned response remains the original
  membership-bound authority.
- Revalidates the requesting parent after all awaited calls and commits the
  fixed-size terminal synchronization bit last. Runtime activation evidence
  remains immutable and no unrelated descendant receives a call.

### 🧪 Testing

  mutation, independently terminal retry, wrong-hash rejection and exact
  reconstruction after a later same-revision reservation changes current
  capacity accounting.

  the child and every bounded affected active member have been independently

## [0.100.40] - 2026-07-29 - Normalized Direct-Child Commitment

### ➕ Added

- Adds a public internal child-commit endpoint for one exact already-verified
  `(ComponentInstanceId, operation_id)`. Workflow authenticates the same
  registered immediate parent and independently reverifies the accepted
  Store artifact, live module, sole-root controller and retained child
  binding before mutation.
- Adds an immutable child commitment receipt that freezes the exact Component
  Registry head, descendant digest and counts, encoded-byte authority,
  Directory time and Directory-authority hash. Exact retry reconstructs the
  original response even after later reservations or Registry revisions.

### 🔧 Changed

- Atomically replaces `Verified` with `Committed`, inserts the normalized
  child row, principal index and parent/role traversal index, and transfers
  one reserved descendant to committed. The parent-role and root managed
  descendant counts remain unchanged because they already count reserved plus
  committed non-removed descendants.
- Replaces the maximum install precharge with exact terminal bytes in the
  same stable compare-and-commit. No capacity check or fallible Registry
  insertion remains after the child is installed.
- Advances the active Component partition revision and content hash over one
  protected O(1) descendant-content digest rather than rescanning as many as
  20,000 normalized child rows on every Registry read. The derived Directory
  head binds the new revision, digest-backed content hash, synchronization
  time and committed-descendant count.
- Commits the child row as `Prepared`. Installation and Registry commitment
  do not pretend its runtime is active; exact Directory distribution,
  activation and active-membership promotion remain separately observed
  transitions.

### 🧪 Testing

- Covers atomic reserve-to-commit accounting, normalized row/principal/
  traversal insertion, prepared child lookup, head and Directory advancement,
  excess-precharge release, interruption reload and exact commit retry.
- Covers child commit Candid, protocol, public workflow guard, replay-policy
  and Prepared-root fence surfaces.

## [0.100.39] - 2026-07-29 - Verified Direct-Child Installation

### ➕ Added

- Adds a public internal child-install endpoint that accepts only an exact
  already-created `(ComponentInstanceId, operation_id)` from the same
  registered immediate parent. The root resolves the accepted child-role
  artifact from its active local Store and derives the immutable
  `ComponentChildBinding` from the owning Component, immediate parent, role
  and returned principal.
- Extends durable child progress through
  `Created → InstallIntent → Installed → Verified`. Install intent freezes the
  exact raw module hash, chunk source, child binding, cost-guard settlement
  and terminal Registry charge before the management install call.
- Freezes the compact parent/role/child traversal-index shape required by the
  following normalized child commitment.

### 🔧 Changed

- Reuses the maintained chunked Store installer, deployment cost guard,
  management status query and retained-binding query. Independent
  verification requires the exact installed module, the Fleet Subnet Root as
  sole controller and the target-retained `ComponentChildBinding`.
- Precharges the later terminal operation receipt, normalized child row,
  principal index and parent/role traversal index against both Component and
  aggregate root Registry limits before installation. The paid effect
  therefore cannot strand an installed child because commitment discovers
  insufficient Registry capacity.
- After an uncertain install call, exact observed code advances without
  repeating the effect. An empty target may retry only after replay-settlement
  recovery and a renewed durable install intent; mismatched code, controller
  or retained binding fails closed.
- Installation does not yet make the child a Registry member or transfer its
  reserved descendant count. Atomic normalized commitment and Directory
  advancement remain next.

### 🧪 Testing

- Covers verified child Candid evidence, public protocol and replay-policy
  classification, the Prepared-root fence, terminal-capacity rejection before
  the paid effect, interrupted intent renewal, installed/verified exact retry
  and preservation of descendant and created-inventory accounting.

- Begins the reinstall-only 0.100 implementation line. No 0.99 installation,
  stable state, topology identity or compatibility decoder is an input to a
  0.100 Fleet.

### ➕ Added

- Added distinct `TreeSpecId` and `TreeGroupId` types for App-declared Tree
  topology and independent scaling groups. Both reject empty, noncanonical or
  over-40-byte names at Serde and Candid boundaries.
- Added generated 32-byte `TreeId` for one concrete Fleet-scoped Canister
  Tree. Its text, Serde and Candid representations are exact 64-character
  lowercase hexadecimal.
- Re-exported the three Tree identity types through the public Canic facade.

### 📚 Documentation

- Opened the 0.100 implementation tracker against immutable `v0.99.34` and
  recorded the staged hard-cut boundary: these foundational contracts do not
  make the remaining 0.99 Subnet Slot or Fleet Root runtime releasable as
  0.100.

### 🧪 Testing

- Focused core tests cover declared-name bounds, invalid Serde input, Candid
  round trips and canonical concrete Tree identity encoding.
