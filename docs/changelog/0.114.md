# Canic 0.114 Changelog

## [0.114.1] - Unreleased

### 🔧 Changed

- Select `canic/candid-export` only in configured, batched, generated infrastructure
  and internal-fixture declaration builds. Preserve application feature/default
  choices and native service generation. The shared catalog classifies this as
  tooling, with no additional role capability or stable-memory allocation.
- Runtime Wasm retains external Candid encoding and decoding while dropping
  Canic's service-printer dependency edge. With Platform 0.15.3, ordinary application
  graphs exclude `pretty`, `arrayvec`, `typed-arena` and `unicode-width`. Candid
  type-error rendering uses upstream Debug formatting; generated interfaces and
  runtime handlers retain their contracts.
- Refresh the embedded allocation peer and its source/tool/lock provenance for
  the current published dependency cohort.

## [0.114.0] - 2026-10-31

### ⚠️ Breaking

- Use Platform's prepared-call API through `ic_platform::call`. Framework
  instrumentation consumes those request/response types directly; consumers of
  the execution boundary must rebuild against the new owner. The standalone
  `ic-call` dependency is removed. Exact request bytes, explicit wait policies,
  cycle attachments, polled-attempt metrics and matching-callback observations
  retain their existing contracts.
- Adopt published Blob/contracts 0.61.0. Upload-certificate assessments return
  the original permission and assessment time without the removed blocker list;
  their Wire method identity is `0x424c_4f42_0059_0009`. Consuming canisters mount
  the upstream declaration, so callers must regenerate bindings from the current
  schema. Release transitions retain the clean-reinstall requirement.
- Adopt Auth/protocol 0.28.0. Delegate scope grammar to upstream `ScopeLabel`,
  preserve its typed validation causes, and classify delegation failures through
  upstream field/target enums. Consumers matching exposed canonical errors must
  use the typed scope cause. Session qualification supplies prepared issuer keys
  and owned requests; signature bytes, verification and authority remain upstream.

### 🔧 Changed

- Use one Store adoption receipt projection while preserving the scoped lookup's
  early no-receipt result, strict lookup authority conflicts, in-flight omission
  and exact verified receipt fields
  ([#690](https://github.com/dragginzgame/canic/issues/690)).
- Share member authority and expected allocation progress validation for
  reservation/install cursor advances. Reserved and Verified remain distinct;
  committed members retain their independent Registry partition checks. Record,
  protocol and error identities are unchanged
  ([#691](https://github.com/dragginzgame/canic/issues/691)).
- Update Backup/Agent to 0.53.1, Memory/Storage to 0.60.3, Metrics Stable to
  0.61.1, Platform to 0.15.3, Query to 0.79.0 and Timers to 0.35.0. Align the root
  catalog and both independent Blob consumers, preserving one runtime identity
  for Memory, Storage, Metrics, Platform and Timers in each selected graph.
  Platform owns prepared calls and the executor; the graph retains one timer
  provider without aliases or local dependency overrides.
- Adopt Logging 0.23.3's append receipt and explicit topic matching. Derive its
  retained-text ceiling from Canic's existing count, message and label bounds;
  preserve sequence results, count retention, query totals and typed refusals.
- Use Build, Host Artifacts/Fs/Process/Text and the exact release metadata
  editor at 0.73.2, with Host Tools and Testkit 0.75.1. Native catalog
  acquisition and fixtures use Query's current `CollectionSourceRequest`
  directly; endpoint collection, timeout, agreement and cache policies are
  unchanged.
- Select Wire/derive 0.13.2 and replace Platform's removed `wire-schema` feature
  with Wire's `platform-types` integration for native Principal/Account metadata.
  Required external IC protocols retain their Candid boundary.
- Select Metrics 0.24.1, shared by Blob, Metrics Stable, Query, Testkit and
  Timers. The full published dependency group retains one Metrics, Memory,
  Storage, Wire, Platform, runtime guard and timer identity in each selected
  Wasm graph without local overrides or compatibility adapters.

- Adopt Shared Tooling at
  `619d194875369e0f72b45477b66adb430acbf6b7` through the canonical exporter.
  The source's committed `VERSION` is 0.27.23; retain the canonical version
  stamp and exact revision. Pending VERSION automation applies to repositories
  where that file owns the version; Canic retains its Cargo version owner.
  Retain captured validation-input checkpoints, structured Cargo observations and
  the opt-in publication helpers; Canic keeps its existing publication owner.
  Construct Canic’s validation fixture from declared runner companions so the
  retained checkpoint helper is present during policy qualification.
  Retain the documented boundary between reusable cores and integration graphs,
  and the shared publication adapter's explicit path and feature selections;
  Canic's publication flow remains product-owned.
- Restore Cargo's normal workspace `target/` and independent nested-workspace
  defaults. General `make clean` explicitly cleans the whole workspace output,
  including nested Wasm caches, generated sources and evidence. Direct Cargo
  overrides retain their normal meaning and explicit-target cache-tag safety.
  Keep evidence that must survive cleanup outside `target/`; builds/releases
  retain artifacts until explicit cleanup. Disposable fixtures qualify cleanup,
  external evidence retention, inherited output settings and packaged paths.
- Include the shared opt-in release-group helpers without changing Canic's
  coordinated package versions or selecting independent publication groups.
  The complete member catalog and inline group explanations apply when a
  workspace opts into independent publication groups.
- Reuse `ic_wire::ByteBuf` in Host handoff envelopes and Ledger archive fixtures.
  The type identity, external CBOR/Candid bytes, argument/nonce binding and
  retained Serde adapters remain unchanged
  ([#714](https://github.com/dragginzgame/canic/issues/714)).

### 🩹 Fixed

- Map diagnostic worker startup refusals and panics to each target's report,
  retaining the eight-worker ceiling and stable output order across cycles,
  metrics and live list observations. Preserve successful rows and ordinary
  query failures when another worker cannot start
  ([#277](https://github.com/dragginzgame/canic/issues/277)).
- Clarify that cycle/token transfers credit ledger accounts; native Coordinator
  and Root funding uses `cycles topup`. Transfer examples use the selected
  identity's account, while arbitrary valid recipient resolution stays available
  ([#367](https://github.com/dragginzgame/canic/issues/367)).
- Validate the latest root release against its detailed notes for both pending
  and finalized entries. Continue to reject multiple pending releases or a
  pending release placed beneath the latest entry. Executable-admission fixtures
  compare physical paths, including aliased temporary directories, without
  weakening version admission
  ([#450](https://github.com/dragginzgame/canic/issues/450)).
- Remove the duplicate logger wrapper and limits, making the upstream recorder
  their sole owner. Zero capacity still disables logging; changing count or
  message limits starts a fresh diagnostic window. Paging, retention and typed
  append refusals retain their existing contracts
  ([#712](https://github.com/dragginzgame/canic/issues/712)).
