# Canic 0.104 Changelog

## [0.104.2] - 2026-08-19 - Closeout Audit Correction

### 🩹 Fixed - Capability-Exact Timer Ownership

- The semantic ownership guard now freezes native registration actions as well
  as constructors. Aliased, re-exported, moved, unclassified and duplicate
  scheduling or custody authority fails the maintained 45-file ownership
  inventory.
- Automatic-top-up callback and workflow code is retained only in the enabled
  managed artifact. Runtime-only managed, Root, Coordinator and Store
  artifacts no longer inherit that authority merely because cycle code is
  linked.
- The four closed recovery owners now share focused evidence for response loss,
  restart with an active lease, one fenced takeover and stale-completion
  rejection. Cycle top-up additionally retains its exact funding-operation
  identity across the takeover.

### 🧪 Testing - Artifact And Lifecycle Qualification

- Five capability-specific product artifacts prove the expected top-up
  reachability while preserving each role's Candid and lifecycle-export
  surface. The internal selector plumbing adds no supported facade, prelude
  item, lifecycle grammar or stable-state schema.
- The test-only Canic/IcyDB composition retains one provider and one lifecycle
  export pair through Prepared and Active reconstruction, participant rollback
  and corrected-cause retry without duplicate owner rows.
- Cross-inventory validation parses qualified Rust paths, so source fragments
  retained as audit evidence cannot be misclassified as executable storage
  consumers.

### 📊 Audit - Quantitative Authority

- The recorded 0.103.0 and 0.104.0 release-byte table is withdrawn from
  acceptance authority because its embedded release-build-ID inputs were not
  retained. Rebuilt no-ID totals are labeled noncanonical and support no causal
  percentage.
- The 46,593-instruction, zero-memory-page result remains one current
  two-work-sample observation rather than a median, maximum or regression
  threshold.
- This patch changes shipped capability reachability and its semantic guard,
  tests and evidence. It changes no Candid or stable-state schema and remains
  reinstall-only.

## [0.104.1] - 2026-08-19 - Closeout Evidence Correction

### 🔧 Changed - Structural Ownership Proof

- The timer-ownership guard now parses production Rust syntax instead of
  treating comments and string literals as authority. It freezes every native
  registration callsite and rejects renamed, publicly re-exported,
  unclassified or duplicated scheduling capabilities plus aliased raw-provider
  imports and platform timer mechanics.
- The 45-file ownership inventory remains exact, but its completeness now
  follows syntactic timer types, imports, paths and macro tokens rather than a
  frozen lexical hit count.

### 🧪 Fixed - Install Rollback Qualification

- A dedicated managed fixture traps from the synchronous init participant.
  PocketIC proves the failed install leaves the same canister without a module,
  a later round cannot commit deferred work and a corrected install on that
  exact canister succeeds.
- Normal, init-trapping and post-upgrade-trapping artifacts retain identical
  Candid and normalized export sets, including exactly one init and one
  post-upgrade export.
- The existing post-upgrade trap journey continues to prove the prior module
  and state remain committed before corrected retry.

### 🧪 Fixed - Combined Provider Qualification

- The published-IcyDB composition journey now reads the complete shared timer
  inventory through Canic's controller-authorized runtime status instead of
  proving only selected owner rows.
- Exact sorted logical rows are frozen for newly Prepared, settled Prepared and
  Active states across install and same-release upgrade. The comparison covers
  identity, scheduling mode, registration, process condition and enabled state
  while deliberately excluding volatile deadlines and counters.

### 📊 Fixed - Reproducible Quantitative Record

- Intermediate B2-B6 size and instruction deltas are withdrawn from closeout
  evidence because their exact source states were not preserved. They remain
  labeled historical observations in the working notes and no acceptance
  claim depends on them.
- Fresh locked offline builds of the exact `v0.103.0` and `v0.104.0` trees use
  equal-length paths, the same four-role workload and each release's canonical
  builder. They produce 19,424,848 raw / 5,030,696 gzip bytes for 0.103.0 and
  19,124,317 raw / 4,959,729 gzip bytes for 0.104.0. Because the release-owned
  builder binaries differ, these are exact release footprints, not a
  controlled causal percentage comparison.
- The reproducible current provider observation remains two work samples,
  46,593 total instructions and zero Wasm- or stable-memory-page growth.
- This correction changes only tests, a test fixture, development dependencies,
  guards and documentation. It adds no shipped product-role source or runtime
  dependency, so the exact 0.104.0 release-tree footprint remains the product
  candidate evidence.
- Design, status, working evidence and downstream gates now agree that B1-B8
  are implemented, `v0.104.0` is published and 0.105 still requires explicit
  closeout promotion.

## [0.104.0] - 2026-08-19 - Timer Ownership And Lifecycle Composition

### ⚠️ Breaking - Native Timer Ownership

- Canic's public application timer macros, facade, handle and transient claims
  are removed without aliases. Applications must pin and use
  `ic-timers = "=0.6.1"` directly.
- The release is reinstall-only. It does not decode, migrate or import timer or
  asynchronous-recovery state from an earlier Canic release.

### 🔧 Changed - Domain Recovery And Custody

- Auth renewal, capability-pruned cycle top-up, placement acknowledgement,
  intent cleanup, log retention and Root Canister-pool maintenance now own
  exact native registrations and reconstruct schedules from authoritative
  domain demand.
- Memory ID 60 retains only checked domain attempt fences and cycle top-up's
  exact replay identity. Pending scheduling commands, copied provider
  deadlines, retry streaks and terminal provider state are removed.
- One Root watchdog dispatches expired core and pool attempts without becoming
  a second scheduler. Lifecycle deferrals use direct native once claims, while
  distinct Root and Coordinator snapshot paths retain role-pruned linkage.

### ➕ Added - Synchronous Lifecycle Composition

- Ordinary managed, Root and local start macros accept one safe paired
  synchronous lifecycle participant. Canic invokes it after restoring its
  invariants and exact native claims but before bootstrap or deferred
  application work.
- Participant failure traps the enclosing lifecycle message. A failed upgrade
  retains the prior committed Wasm and state, and corrected retry reruns from
  that boundary. Store and Coordinator start macros remain closed.
- A maintained direct-native guide and executable fixture cover exact provider
  pinning, once and after-completion registrations, cancellation, unregister,
  deliberate detachment, volatile custody and durable-demand reconstruction.
- A Canic-owned managed fixture composes that lifecycle participant with exact
  published `icydb = "=0.230.2"`. Both frameworks share one `ic-timers 0.6.1`
  package and retain separately named timer rows through Prepared and Active
  same-release recovery, including participant rollback and corrected retry.

### 🔧 Changed - Test And CI Feedback

- The internal PocketIC harness uses `ic-testkit` 0.8.9 structured diagnostics
  with each canister's exact controller. Multi-canister readiness checks query
  the complete target set, aggregate same-tick transport failures and delegate
  labeled bounded status/log collection to the upstream collect-all batch.
- Test Wasm labels travel with every upstream specification, progress event,
  outcome and failure. Failed entries retain their primary phase and partial
  phase timings, while selected-graph semantic cache identity reuses an
  unaffected artifact across unrelated host-only dependency changes.
- Every repository PocketIC builder uses bounded instance construction against
  one runner-owned server shared by the serial lane. The runner verifies the
  pinned binary, bounds port readiness, retains startup output and terminates
  its exact child on every handled exit.
- The new prepared concurrent Wasm-input snapshot remains disabled: it is
  process-local, the governed serial lane crosses Cargo test processes and
  Canic has no source write-exclusion guard covering every declared input.
  Ordinary batches therefore retain independent validation and exact artifact
  reuse instead of asserting immutability that the harness cannot enforce.
- Volatile workspace-version and publication claims are removed from current
  status and detailed changelog prose. A cheap document-semantics gate rejects
  those mirrors before expensive compile or PocketIC work begins.

### 📊 Audit - Wasm And Runtime

- The B6 managed, Root and runtime-probe artifacts contain the intended Candid
  and normalized canister exports, including exactly one init/post-upgrade
  pair. The 0.104.1 correction independently compares the normal and trapping
  managed variants.
- The combined Canic/IcyDB probe is test-only. Its final fast artifact is
  5,959,481 raw and 1,519,923 deterministic-gzip bytes; normal and trapping
  builds retain identical Candid and exactly one lifecycle export pair, so no
  shipped product-role size or interface change is claimed.
- The release contains one timer provider and no raw-provider consumer, plus a
  classified 45-file ownership inventory across applications, crates and
  executable canister fixtures. The 0.104.1 follow-up strengthens its original
  lexical guard into structural syntax and exact-capability enforcement.
- The final provider observation is 46,593 total instructions with zero Wasm-
  or stable-memory-page growth. Phase-to-phase quantitative observations are
  not release acceptance evidence because their exact source states were not
  retained.
