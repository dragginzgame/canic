# Canic 0.104 Changelog

## [0.104.0] - 2026-08-19 - Timer Ownership And Lifecycle Composition

### ⚠️ Breaking - Native Timer Ownership

- Canic's public application timer macros, facade, handle and transient claims
  are removed without aliases. Applications must pin and use
  `ic-timers = "=0.6.1"` directly.
- The release is reinstall-only. It does not decode, migrate or import timer or
  asynchronous-recovery state from an earlier Canic release.

### 🔧 Changed - Domain Recovery And Custody

- Auth renewal, capability-pruned cycle top-up, placement acknowledgement,
  intent cleanup, log retention and Root Canister-pool maintenance now own
  exact native registrations and reconstruct schedules from authoritative
  domain demand.
- Memory ID 60 retains only checked domain attempt fences and cycle top-up's
  exact replay identity. Pending scheduling commands, copied provider
  deadlines, retry streaks and terminal provider state are removed.
- One Root watchdog dispatches expired core and pool attempts without becoming
  a second scheduler. Lifecycle deferrals use direct native once claims, while
  distinct Root and Coordinator snapshot paths retain role-pruned linkage.

### ➕ Added - Synchronous Lifecycle Composition

- Ordinary managed, Root and local start macros accept one safe paired
  synchronous lifecycle participant. Canic invokes it after restoring its
  invariants and exact native claims but before bootstrap or deferred
  application work.
- Participant failure traps the enclosing lifecycle message. A failed upgrade
  retains the prior committed Wasm and state, and corrected retry reruns from
  that boundary. Store and Coordinator start macros remain closed.
- A maintained direct-native guide and executable fixture cover exact provider
  pinning, once and after-completion registrations, cancellation, unregister,
  deliberate detachment, volatile custody and durable-demand reconstruction.
- A Canic-owned managed fixture composes that lifecycle participant with exact
  published `icydb = "=0.230.2"`. Both frameworks share one `ic-timers 0.6.1`
  package and retain separately named timer rows through Prepared and Active
  same-release recovery, including participant rollback and corrected retry.

### 🔧 Changed - Test And CI Feedback

- The internal PocketIC harness uses `ic-testkit` 0.8.8 structured diagnostics
  with each canister's exact controller. Multi-canister readiness checks query
  the complete target set, aggregate same-tick transport failures and delegate
  labeled bounded status/log collection to the upstream collect-all batch.
- Test Wasm labels travel with every upstream specification, progress event,
  outcome and failure. Failed entries retain their primary phase and partial
  phase timings, while selected-graph semantic cache identity reuses an
  unaffected artifact across unrelated host-only dependency changes.
- Every repository PocketIC builder uses bounded instance construction against
  one runner-owned server shared by the serial lane. The runner verifies the
  pinned binary, bounds port readiness, retains startup output and terminates
  its exact child on every handled exit.
- Volatile workspace-version and publication claims are removed from current
  status and detailed changelog prose. A cheap document-semantics gate rejects
  those mirrors before expensive compile or PocketIC work begins.

### 📊 Audit - Wasm And Runtime

- B5 reduces the canonical four-role product set by 292,488 raw and 67,034
  deterministic-gzip bytes from B4. B6 leaves raw bytes unchanged, moves gzip
  by one byte and shows only noise-scale interval differences.
- The B6 managed, Root and runtime-probe artifacts retain exact B5 Candid and
  normalized canister exports, including exactly one init/post-upgrade pair.
- The combined Canic/IcyDB probe is test-only. Its final fast artifact is
  5,959,481 raw and 1,519,923 deterministic-gzip bytes; normal and trapping
  builds retain identical Candid and exactly one lifecycle export pair, so no
  shipped product-role size or interface change is claimed.
- The lexical timer call-count guard is replaced by semantic ownership
  classification across applications, crates and executable canister fixtures.
  The final graph contains one timer provider and no raw-provider consumer;
  recovery, projection, lifecycle and application classes are capability-
  constrained independently.
- The B8 fresh-target four-role total remains exactly 19,123,973 raw bytes and
  moves by seven compression-noise bytes to 4,959,566 gzip. The directly
  comparable interval remains exactly 46,593 total instructions with zero
  Wasm- or stable-memory-page growth.
