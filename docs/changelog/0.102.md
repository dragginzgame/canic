# Canic 0.102 Changelog

## [0.102.2] - 2026-08-15 - Diagnostic And Runtime Foundations

### 📊 Audit

- All 2,864 provisional diagnostic identities now name a symbolic producer
  function or typed branch. Dedicated guards close the remaining 239 Component
  Registry workflow, 449 direct Registry-ops and 230 grouped-provisioning
  families, leaving no producer-anchor debt.
- The 2,895-label frontier expands to 3,898 exact producer-qualified entries
  plus 31 safe public projections. Those observations map exactly once onto
  960 composable exact contracts and the 31 projections, yielding the dense
  proposed allocation `1..=991` at a 3.96:1 coverage-to-code ratio.
- All 503 singleton rows carry an explicit non-composition rationale. The
  register also materializes aggregate configuration, protected deployment,
  activation-admission and Intent-store projection rules, including all eight
  exact identities reused as projection targets.

### 🔧 Changed - B1 Review Boundary

- The generated review register binds every row's canonical condition,
  handling contract, producer coverage, exposure, remediation and action. A
  targeted guard rejects byte drift, duplicate or missing coverage, missing
  producer ownership, an ungrounded projection or a four-digit initial
  allocation.
- Adversarial guards keep stale Registry authority, completed pool handoff,
  cycles cooldown, grouped-provisioning completion and root-draining exposure
  mapped to their distinct handling contracts.
- Proposed codes `1..=991` are not yet the permanent current ledger or runtime
  authority. The current and retired runtime-ledger sets remain truthfully
  empty, and B2 remains blocked until the maintainer approves or corrects the
  complete register.
- This checkpoint changes repository evidence only. The maintained
  `ErrorCode + message` contract, internal string propagation, Candid surfaces,
  stable state and release Wasm remain unchanged.

### 🔧 Changed - Timer And Subnet Observation

- Canic scheduling and timer observability hard-cut to `ic-timers 0.5.0`.
  Application timer creation and cancellation are fallible, fixed declarations
  are scoped by runtime role, failed claim custody rolls back, and authority
  snapshots reject out-of-custody claims around timer transitions.
- One neutral `CanisterTimerStatus` inventory reports Canic and application
  timers without creating a second timer authority. It preserves policy-
  specific callback capabilities and bounded instruction and memory-page
  observations.
- The host Subnet catalogue adapter advances from `ic-query 0.37.1` to
  `0.40.1`. Recovery-critical asynchronous renewal, top-up, acknowledgement
  and pool work remain blocked from release until a qualified durable re-kick
  protocol exists.

### 📚 Documentation

- Fleet-estate platform, cost, balance, controller and empty-topology
  qualification move into the evidence-only 0.105 predecessor. It authorizes
  no external effects or production estate state.
- The remaining provisional design sequence moves from 0.105-0.113 to
  0.106-0.114; published releases and historical records retain their original
  identities.

### 🥾 Governance

- Package/install contract checks now belong to the canonical release-
  validation matrix guard. The duplicate executable guard and its separate
  Make and CI wiring are removed without dropping the package, downstream-Wasm
  or local-Fleet assertions.
- The audit catalog derives its complete active membership bidirectionally from
  the fingerprint manifest instead of freezing a numeric method count. Exact
  fingerprint rows must be unique, and stale 0.100 prose anti-resurrection
  checks no longer burden current documentation.
- Canic-owned product protocols and schema generations remain at `v1` before
  1.0. Truthful upstream versions, historical records and audit-method or
  evidence revisions remain explicitly outside that product-version rule.
- The embedded blob inventory gates are marked for removal with the 0.109 M7
  hard cut rather than becoming permanent release machinery.

### 🧪 Testing

- The targeted diagnostic-ledger suite passes 60 tests with no ignored cases,
  and warning-denied Clippy passes for that integration target.
- Changelog, current-document, workspace-test inventory and release-validation-
  matrix governance checks pass for the review checkpoint. The consolidated
  audit-catalog and release-integrity guards, ShellCheck and Actionlint also
  pass.

## [0.102.1] - 2026-08-14 - Diagnostic Inventory Closure

  bounded source passes cover the complete direct-constructor frontier,

  authority, all 56 GC/reclamation/deletion constructions and both management
  transports. A combined GC-write-fence/release-absence branch is explicitly

- The current Canister durable-string census and native-only configuration
  zero-row exclusion are closed. No decision parses retained failure prose;
  recovery-significant and owned operational fields remain identified for the

### 🔧 Changed - B1 Handoff

  typed host retry dispositions and projection-observability rules are ready
  for the allocation review. No number, host catalogue or generated current
  registry is created by this checkpoint; those remain the final B1 gate.
- The active design directory is reduced to its normative design, compact

  source-by-source B1 ledgers remain available as bounded working audit
  evidence and must be consolidated or deleted when their allocation work is

  historical ideas and post-46 backlog collections are frozen at their current
  file and topic ceilings rather than remaining an unbounded escape hatch.
- This checkpoint changes documentation and review evidence only. Public
  `ErrorCode + message`, runtime propagation, Candid interfaces, generated

### 🧪 Testing

## [0.102.0] - 2026-08-13 - Faster Fleet Builds And Diagnostic Groundwork

### ➕ Added

- `canic install <app> <fleet> --fleet-input <path> --release-build <id>` can
  create another fresh Fleet from one exact finalized release build under the
  same ICP root without rerunning Cargo or artifact transforms. An interrupted
  install selects its recorded finalized build automatically when the exact
  same-release Fleet session is resumed.
- Finalized release-build authority now records the exact Canic builder version
  and Cargo profile. Explicit reuse admits only the current Canic version and
  the recorded profile, current App topology, exact role/package identities,
  canonical application and infrastructure manifests, and revalidated raw and
  gzip Wasm bytes. A supplied conflicting profile or changed package fails
  before activation.
- `CANIC_TRACE_ARGV=1` prints an opt-in pre-parse snapshot containing the
  process ID, executable resolution, argument count and escaped OS argument
  boundaries. It provides evidence for intermittent wrapper or executable-
  resolution failures without changing normal command output.
- `CANIC-WASM-001/v3` establishes a current nine-role release/debug footprint
  baseline at immutable `v0.101.53`. It covers six configured Components, Fleet
  Subnet Root, Fleet Coordinator and Wasm Store with isolated offline build
  state and checksum-pinned tooling. Historical v2 measurements remain valid
  but are explicitly non-comparable.

### 🔧 Changed - Build And Install Performance

- Standalone `canic build <app> [role]` now uses Clap's `fast` profile default
  for normal iteration and records that resolved profile in normalized build
  provenance. `--profile release` remains the explicit production-artifact
  choice; fresh install and deployment planning continue to default to
  `release`.
- The durable release-build ID is embedded by each leaf canister instead of by
  `canic-core`. A new Fleet identity still recompiles the leaves that must carry
  it, but no longer invalidates `canic-core` and the entire shared runtime
  dependency graph.
- Local configured builds export Candid from the exact selected-profile Wasm.
  One Cargo command per Cargo workspace and profile now supplies both the
  installed artifact and its extracted interface; the former second debug-only
  Candid pass is removed. IC builds continue to omit the Candid export pointer,
  generated sidecar and `candid:service` metadata.
- Fleet Coordinator retains its runtime-only package contract with no build
  script. Its local leaf build uses one `cargo rustc` invocation with the local
  Candid cfg, while IC uses ordinary `cargo build`. Wasm Store and configured
  roles select the same local cfg through their existing Canic build scripts.
  The finish macro confines that host-injected cfg to its private export module
  with a narrow documented lint exemption, so ordinary runtime-only Coordinator
  and test-stub builds remain warning-free without restoring package build
  scripts or suppressing unrelated crate code.
  Canonical checked-in Coordinator and Store DIDs remain source authority;
  intentional refresh extracts the already-built selected local Wasm instead
  of compiling debug Wasm again.
- After each shared configured Cargo batch succeeds, artifact copying,
  shrinking, Candid extraction, metadata embedding and gzip materialization run
  concurrently across roles. Output order remains the admitted role order, and
  any worker failure still fails the complete build.
- Release and Canister Cargo invocations now require the existing lockfile.
  One no-follow workspace lock covers each shared Wasm target from Cargo entry
  through artifact transformation and publication, so concurrent Canic builds
  cannot consume or overwrite another invocation's leaf output. Release
  versioning also rechecks tracked cleanliness after validation and before
  mutating package versions.
- Canic's exported macro cfg surface now has one canonical catalogue shared by
  the facade build script and downstream `canic::build!` expansion. Dormant
  negative endpoint switches, unused role-state cfgs and unused compile-time
  environment values are hard-cut instead of remaining untestable build
  branches.
- Whole-App builds now execute Coordinator and Store infrastructure before the
  shared configured batch, then render an infrastructure-first artifact report.
  The report shows one-per-Fleet versus one-per-Fleet-Subnet instance scope,
  identifies the selected App config, states that root Wasm remains
  Subnet-unbound until install and gives the root row the honest shared-batch
  duration rather than an unqualified `shared` label.
- Install timing separates preflight, configured build, infrastructure build,
  supplied-plan materialization, finalized-artifact reuse, post-build safety
  gate, manifest emission and complete Fleet activation. Nonzero residual
  planning/receipt work is reported explicitly, and centisecond rows are
  derived so the displayed phases add exactly to the displayed total.
- A real `canic build demo --profile fast` completed in 110.31 seconds
  immediately after the implementation change and 25.49 seconds on the
  identical cache-hit run. The latter comprised 15.13 seconds for the shared
  configured artifacts and 10.37 seconds for one Coordinator and one Store
  build. After the infrastructure-first reporting change, another cache-hit run
  completed in 22.97 seconds: 14.68 seconds for the shared configured batch,
  3.24 seconds for Coordinator and 5.04 seconds for Store. These are local
  observations, not an immutable cross-release benchmark.

### 🩹 Fixed - CLI Diagnostics

- Top-level command selection and `canic build` option parsing now retain
  Clap's exact diagnostic, usage and exit code. Missing subcommands, invalid
  values and other parse failures exit 2 with the concrete `error:` line;
  `--help` and `--version` remain zero-exit Clap display actions.
- The top-level parser owns subcommand requirement and global option parsing,
  while leaf dispatch receives the exact trailing OS arguments. This removes
  the custom branch that could render bare top-level usage without the parse
  cause and makes a captured argv trace directly comparable with the parser
  input.

### ⚠️ Breaking

- The pre-1.0 release-build plan CBOR record hard-cuts to the current builder-
  version/profile shape. A 0.101 plan is not decoded, migrated or accepted for
  0.102 artifact reuse. Cross-release Fleet transitions remain reinstall-only;
  `--release-build` is a same-release optimization, not installation adoption
  or compatibility recovery.

### 📊 Audit

- The compact-diagnostic-code line remains evidence-only. Its current/retired
  allocation-ledger contract, direct and transitive constructor inventories,
  dynamic public-context ownership, masked-error correlation owners and
  representative Wasm measurement method are documented, but no public Candid
  error, numeric allocation, runtime constructor, stable state or canister
  behavior has changed in 0.102.0. At this checkpoint, 2,159 of 2,499 effective
  producer sites are classified and 194 dynamic public values have ownership
  dispositions; 340 producer dispositions remain deliberately open. The
  remaining Wasm Store lifecycle group is closed across cycle reclamation,
  module resolution, typed internal calls, inventory and physical deletion;
  Fleet Registry Mirror synchronization, acknowledgement, snapshot authority
  and monotonic activation are also closed. Root Component Directory
  synchronization and cross-root Fleet-service peer authority are closed
  without adding a prose wrapper around typed topology failures. Core
  provisioning-plan and Fleet Registry conversion adapters are proved
  transparent to their existing typed families.
- This is the maintainer-requested release checkpoint for the completed
  operator outcomes and reviewable evidence snapshot. Evidence-only B1 remains
  active for later 0.102 batches; the checkpoint does not waive its gates.
- Maintainer feedback is incorporated into the design boundary: permanent
  retired-code history, Fleet-atomic activation from one admitted release set,
  registered producer identities distinct from unknown decoded values, and no
  loss of remediation-significant dynamic data. Mutating diagnostic batches
  remain blocked on approval of the complete evidence inventory.

### 🥾 Governance

- Repository scope now permits an agent to create and bootstrap a specifically
  authorized named new repository at its exact target path. Inspection,
  review, audit, diagnosis, design or feedback about an existing sibling stays
  read-only unless the maintainer separately authorizes mutation.
- The approved 0.103 direction defines framework-neutral local application
  authorization over verified bounded Fleet/role/scope sessions without a
  dependency on downstream frameworks. Its selected hard cut adds a required
  signed token presenter and removes presenter-less, subject-equals-caller and
  first-use bearer compatibility semantics. Evidence-only B1 must prove full
  propagation, scope issuance, canonical type ownership and pure-policy
  boundaries before runtime implementation. The at-most-60-second proof and
  protected local session configurable up to 1,800 seconds have independent
  clocks and capacity evidence; proof expiry does not end or extend a committed
  session. B1 must also prove browser-neutral native-agent proof acquisition.
  A downstream IcyDB allowlist remains independent framework-owned work rather
  than a Canic dependency or release gate. The former provisional
  0.103-0.111 designs move to 0.104-0.112; published releases, historical
  changelogs, archived status and audit evidence keep their original
  identities.

### 🧪 Testing

- Targeted release-build tests cover canonical profile/version persistence,
  one-way finalization, exact idempotent reuse, competing finalizers, unsafe
  paths, malformed/noncanonical records and identity mismatches.
- Install tests prove interrupted-session recovery, explicit finalized-build
  selection, profile and Canic-version rejection, complete manifest/byte
  revalidation, changed-package rejection and display-exact timing totals.
- Build tests prove one configured Cargo command per workspace, selected-
  profile local Candid extraction, runtime-only Coordinator package validity
  and distinct local-versus-IC Coordinator command shapes. A real complete Demo
  App build and its identical cache-hit rerun both succeeded.
- The isolated packaged-downstream proof builds one typed Canister through
  packaged `build!`, `start!` and `finish!` at Rust 1.91 with warnings denied.
  It extracts the typed endpoint from local Wasm, proves IC Wasm omits that
  local-only export, and builds both generated-wrapper and canonical packaged
  Wasm Store paths with locked dependency resolution.
- Targeted checks pass for the changed runtime, control-plane, host, CLI and
  facade packages. Package-scoped Clippy passes with warnings denied, along
  with install parsing, recursive help ordering, reference-surface, changelog
  governance and current-document semantic guards.

### 🧭 Migration Notes

- Operators may reuse a release build only after an install has finalized it
  and printed its release-build ID. Use that ID with `--release-build` for a
  separate fresh same-release Fleet under the same ICP root; exact interrupted
  retries require no extra flag.
- If source topology, package identity, profile or Canic version changed,
  create a new release build. Do not copy or edit release-build state to bypass
  the admission checks.
- Workspace package versions remain `0.101.53` in this draft. Version mutation,
  full deployment qualification and publication remain maintainer-owned release
  preparation steps.
