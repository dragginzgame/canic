# Canic 0.102 Changelog

## [0.102.2] - 2026-08-17 - Diagnostic Runtime Catalogue

### ⚠ Simplified - Semantic Reasons

- Maintainer review rejects the unreleased 991-row condition-plus-handling
  register as the final diagnostic taxonomy. The maintained architecture is
  now the small contract: `DiagnosticCode`, `RegisteredDiagnosticCode`,
  `Error { code: u16 }`, code-first `InternalError`, existing typed domain
  errors and a host-owned reason catalogue.
- The exhaustive B1 inventory and Wasm evidence remain accepted. Distinct
  raw/registered types, host catalogue/CLI machinery and finite typed
  Access/Store cleanup remain reusable. The frontier's tooling and allocation
  authority are removed at closeout while useful evidence remains archived.
- The 991 candidate was never emitted by an admitted release and creates no
  current or retired history. Unreleased allocations may change freely; once
  released, `code + name` is the immutable semantic identity. Numbers are
  merely nonzero and unique; density and ranges are not invariants.
- One host-only `reasons.toml` authority generates registered runtime constants
  and the boring host catalogue of code, name, origin, summary and optional
  guidance. 0.102 generates no language-neutral JSON registry and introduces
  no generic handling framework.
- A flat host-only `.2` release snapshot records only each diagnostic's numeric
  code and symbolic name. It may move with the ledger until `.2` ships; after
  release, the current reason ledger remains the sole authority for mutable
  origin, summary, optional guidance and retirement state.
- The focused reason-register guard rejects a missing or renamed released
  identity without adding a per-release history database, fingerprint,
  generated artifact or runtime data.
- Permanent ledger tests no longer read the archived B1 semantic census or
  freeze the initial current/retired row counts. The ledger accepts only
  `code`, `name`, `origin`, `summary`, optional `guidance` and `retired`, so
  migration evidence and extra taxonomy fields retain no authority.
- A generated code-free review collapses the 991 tuples into 167 mechanical
  origin-qualified buckets. Four mixed global buckets split during review. The
  completed review exactly partitions all 2,895 provisional identities into
  161 qualifying registered cause families and ten local typed families, with
  no exact-owner decision left open. A superseded
  1,355-row pass split subsystem, field, phase and public-target context back
  into identity; it remains non-authoritative migration evidence. Final code
  count is not a KPI, but handling and producer context do not allocate codes.
- Existing typed callers retain retry, reconciliation and policy decisions.
  Public projection is explicit at typed mapping or `InternalError`
  construction boundaries; there is no central projection table. A masked
  exact identity is registered only when an existing operator, durable or
  machine consumer independently qualifies it. Otherwise the exact failure
  remains local and maps directly to the safe public reason.
- Correctness-, recovery- and caller-required dynamic data receives the
  smallest endpoint-specific typed owner when necessary. Nonessential operator
  context may be deliberately dropped and recorded rather than creating a new
  status or lifecycle subsystem. Durable work remains limited to fields
  directly disturbed by removal of diagnostic strings.
- Implementation is organized as Register, Map, Cut, then Clean and measure.
  All four phases are complete. Targeted canonical release builds cover a
  representative Component, Fleet Subnet Root, Fleet Coordinator and Wasm
  Store. Their data sections are all smaller than the retained baseline and
  bounded scans find no host catalogue or B1 register material. Only Root is
  smaller overall across the non-isolated release-line comparison, so the
  closeout makes no causal diagnostic-savings claim.
- The detailed allocation and validation entries below record the superseded
  implementation candidate and remain useful scaffolding/evidence history; they
  no longer confer allocation authority.
- The downstream Toko topology qualification is no longer part of Canic's test
  estate. Its dedicated configuration, three database stubs, four
  project-hierarchy stubs, three-Subnet qualification, project/group/child
  PocketIC journeys, build paths and reporting helpers are removed. The
  retained Registry and authentication journeys use ordinary issuer Components
  and no downstream project model.
- Release cadence no longer invents a 6–10 release target or warns that a
  coherent minor has too few releases. Minor lines have no minimum; the
  advisory now surfaces only the soft guideline of no more than 12 published
  releases before an explicit minor-boundary reassessment.

### ⚠ Changed - Compact Diagnostic Hard Cut

- Public Rust and Candid errors are now exactly `Error { code: u16 }`; the
  symbolic `ErrorCode` enum and public `message` field are deleted from the
  facade, checked-in Fleet Coordinator/Wasm Store DIDs, host/CLI callers and
  maintained tests.
- `InternalError` now owns an exact registered reason and an explicit safe
  public projection. It stores no diagnostic message, class, origin or
  optional public DTO. An already decoded remote `Error` is forwarded
  losslessly without converting its arbitrary raw number into producer
  authority.
- Existing retry and low-cardinality metric decisions now inspect their typed
  state or semantic reason codes rather than the removed class/origin
  taxonomy. Runtime diagnostic logging is compact numeric output.
- The accepted `reasons.toml` ledger contains 161 current reasons and no
  retired rows. It generates only prose-free runtime constants and the
  host-owned catalogue; known, retired and unknown host lookup remains
  lossless.
- The superseded allocation TOML/JSON, central projection/handling machinery
  and one-time executable B1 inventory test are removed. The useful B1
  producer and semantic-review evidence remains archived.

### 📊 Audit

- All 2,864 provisional diagnostic identities now name a symbolic producer
  function or typed branch. Dedicated guards close the remaining 239 Component
  Registry workflow, 449 direct Registry-ops and 230 grouped-provisioning
  families, leaving no producer-anchor debt.
- The 2,895-label frontier expands to 3,898 exact producer-qualified entries
  plus 31 safe public projections. Those observations map exactly once onto
  960 exact condition-plus-handling tuples and the 31 projections, yielding the
  dense candidate `1..=991` at a 3.96:1 coverage-to-row ratio.
- All 503 singleton rows carry an explicit non-composition rationale. The
  register also materializes aggregate configuration, protected deployment,
  activation-admission and Intent-store projection rules, including all eight
  exact identities reused as projection targets.

### 🔧 Changed - Diagnostic Candidate Scaffolding

- The generated review register binds every row's canonical condition,
  handling contract, producer coverage, exposure, remediation and action. A
  targeted guard rejects byte drift, duplicate or missing coverage, missing
  producer ownership, an ungrounded projection or a four-digit initial
  allocation.
- The maintainer initially approved the complete 991-row register as one
  coherent implementation candidate. Later cause-family review supersedes its
  numeric authority while preserving its semantic groups, handling contracts,
  projections, observability owners and singleton evidence.
- Adversarial guards keep stale Registry authority, completed pool handoff,
  cycles cooldown, grouped-provisioning completion and root-draining exposure
  mapped to their distinct handling contracts.
- Codes `1..=991` are materialized as provisional registered identities, while
  arbitrary decoded numbers remain lossless raw identities that cannot acquire
  producer authority. Replacement B2 regenerates these constants from the
  reduced reason ledger rather than retiring unreleased candidate numbers.
- The candidate host ledger has 991 provisional and zero retired rows. Its
  typed catalogue validates class, semantic origin, disposition, exposure,
  projection, producer ownership and anti-reuse rules, then byte-checks a
  language-neutral current-code registry. Retired and unknown numbers remain
  lossless and distinguishable.
- `canic diagnostic E123` and its raw-decimal form render known allocation
  metadata and preserve distinct retired or unknown outcomes without parsing
  labels or historical prose.
- A protocol-surface guard pins the pre-B2 public `Error` DTO and checked-in
  Fleet Coordinator/Wasm Store DID files to the symbolic `ErrorCode + message`
  contract and rejects compact numeric diagnostic fields before the B4 hard
  cut.
- The former B2 implementation is reusable prose-free runtime and host
  scaffolding, not an accepted identity taxonomy. The maintained
  `ErrorCode + message` contract, internal string propagation, Candid surfaces
  and diagnostic-owned stable state remain unchanged until their planned hard
  cuts.
- B3 preparation removes the public `AccessErrorKind` taxonomy and the
  `AccessError::Denied(String)` catch-all. Direct controller, topology, Fleet,
  network, token, attestation, scope, service and access-expression failures
  are finite typed variants, while verifier, configuration and runtime causes
  remain typed instead of being flattened through their rendered text. Active
  Registry membership and Fleet-service Authority checks now distinguish an
  ordinary negative predicate from protected Registry/runtime failure.
- Every one of the 26 direct access variants selects its provisional registered
  exact/public identity pair. Access failure observation records compact exact
  and projected codes; masked static-configuration and TTL failures keep their
  distinct internal number and safe public projection. This is producer
  preparation only: every numeric mapping is regenerated after the reduced B2
  register is accepted, while endpoint `Error`, Candid, host and CLI decoding
  still use the old contract.
- All 13 finite `TemplateManifestOpsError` variants now select their provisional
  exact Store identity without deriving a code from rendered text. Hash,
  capacity, missing-artifact and bounded-index conditions reuse the reviewed
  shared handling identities.
- Publication binding and release preparation replaces five broad
  `InvalidState(String)` branches with finite typed causes, renames the GC
  write fence explicitly and splits GC fencing from exact-release absence.
  Twelve finite publication causes select provisional exact/public identities and
  emit compact Wasm observations; the remaining broad GC and transport
  wrappers cannot select a generic identity and remain open for exact typing.

## [0.102.0] - 2026-08-13 - Faster Fleet Builds And Diagnostic Groundwork

### ➕ Added

- `canic install <app> <fleet> --fleet-input <path> --release-build <id>` can
  create another fresh Fleet from one exact finalized release build under the
  same ICP root without rerunning Cargo or artifact transforms. An interrupted
  install selects its recorded finalized build automatically when the exact
  same-release Fleet session is resumed.
- Finalized release-build authority now records the exact Canic builder version
  and Cargo profile. Explicit reuse admits only the current Canic version and
  the recorded profile, current App topology, exact role/package identities,
  canonical application and infrastructure manifests, and revalidated raw and
  gzip Wasm bytes. A supplied conflicting profile or changed package fails
  before activation.
- `CANIC_TRACE_ARGV=1` prints an opt-in pre-parse snapshot containing the
  process ID, executable resolution, argument count and escaped OS argument
  boundaries. It provides evidence for intermittent wrapper or executable-
  resolution failures without changing normal command output.
- `CANIC-WASM-001/v3` establishes a current nine-role release/debug footprint
  baseline at immutable `v0.101.53`. It covers six configured Components, Fleet
  Subnet Root, Fleet Coordinator and Wasm Store with isolated offline build
  state and checksum-pinned tooling. Historical v2 measurements remain valid
  but are explicitly non-comparable.

### 🔧 Changed - Build And Install Performance

- Standalone `canic build <app> [role]` now uses Clap's `fast` profile default
  for normal iteration and records that resolved profile in normalized build
  provenance. `--profile release` remains the explicit production-artifact
  choice; fresh install and deployment planning continue to default to
  `release`.
- The durable release-build ID is embedded by each leaf canister instead of by
  `canic-core`. A new Fleet identity still recompiles the leaves that must carry
  it, but no longer invalidates `canic-core` and the entire shared runtime
  dependency graph.
- Local configured builds export Candid from the exact selected-profile Wasm.
  One Cargo command per Cargo workspace and profile now supplies both the
  installed artifact and its extracted interface; the former second debug-only
  Candid pass is removed. IC builds continue to omit the Candid export pointer,
  generated sidecar and `candid:service` metadata.
- Fleet Coordinator retains its runtime-only package contract with no build
  script. Its local leaf build uses one `cargo rustc` invocation with the local
  Candid cfg, while IC uses ordinary `cargo build`. Wasm Store and configured
  roles select the same local cfg through their existing Canic build scripts.
  The finish macro confines that host-injected cfg to its private export module
  with a narrow documented lint exemption, so ordinary runtime-only Coordinator
  and test-stub builds remain warning-free without restoring package build
  scripts or suppressing unrelated crate code.
  Canonical checked-in Coordinator and Store DIDs remain source authority;
  intentional refresh extracts the already-built selected local Wasm instead
  of compiling debug Wasm again.
- After each shared configured Cargo batch succeeds, artifact copying,
  shrinking, Candid extraction, metadata embedding and gzip materialization run
  concurrently across roles. Output order remains the admitted role order, and
  any worker failure still fails the complete build.
- Release and Canister Cargo invocations now require the existing lockfile.
  One no-follow workspace lock covers each shared Wasm target from Cargo entry
  through artifact transformation and publication, so concurrent Canic builds
  cannot consume or overwrite another invocation's leaf output. Release
  versioning also rechecks tracked cleanliness after validation and before
  mutating package versions.
- Canic's exported macro cfg surface now has one canonical catalogue shared by
  the facade build script and downstream `canic::build!` expansion. Dormant
  negative endpoint switches, unused role-state cfgs and unused compile-time
  environment values are hard-cut instead of remaining untestable build
  branches.
- Whole-App builds now execute Coordinator and Store infrastructure before the
  shared configured batch, then render an infrastructure-first artifact report.
  The report shows one-per-Fleet versus one-per-Fleet-Subnet instance scope,
  identifies the selected App config, states that root Wasm remains
  Subnet-unbound until install and gives the root row the honest shared-batch
  duration rather than an unqualified `shared` label.
- Install timing separates preflight, configured build, infrastructure build,
  supplied-plan materialization, finalized-artifact reuse, post-build safety
  gate, manifest emission and complete Fleet activation. Nonzero residual
  planning/receipt work is reported explicitly, and centisecond rows are
  derived so the displayed phases add exactly to the displayed total.
- A real `canic build demo --profile fast` completed in 110.31 seconds
  immediately after the implementation change and 25.49 seconds on the
  identical cache-hit run. The latter comprised 15.13 seconds for the shared
  configured artifacts and 10.37 seconds for one Coordinator and one Store
  build. After the infrastructure-first reporting change, another cache-hit run
  completed in 22.97 seconds: 14.68 seconds for the shared configured batch,
  3.24 seconds for Coordinator and 5.04 seconds for Store. These are local
  observations, not an immutable cross-release benchmark.

### 🩹 Fixed - CLI Diagnostics

- Top-level command selection and `canic build` option parsing now retain
  Clap's exact diagnostic, usage and exit code. Missing subcommands, invalid
  values and other parse failures exit 2 with the concrete `error:` line;
  `--help` and `--version` remain zero-exit Clap display actions.
- The top-level parser owns subcommand requirement and global option parsing,
  while leaf dispatch receives the exact trailing OS arguments. This removes
  the custom branch that could render bare top-level usage without the parse
  cause and makes a captured argv trace directly comparable with the parser
  input.

  `--release-build` is a same-release optimization, not installation adoption

### 🧭 Migration Notes

- Operators may reuse a release build only after an install has finalized it
  and printed its release-build ID. Use that ID with `--release-build` for a
  separate fresh same-release Fleet under the same ICP root; exact interrupted
  retries require no extra flag.
- If source topology, package identity, profile or Canic version changed,
  create a new release build. Do not copy or edit release-build state to bypass
  the admission checks.
- Workspace package versions remain `0.101.53` in this draft. Version mutation,
  full deployment qualification and publication remain maintainer-owned release
  preparation steps.
