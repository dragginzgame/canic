# Canic 0.99 Changelog

## [0.99.27] - 2026-07-25 - Terminal Host Authority Commitment

### ⚠️ Breaking

- Removed the temporary public `FleetActivationContinuationRequired` host
  error. The maintained install path no longer stops successfully activated
  Fleets at sequence three: it either commits terminal host authority and
  returns success or preserves the typed activation/catalog/receipt failure.

### 🔧 Changed

- Fresh installation publishes one canonical network-scoped Fleet catalog row
  only after every managed Canister has exact durable `Active` evidence.
  Publication is serialized by one close-on-exec kernel lock, rejects Fleet
  name, ID or root-principal collisions and atomically replaces canonical
  sorted JSON through synced sibling staging.
- The sequence-four `HostAuthorityCommitted` journal records the exact catalog
  document hash only after the catalog is durable and the journalled
  root-install receipt still proves the same network, Fleet, App, activation
  operation and root principal.
- Restart after catalog publication but before journal advancement converges
  through the existing exact row without rewriting its provenance. Observation
  of a terminal install revalidates the catalog row and root receipt and
  performs no activation or catalog effect.
- The Fleet-install command now returns success only after the terminal
  authority is durable. Missing, unsafe, corrupt or contradictory catalog and
  receipt evidence fails closed without advancing the active journal.

### 🧹 Cleanup

- Centralized durable no-follow advisory lock creation in the host file-I/O
  owner and reused it for both activation and catalog single-writer
  boundaries.

### 🧪 Testing

- Focused catalog tests cover canonical bytes, exact idempotency, collision
  rejection without mutation and concurrent commits without lost Fleet rows.
- Focused activation tests cover sequence-four durability, terminal restart
  observation, exact idempotency, root recovery and rejection of missing
  receipts or mismatched catalog identity without journal mutation.
- Targeted format, host check/tests, strict Clippy, layering, changelog
  governance and diff-hygiene checks cover this batch. It changes the install
  command outcome and removes one public host error type, but does not change
  package versions, dependencies, Cargo.lock, stable Canister state, Candid,
  Fleet-catalog JSON shape or CLI grammar.

## [0.99.26] - 2026-07-25 - Durable CanistersActivated Recovery Authority

### 🔧 Changed

- Fresh installation now resumes the exact sequence-two credential generation,
  activates every manifest child before the root and advances only after the
  returned or reconciled root status proves the complete journalled identity,
  cascade manifest, credential manifest and `Active` phase.
- The sequence-three `CanistersActivated` journal deterministically records
  the root and every child's canonical activation-evidence hash. Exact restart
  observes that durable authority without another activation call; host Fleet
  catalog publication remains deliberately unavailable until its separate
  final transition.
- Until that final publication transition lands, the typed install
  continuation diagnostic now reports that the root and managed Canisters are
  durably `Active` at sequence three rather than incorrectly describing the
  completed work as merely `Prepared`.
- Root preparation, root resume, child credential preparation and child
  activation now reconcile uncertain call outcomes through the protected
  activation-status query. Contradictory identity, evidence, generation,
  projection, phase or activation-time observations preserve the original
  call cause and fail closed.

### 📚 Documentation

- The proposed 0.100 multi-subnet design now compiles each App Tree Spec into
  independently scaled, heterogeneous Tree Groups. Every concrete Canister
  Tree has a stable `TreeId`, one Tree Root, one exact group/spec-hash binding
  and one physical placement `SubnetId`; placement may repeat across Trees
  without merging their identities, roots or registries.
- The design distinguishes the default workload Tree Spec from the
  separately selected Authority Subnet, introduces distinct `TreeSpecId` and
  `TreeGroupId` identities, removes ambiguous member-root and super-root
  terminology, and keeps application user/project routing outside the Canic
  Fleet Registry. Fresh Tree Specs also exclude
  `[services.fleet]` roles so 0.101 can provision them on the Authority Subnet;
  an existing 0.99 candidate remains adoption-only. The proposed 0.101 design
  preserves the `tree_groups` and `trees` fields unchanged while publishing those
  Fleet-authoritative services.

### 🧪 Testing

- Focused runtime tests cover exact non-root identity, cascade, generation,
  phase and activation-time validation.
- Focused host tests cover canonical sequence-three encoding, complete
  per-Canister evidence, restart without effects, exact idempotency, partial
  and conflicting evidence rejection, root recovery and live effect-before-
  journal ordering.
- Targeted format, core/host tests, strict Clippy, layering, changelog
  governance and diff-hygiene checks cover this batch. It changes live
  fresh-install recovery and the internal host journal only; it does not
  change package versions, dependencies, Cargo.lock, stable Canister state,
  Candid, public JSON or CLI grammar.

## [0.99.25] - 2026-07-25 - Durable CanistersPrepared Activation Handoff

### ⚠️ Breaking

- The fresh-install activation journal now uses the frozen raw-byte encoding
  for `AppId` inside `FleetActivationIdentity`. Pre-0.99.25 in-progress
  journals are deliberately not decoded through a text-value fallback,
  migration or compatibility path; the reinstall-only 0.99 line starts a new
  activation.

### 🔧 Changed

- After the verified root install is durably recorded, the host invokes the
  controller-only preparation update. That root-owned operation returns only
  after every synchronous child cascade acknowledges durable `Prepared`
  evidence; the host then admits its exact manifest without assuming the CLI
  operator directly controls each child.
- The sequence-two `CanistersPrepared` journal stores the root cascade
  manifest, credential generation and manifest, raw-principal-sorted Canister
  inventory and exact root activation-evidence hash. Canonical shared hash
  functions reject non-canonical ordering, more than 4,096 total Canisters or
  more than 64 credential entries.
- A restart at `RootInstalled` recovers the exact root-install receipt by its
  journalled raw-byte hash before any root resolution, creation or reinstall.
  A restart at `CanistersPrepared` observes the durable record without another
  external call.
- Partial child preparation, mismatched identities or hashes, changed
  prepared evidence, missing receipts, unsafe receipt entries and
  non-canonical or oversized host records fail closed without advancing the
  journal.

### 🧪 Testing

- Focused core and host tests cover manifest bounds, canonical evidence
  hashing, exact receipt recovery, root-before-effect ordering, complete
  root-manifest admission, monotonic sequence-two durability, restart,
  idempotency and conflicting-evidence rejection.
- Strict targeted Clippy and formatting cover the changed core/host boundary.
  This batch changes live fresh-install behavior and the internal activation
  journal encoding. It does not change package versions, dependencies,
  Cargo.lock, stable Canister state, Candid, public JSON, CLI grammar or
  operator output.

## [0.99.24] - 2026-07-25 - Fleet-Scoped Deployment Receipt Authority

### ⚠️ Breaking

- Deployment receipts now live only under
  `.canic/networks/<canonical-network-id>/fleets/<fleet-id>/deployment-receipts/`.
  The former environment/Fleet-name directory has no reader, migration,
  fallback or compatibility writer.
- The public host latest-receipt lookup now requires an exact `FleetKey`
  instead of an environment profile and Fleet name. Callers that begin with
  an operator-facing Fleet name must resolve the canonical catalog first.

### 🔧 Changed

- Fresh install durably plans the activation journal and allocates the Fleet
  ID before persisting successful deployment-truth, execution-preflight,
  build or manifest receipts. Pre-Fleet checks still print their result and
  return typed blocking causes, but cannot create an ambiguously keyed
  receipt.
- `canic deploy inspect resume-report <fleet>` resolves the Fleet name through
  the canonical catalog before selecting the latest receipt. An explicit
  `--receipt` remains the direct input for evidence that predates catalog
  publication.
- Successful root-install receipts now retain canonical network, App, Fleet
  ID, activation-operation ID and release-build ID evidence from the exact
  observed `Prepared` status. `RootInstalled` rejects a receipt belonging to
  any different activation identity before journal mutation.

### 🧹 Cleanup

- Removed the discarded failed-preflight receipt construction and the unused
  receipt-path field from admitted root-install evidence.

### 🧪 Testing

- Focused host tests cover canonical Fleet-keyed paths, pre-Fleet
  non-persistence, exact activation-identity admission, mismatch rejection,
  journal idempotency and current phase ordering.
- Focused CLI tests prove catalog-to-`FleetKey` resolution selects the
  canonical latest receipt.
- This hard cut changes a public host Rust function signature, the receipt
  filesystem location and root-receipt evidence semantics. It does not change
  package versions, dependencies, Cargo.lock, stable Canister state, Candid,
  the `DeploymentReceiptV1` JSON shape or CLI command grammar.

### 🧹 Cleanup

### 🧪 Testing

## [0.99.20] - 2026-07-24 - Convergent Cascade Correctness

### 🩹 Fixed

- Retrying an exact Fleet-state command now cascades the root's current state
  even when the command was already applied locally. A transient child fanout
  failure can therefore converge after that child returns instead of the
  unchanged root value suppressing the repair.
- Received state snapshots prepare and validate every Fleet-state and
  Directory replacement before the first mutation. Once local application
  starts, all remaining commits are infallible, so a late-invalid Directory
  cannot expose a partial local snapshot.
- Received topology snapshots now require one structurally consistent branch:
  exact receiver role and parent, unique path nodes and children rows,
  contiguous parent links, explicit rows for leaves, and matching next-hop
  identity and role. Contradictory evidence rejects before child-cache or
  activation-evidence mutation.

### 🔒 Security

- Explicit update payload limits are enforced by the generated raw export
  before allocating, copying or decoding Candid bytes. The maintained
  16,384-byte cascade limit now protects inter-Canister calls as well as the
  earlier ingress inspection gate.
- Both state and topology cascade endpoints use the same raw bound; the
  inspection hook remains an earlier ingress rejection only and is no longer
  mistaken for the inter-Canister enforcement authority.

### 🧪 Testing

- Focused structural tests cover exact topology acceptance plus missing,
  duplicate, extra, broken-parent, missing-hop and role-mismatch rejection.
- Focused state tests prove that a failure discovered while preparing the
  final Directory leaves Fleet state and both existing Directories unchanged.
- Real PocketIC coverage relays accepted and oversized payloads between two
  canisters, and exercises exact Fleet-state repair after a child is stopped,
  fanout fails and that child restarts.
- No package version, stable schema, Candid data shape, JSON or CLI contract
  changes are included. The direct `ic0 1.1.0` declaration supplies hidden
  macro plumbing for the pre-copy System API size check and reuses the version
  already present in the lockfile.

### 🔧 Changed

  non-authoritative, while every root, bootstrap child and dynamically
  provisioned child now carries the same exact release-build identity.
- Dynamic Wasm-store creation now receives the same Fleet-state cascade

### 🧪 Testing

- The real root → user-hub → user-shard PocketIC journey passes with
