# Canic 0.103 Changelog

Release truth: `v0.102.2` remains the latest published package. The local
`v0.103.0` ref is an unpushed lightweight development tag whose commit still
declares package version `0.102.2`; it is not a Canic release. `0.103.0` is the
single current open changelog target pending the human-owned minor-version,
release-commit and annotated-tag flow.

## [0.103.0] - 2026-08-17 - Role-Owned Candid Surface

### 📝 Summary

- This release closes the 0.102 audit findings, freezes the accepted role-
  surface evidence and hard-cuts Canic to profile-exact role command/status
  control planes with private autonomous workflow phases.

### 🔧 Changed - Presentation

- Host/CLI fixtures, active application documentation and Skynet endpoint
  presentation now consume the role-owned command/status surface. Seven
  representative generated profiles prove that capability differences change
  selectors and referenced types without adding control methods.
- Standalone-local canisters now emit one capability-pruned `canic_status`
  method plus selected external standards. Local mode gains no Fleet command
  authority merely because the facade implements Fleet workflows.

### ➖ Removed - Legacy Emitters

- The legacy shared, non-root, cycle and topology endpoint-emitter modules are
  deleted. Current runtime protocol constants and replay declarations retain
  only command, status and the two admitted Store byte lanes; no alias emitter
  or compatibility surface remains.
- Raw pre-cut Root and managed Candid snapshots are removed from the current
  worktree so historical interfaces cannot be mistaken for callable contracts.
  The reproducible B1 capture keeps only normalized method evidence and exact
  transient-interface hashes.

### 📊 Audit - Surface Closeout

- Current-surface facade guards, local-only emission checks and all exact role
  replay manifests pass. Across the four representative B1 roles, 188 Canic
  method appearances become ten: two per ordinary role and four for Store.
- Representative post-cleanup fast-profile Wasm hashes and sizes are retained
  as current artifact identity. No isolated same-source pre-cut pair exists,
  so 0.103 makes no causal Wasm-size savings claim.

### 🔧 Changed - Autonomous Role Operations

- Root and Coordinator now expose only `canic_command` and `canic_status`.
  The accepted unions contain up to 32 Root commands and exactly nine
  Coordinator commands, with correlated typed responses and durable operation
  receipts only for genuinely asynchronous work.
- Managed canisters expose only cfg-pruned `canic_command` and `canic_status`
  control methods. Runtime-only, sharding/top-up and delegated-token issuer
  profiles retain only their exact compiled variants and types.
- Wasm Store control is hard-cut to ten `StoreCommand` variants and seven
  `StoreStatusRequest` selectors. Exact Store authority replaces the generic
  managed binding, while chunk read/publish remain the only separately named
  Canic byte lanes.
- Component provisioning and Root removal advance through private reconcilers
  after one accepted intent. Their status queries resolve the exact durable
  domain from the operation ID and admit only the controller or an exact
  participating Root where that participant owns an observation.
- Per-variant ingress bounds are selected after decoding the closed command.
  Authority remains variant-specific; moving methods into a union does not
  broaden controller, Root, Component or operation-participant access.
- Initial release-set bytes are staged through the bounded pre-adoption Store
  installer seam, then the adopted Store is reverified under its final exact
  Root authority.

### ➖ Removed - Phase Surfaces

- Root's standalone endpoint families and Coordinator's standalone Registry,
  provisioning and Root-removal phase methods are removed with their protocol
  constants, replay rows, host/inter-canister callers and fixtures. No alias,
  forwarding wrapper, fallback decoder or mixed old/new protocol remains.
- Temporary Root Store-staging command variants, Coordinator snapshot/removal
  phase variants and public Component provisioning phase variants are absent
  from the maintained unions. Workflow phases remain private implementation
  state.
- Standalone managed and Store control/status methods, their protocol
  constants, replay rows and maintained callers are removed. Decoded remote
  diagnostics and Store bytes retain their typed forwarding and bounded
  transport behavior.

### 🧪 Testing - Operations and Caller Cut

- Focused control-plane evidence covers exact operation ownership, replay after
  lost responses, terminal receipt freezing, Root-draining reservation
  authority, Store controller transitions and release-set catalogue equality.
- Canonical Coordinator Candid parses with exactly two methods, nine command
  variants and seven status selectors. Source/caller residue scans find none of
  the removed Root staging, Coordinator removal or Component advance surfaces.
- Exact PocketIC journeys prove pre-adoption Store bootstrap/reverification and
  autonomous draining through Store deletion and external Root-deletion
  readiness. Focused host deletion recovery tests cover interruption,
  uncertainty, authority drift and terminal replay.
- Canonical Runtime-only, sharding/top-up, delegated-token issuer and Store
  builds prove exact profile-selected variants and method sets. The Store GC
  fence rejects zero or conflicting operation identities.

### 🥾 Governance

- Ordinary `continue`, `keep going` or `next` wording now finishes the current
  accepted in-repository batch and advances into the next accepted, sequenced
  batch without a phase label or magic phrase. Broad validation, release/Git
  mutation, deployment, destructive action and external effects retain their
  separate authority boundaries.

### 🩹 Fixed - Dependency Security

- The transitive HTTP/2 stack now uses `h2` 0.4.16, closing
  `RUSTSEC-2026-0258`. Dependency-risk fixtures populate the exact locked graph
  before offline ownership checks and retain valid audit JSON long enough to
  report newly discovered vulnerabilities instead of exiting silently.

### 🔧 Changed - Profile Foundations

- Managed, Root, Coordinator and Store roles gain closed passive status
  selectors derived from their exact compiled capabilities. External artifact
  metadata selects the profile before the first call, while `Overview` verifies
  rather than chooses that binding.
- Typed role contracts and generated Candid bind each representative build to
  its exact command/status variants, referenced types and public handlers.
  Capabilities prune unavailable protocol reachability instead of adding
  methods.

### 🧪 Testing - Profile Pruning

- Canonical Runtime-only, sharding/top-up, delegated-token issuer, Root signer/
  non-signer and Store builds prove positive and negative selector/type
  reachability. Reserved-name collision, incompatible-feature and thin-start
  guards pass their focused owners.

### 📝 Summary - 0.102 Closeout

- The evidence-only B1 inventory for the role-owned Candid hard cut and every
  severity finding from the `v0.102.2` diagnostic audit are complete alongside
  the release-reliability work accumulated since that tag.
- Runtime change is limited to preserving the four caller-required
  request-cycles preflight values identified by the 0.102 audit. The canonical
  Store Candid is also resynchronized with already-maintained 0.102 authority
  source. The accepted B1 register and corrected 0.102 boundary are the frozen
  inputs to the completed B2-B7 role-surface implementation above.

### 🩹 Fixed - 0.102 Closeout

- Request-cycles policy denials are typed success-channel outcomes carrying
  the approved transfer amount, remaining and maximum child budget, or exact
  cooldown delay. The parent balance stays private, and automatic top-up uses
  the typed result for retry/stop decisions rather than recovering policy from
  an error code. The canonical Wasm Store declaration is regenerated with that
  hard cut and focused Candid tests pin every continuation field. Regeneration
  also removes its stale generic managed-init declaration and records the
  already-maintained exact sibling Store authority and authority query.
- The released 161-identity baseline is read directly from the exact 0.102.2
  reason ledger Git object and its retirement state. Focused transition evidence
  rejects renaming, renumbering, deletion, code/name reuse and retirement
  reversal while allowing presentation updates and active-to-retired changes.
- The central host response error automatically renders number, name, origin,
  summary and optional guidance for known codes while keeping retired and
  unknown codes lossless.
- The dynamic-value evidence now records zero unresolved owners under the final
  qualification rule, and the retained Wasm closeout includes exact immutable
  `v0.102.2` artifact identities rather than only the pre-release candidate.
- Canonical infrastructure Candid extraction removes trailing whitespace before
  writing checked-in or build-local declarations, so regenerated contracts pass
  repository diff hygiene without a separate hand-edited formatting step.

### 📊 Audit

- An immutable `v0.102.2` baseline freezes 207 emitted methods across
  representative Root and managed profiles plus the canonical Coordinator and
  Store interfaces. The inventory separates 188 Canic-owned appearances,
  three external-standard methods and 16 application-fixture methods.
- Every Canic-owned appearance has one review disposition: 45 role-command
  variants, 80 role-status variants, two justified Store byte lanes or 61
  private deletions. Retained rows record the released Rust signature and the
  executable in-repository caller subset rather than treating lexical matches
  as live consumers.
- The manifest freezes the exact capability-pruning matrix, DTO rules,
  operation ownership and the 0.104 timer-consumer handoff. It adds no timer
  registration, recovery key or durable timer record.

### 🔧 Changed - Role-Surface Contract

- Existing typed configuration remains the capability authority, with bounded
  overview status used for compiled-capability discovery. Capabilities prune
  variants, handlers and reachability instead of adding methods.
- Target command and status variants remain flat and role-specific. Remote
  multi-step progress maps to local operation status, while update-only
  canister inspection is classified as an atomic Root command.
- Non-authoritative reference assets under optional design ideas no longer
  count as Canic design authorities or block repository validation.

### 🥾 Changed - Release Reliability

- The root Cargo manifest is the sole live package-version authority. Current
  status may describe a published baseline or open draft without becoming a
  second version source that a version-only release commit can invalidate.
- Release validation now reports one result for the exact `main` commit, with
  an explicit post-bump candidate guard. Release-profile compilation runs for
  release commits rather than being triggered by a disconnected tag-only
  workflow.
- Cheap source, policy and security checks gate expensive compilation and test
  jobs. CI checkouts do not persist credentials, jobs have bounded timeouts,
  dependency updates have explicit ownership and weekly advisory checks remain
  separate from the release result.
- A disposable local/remote Git fixture proves historical-tag cleanup preserves
  local recovery refs when remote deletion fails, verifies both deletion
  boundaries and cannot republish removed refs from the cleaned clone. CI,
  release, Make and Rust-toolchain authorities all require maintainer review.
- Unused Candid, ICP and Wasm tooling and unnecessary full-history checkouts
  are removed from jobs that do not consume them. ShellCheck is installed at a
  pinned version.
- One shared `cargo-get` reader now owns current and committed workspace-version
  queries across CI, cadence, release, push and publish paths. CI installs the
  existing exact tool pin instead of retaining parallel AWK manifest parsers.

### 🧪 Testing

- Ordinary workspace tests and serial PocketIC tests now run and report as
  separate lanes with job-summary timings, so a slow or failing integration
  lane no longer obscures the ordinary-test result.
- Focused release-flow, workflow-lint, shell and plan-only lane checks cover
  the revised orchestration, including tag-deletion failure and success paths.
  Complete release validation remains owned by the maintainer's version-and-
  release flow.
