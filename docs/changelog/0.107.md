# Canic 0.107 Changelog

## 0.107.2 - 2026-08-21

This open correction adds digest-stable cold-cache planning and installation,
admits the effective ICP installation identity before builds, adopts the
published upstream routing-authority and portable fixture API fixes, and
restores truthful B5 closeout evidence. Its runtime-boundary changes remain
limited to host-side catalog acquisition, identity admission, typed plan
diagnostics and deterministic host fixtures; compile-time lint and visibility
hygiene does not change generated Canister code. The required human 0.107
closeout audit remains next.

### ➕ Added - Read-Only Catalog Acquisition

- Adds `canic deploy plan --refresh-catalog`. Ordinary planning remains cache-
  only; the explicit mode may issue public NNS Registry query calls and update
  Canic's private `.canic/ic-query` cache only when the mainnet catalog cache
  is missing or invalid.
- Makes fresh installation use the same live-capable acquisition policy before
  planning, so a fresh checkout does not need a separate cache-seeding command.
  Both the explicit plan mode and installation compile from `ic-query`'s stable
  validated snapshot authority, keeping the plan digest stable when install
  follows a refreshed plan.
- Keeps the deployment boundary effect-free in both modes: no Wasm build,
  deployment-state write, Canister creation, install, controller change or IC
  update call is authorized. Stable Registry version, catalog digest,
  assurance and source endpoints remain canonical plan authority; cache path,
  collection time and disposition are separate report-only acquisition
  provenance.
- Documents the cold-cache workflow in CLI help and the active operator
  walkthrough/checklist, and repairs Medic's plan hint to include the required
  Fleet input while retaining the existing target, profile and optional
  finalized-release authority.

### 🩹 Fixed - Early Installation Admission

- Resolves the effective ICP CLI identity after exact plan recompilation but
  before release-build allocation or Wasm build preparation.
- Rejects an anonymous, unusable or non-matching identity unless its Principal
  exactly equals the operator Principal in the Fleet input. Later controller
  observations remain in place as time-of-check/time-of-use defenses.
- Gives non-interactive encrypted identities the direct
  `CANIC_ICP_IDENTITY_PASSWORD_FILE` remedy and documents the admission
  boundary in install help and the Fleet-input architecture.
- Makes a cache-only catalog blocker recommend `--refresh-catalog` instead of
  incorrectly telling the operator to repair an otherwise valid Fleet input.

### 🩹 Fixed - Registry And Snapshot Authority

- Advances the host-only Subnet Catalog dependency to published
  `ic-query 0.42.0`. It retains `0.41.2`'s complete pinned
  `canister_ranges_*` reconstruction and legacy `routing_table` fallback only
  when the modern family is genuinely absent; a modern-family error cannot
  fall back.
- Uses `snapshot_authority()` for reproducible plan identity and keeps
  `CatalogLoadOutcome::path` plus `.disposition` outside the canonical plan.
  The old combined authority accessor is hard-cut without a Canic adapter.
- Adopts the portable canonical Registry-key constants, typed Subnet-list,
  legacy-routing, routing-shard and Subnet-record subject constructors, plus
  the ordinary uncertified-query evidence constructor needed by downstream
  fixtures without hand-formatted Registry keys.
- Retains the exact returned Registry-value version, failing endpoint and
  assurance, every completed Registry-record read, shard range-start identity
  and inline/chunked encoding in schema-1 plan JSON and text.
- Keeps old catalog cache shapes as a hard cut. They fail validation and must
  be refreshed; Canic adds no compatibility reader, migration or weaker-
  evidence fallback.

### 🧪 Testing

- Host projection evidence covers the failing value plus one completed
  chunked routing-shard read without deriving identity from error prose.
- CLI rendering covers the same complete typed evidence while preserving
  unknown retryability and explicit false build/workspace/IC-effect facts.
- The Root-subnet cache fixture now supplies the required Registry-record
  evidence through the public typed builders and uses an injected observation
  time, so it cannot silently refresh from mainnet during a unit test.
- Fleet-input catalog fixtures now carry the same complete typed record
  evidence required by `ic-query 0.42.0`. Focused tests prove refreshed and
  cache-hit outcomes share canonical authority while JSON/text preserve their
  different cache path, collection time and disposition outside the plan.
- Removes two unrelated complete-validation flakes exposed by the maintainer
  release gate. Placement recovery now compares the operation-returned bound
  timestamp with the exact durable row instead of sampling the wall clock a
  second time, and fake `ic-wasm` tools are written through a closed staging
  path and atomically published before execution after Linux reported
  `ETXTBSY` for direct publication.
- The Fleet deployment-restore and every serial PocketIC lane passed in that
  gate. Focused placement, artifact-transform and warning-denied Clippy reruns
  pass after the corrections; the complete gate remains maintainer-owned.

### 🧹 Changed - Lint Hygiene

- Makes dead code and unfulfilled lint expectations workspace-level hard
  errors, ensures every workspace member inherits that policy, and preserves
  the intentional Clippy style-policy exceptions. The previously opted-out
  sharding Root stub now inherits the policy and uses a const empty init.
- Denies `unreachable_pub` for the tractable `canic` and `canic-macros`
  surfaces, narrows one standalone-config helper and the internal endpoint
  parser/validator/expander types, and records the two exact parent-module
  visibility exceptions with checked `expect` attributes.
- Keeps the one exported-macro `unexpected_cfgs` allowance because canonical
  builds register the cfg and emit no lint while runtime-only consumer builds
  may legitimately require the suppression.
- Removes the redundant runtime schema dependency from the test-only combined
  IcyDB probe and the redundant `icydb` dependency from its schema crate.
  Cargo-machete exceptions now name only direct dependencies required by
  destination-crate macro expansion, and the repository scan is clean.

### 🥾 Governance

- The correction changes no Canister runtime, stable state, Candid or managed-
  role artifact and performs no IC update mutation. Catalog acquisition is
  limited to public Registry queries and the private catalog cache. The
  compile-time visibility cleanup changes no generated macro output. B5/B7 are
  reconciled to the corrected published dependency; human closeout acceptance
  is still required before 0.108 production.

## 0.107.1 - 2026-08-20

This published checkpoint completed the first typed catalog-failure batch that
was externally blocked at `0.107.0`. Its closeout-readiness claim was later
superseded by the modern Registry routing-authority defect corrected in
`0.107.2`; it did not accept or close the minor.

### 🔧 Changed - Typed Catalog Failure Provenance

- Advances the exact host-only Subnet Catalog dependency from published
  `ic-query 0.40.1` to `0.41.0`. Both cached preflight and live host wrappers
  now use its detailed failure APIs rather than the legacy source-error-only
  results.
- Adds one exhaustive Canic projection of the upstream typed request source,
  endpoints, assurance, load stage, cache disposition and trigger, known
  Registry version, offending subject, code/category and retryability. An
  unknown retry result retains its typed reason and is never relabeled
  transient.
- Adds `catalog_failure` to schema-1 deployment-plan JSON and a matching text
  section. Catalog failures are attributed to Fleet-catalog evidence and carry
  explicit `build_started = false`, `workspace_mutation_started = false` and
  `ic_mutation_started = false` facts.
- Keeps source prose as secondary operator detail only. No version, subject,
  cache state or retry decision is parsed from strings, and no dependency fork
  or fallback collector is introduced.

- The focused direct-plan suite and warning-denied host/CLI Clippy pass. The

### 🥾 Governance

## 0.107.0 - 2026-08-20

This is a maintainer-requested checkpoint release. It publishes the coherent
B2-B4 and B6 outcomes plus the B7 evidence independent of B5. It does not
close the 0.107 minor.

### Fleet Planning And Effect Boundary

- Direct `canic deploy plan` receives the selected top-level environment and
  rejects hidden or canonical target disagreement before Fleet-catalog work.
- Direct planning now requires `--fleet-input`, uses the same `--profile` and
  optional `--release-build` spelling as install, and no longer accepts its old
  `--config` or `--build-profile` options.
- Plan and install call one pure host preflight for canonical Fleet identity,
  Coordinator/root placement, Component admissions, initial group assignments,
  limits and positive creation funding. Its structured result records that no
  build, workspace mutation or IC mutation has begun.
- Fresh install loads target authority, Fleet input and its read-only release
  source before any release-build allocation. Invalid Fleet schema or topology
  fails in Planning without creating release-build state.
- Mainnet preflight consumes existing validated cache authority without a
  network call or cache publication. B5 retains ownership of final structured
  live catalog collection and provenance.

### Canonical Decision And Recovery

- One compact canonical decision includes exact workspace or finalized release
  authority, expected artifacts, placement, derived Canister counts,
  per-category funding, maximum operator debit and strictly bounded operator-
  balance evidence. Its domain-separated SHA-256 digest excludes report output
  paths and generated delivery files.
- Direct planning renders the complete decision in text and JSON. Install
  recompiles it before release-build allocation and can require an exact
  expected digest; changed source or balance evidence fails before an effect.
- Same-release install recovery preserves the original decision source and
  digest. Persisted Fleet plans, deployment truth, completion receipts, known
  replica rejection receipts and resume comparisons bind the same digest and
  reject conflicting authority.

### Durable Runtime Whitelist

- Managed application roles now bootstrap memory ID 61 from the validated
  compiled whitelist exactly once. The stable schema owns at most 256 sorted
  principals, one revision and digest, and one retained exact-operation result;
  post-upgrade validates that authority without reseeding or merging config.
- Existing managed `canic_command` and `canic_status` methods gain bounded
  `RuntimeWhitelist` variants under controller-first or exact stable-Root
  authorization. Root, Coordinator, Store and standalone-local specialized
  surfaces do not gain the variants, and `caller::is_whitelisted()` no longer
  reads compiled configuration after bootstrap.
- Authoritative mutation outcomes are now distinct model and stable-record
  types, while the public outcome remains a passive DTO. Explicit `ops`
  conversions preserve the existing stable encoding and Candid surface without
  making policy, model or storage depend on boundary data.

### Validation

- Focused CLI coverage freezes the new grammar, removed spellings, required
  Fleet input, exact finalized release source, structured no-effect output and
  invalid-input behavior.
- Focused host coverage proves canonical root ordering, effect-boundary
  rejection, incomplete placement rejection, install source ordering and
  no-allocation failure for invalid schema and admissions.
- Focused B4 coverage proves complete counts/funding, stale and insufficient
  balance rejection, workspace-source exclusions, plan/install digest parity,
  exact retry, changed-authority conflict, receipt binding and resume mismatch
  rejection. Warning-denied host/CLI Clippy passes.
- Focused runtime-whitelist policy, storage conversion, stable-schema,
  allocation, macro-surface and Candid checks pass. The real maximum schema
  encodes to 8,417 bytes, the status page to 4,072 bytes and one mutation to
  101 bytes.
- One bounded managed-role PocketIC journey proves compiled seeding,
  independent controller and stable-Root administration, unrelated-caller
  denial, response-loss exact retry, conflict rejection, immediate removal,
  same-release restoration, re-addition without a rebuild and zero implicit
  0.105 application sessions.
- Targeted policy-purity, passive-DTO, lifecycle, stable-memory, changelog and
  current-document guards pass, as do the layering guard, formatting and diff
  checks.
- Current-source qualification harnesses now verify the exact bytes they
  install without comparing later 0.107 artifacts to the immutable
  `v0.105.0` fixture identity retained by the accepted 0.106 protocol.

### Remaining 0.107 Closeout Gate

- Locked `ic-query 0.40.1` and the inspected upstream source cannot retain the
  accepted failed-load cache/version context or represent unknown
  retryability. B5 remains blocked without a fork, error-string parser or
  guessed retry classification.
- The read-only Toko checkout contains no Canic integration or
  CANIC-011/012/013 evidence. B7 records that exact downstream blocker instead
  of modifying Toko.
- Once the upstream typed API exists, B5 propagation and final B7
  reconciliation remain required. The resulting source must then receive the
  human-requested 0.107 closeout audit before 0.108 production work begins.
