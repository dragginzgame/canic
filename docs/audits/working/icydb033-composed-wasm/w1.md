# ICYDB-033: six matched composition subjects for IcyDB 0.260 W1

Owner: Canic audit fixture and host artifact builder. Requested by the
maintainer on 2026-09-20 from IcyDB's
`docs/design/0.260-runtime-footprint/canic-handoff.md`.

**Canic's requested extension and fresh measurement handoff are complete.**
IcyDB's 0.260 status owner can resume W1 reconciliation and decide whether the
evidence justifies a separate W2 experiment. No runtime reduction is proven.
The [structured evidence](w1-measurements.json) contains all compiler/final
hashes, inputs, feature selections, attribution and qualification records.

## Comparison contract

These are controlled synthetic compositions, not complete Toko Miner
qualification. The full ICYDB-033 application attribution remains open until
separately qualified or explicitly narrowed by the maintainer. There is no
runtime optimisation in this batch and no proven removable-byte estimate.

The existing [fixture](../../../../canisters/audit/icydb_composed/Cargo.toml)
and [runner](../../../../crates/canic-host/examples/icydb_composed_audit.rs)
now accept six cumulative subjects:

| Subject | Reachable surface |
| --- | --- |
| `host` | Canic host and the fixed audit wire adapters; audit operations return `Unavailable` |
| `participant` | Empty metrics-enabled IcyDB participant, existing synchronous lifecycle and journaled store |
| `binding` | One generated entity and its typed binding |
| `query` | The same binding and a fixed typed page query |
| `write` | The same query plus typed insert and typed result decoding |
| `ten` | Ten matching entities with binding, page and insert reachable for each |

Every entity has an explicit `Nat64` primary key and a `Nat64` value in the
same journaled store. Slot zero uses exactly the same generated entity in
every nonempty subject. Slots one through nine add matching distinct nominal
entities; no extra index, relation, timestamp or generated-ID workload is added.
The historical schema package/container names remain the existing fixture's
identity; the selected schema is no longer necessarily empty.

All subjects expose `audit_binding(nat8)`, `audit_page(nat8)` and
`audit_insert(nat8, nat64, nat64)` with the same result schema and Canic endpoint
adapters. The selected slot and insert fields come from ingress. Unsupported
operations return `Unavailable`; invalid entity slots, unavailable databases
and rejected operations have distinct outcomes. Binding reports successful
typed binding. Query prepares a live page cursor with limit 16, executes its
trusted page and decodes each returned row through the generated adapter;
insert encodes the generated insert type, executes the trusted typed write and
decodes its returned row. Each enabled operation runs inside IcyDB's existing
request-execution owner. These public audit endpoints are fixture-only.

Keeping the adapters fixed controls their declaration and wire shape. It does
not make adjacent binary differences additive ownership partitions: whole
program optimisation and shared codec/generic reachability can still change.
The participant increment includes selected metrics and lifecycle/recovery.
The insert increment is conditional on machinery already retained by recovery
and query. Nine additional matching entities measure this exact scaling
cohort, not a universal bytes-per-entity constant.

### Post-link reachability

All five participant Candid sidecars are byte-identical. The host differs only
by the participant's metrics surface; all three audit adapters remain present.
The production builder validates runtime exports against each sidecar.

Separate named diagnostics use the exact retained compiler bytes and the same
shrink/`-Oz` pipeline, retaining names for inspection. Name retention changes
function/type numbering, so raw equality is not assumed. The retained one-off
inspection matches every function body against its canonical counterpart
under a bijective function mapping, resolves type-number differences by exact
signatures, compares the remaining module context and checks unchanged external
function references. All defined functions match in all six subjects; no
unmatched body is attributed by guessing.

Direct-call paths from the optimized audit exports reach each selected typed
binding, the page execution owner and the insert/commit owner. The ten-entity
artifact retains all ten bindings from each of its three audit exports, with
shared query/write implementations. Single-entity wrappers can be inlined:
the binding-only canonical export references `AuditEntity01` at linear-memory
address 1,095,936 and retains its schema-lowering checks; the query-only page
reaches `execute_structural_projection_page`; the one-entity insert reaches
`BoundWriteEncoder`, `PreparedRowCommitOp::apply` and typed result decoding.
These paths establish retained executable surfaces, not successful IC execution.

### Named owner to investigate

The concrete new investigation owner is IcyDB's
`db::executor::projection::facade::execute_structural_projection_page`, reached
through the prepared page cursor and structural projection routing. In the
one-page named diagnostic, its closure occupies **43,282 shallow bytes** and
retains **330,541 bytes**. The audit-page export retains **788,181 bytes**,
including its wrapper and dominated dependencies. These nested figures overlap;
do not add them or call them removable bytes. The page also reaches predicate
planning and index-backed covering-scan machinery despite this simple schema
and fixed limit, making route selection a concrete place for IcyDB to inspect.

The empty participant still retains the startup-watchdog closure (129,364
shallow / 872,819 retained bytes), but this batch does not repeat the discarded
startup-outlining experiment or suggest removing recovery. **No safe reduction
has been demonstrated.** A W2 candidate needs a matched counterfactual and its
own semantic and IC-cost evidence before any optimisation claim.

## Reproduction

After checking that no other Canic command owns the shared build target, build
the runner with `CARGO_NET_OFFLINE=true RUSTC_WRAPPER= cargo build --locked
-p canic-host --example icydb_composed_audit`. Use the frozen source and locks:

```bash
export CARGO_NET_OFFLINE=true RUSTC_WRAPPER=
export CARGO_TARGET_DIR="$PWD/target/icydb033-w1/wasm"
export CARGO_PROFILE_RELEASE_STRIP=none CANIC_MEMORY_BUCKET_PAGES=16
for variant in host participant binding query write ten; do
  target/debug/examples/icydb_composed_audit build \
    canisters/audit/icydb_composed target/icydb033-w1/evidence "$variant"
done
```

No PocketIC execution, installation, lifecycle/recovery semantic check,
wall-clock/native timing comparison, instruction/cycle measurement, full
workspace gate, version bump, publication or deployment is claimed. IcyDB and
Toko Miner remain read-only. The IcyDB 0.260 status owner must incorporate this
Canic-side return evidence; this batch does not edit the sibling status file.
