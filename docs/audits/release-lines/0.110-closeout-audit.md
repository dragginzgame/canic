contains all eleven canonical roles and four fixtures, but explicitly records
`clean_repeat_claim: false`. Its build method reuses dependencies and does not
claim the two independent clean builds required by B5. It qualifies its own
checkpoint, not the new recovery-controller fields, Candid changes and other
runtime changes in the `.42` candidate.

The retained B2 source manifest differs from the audited checkout at 149 of
its recorded paths, including `Cargo.toml`, `Cargo.lock` and control-plane
production sources. The archive retains the exact path/hash comparison. This
is direct evidence that the old measurements cannot stand in for final-source
qualification. No complete final-source B5 report was found in the current
handoff, design tracker or retained audit reports.

B2's Root had 7,484,879 code-section bytes and 10,083 defined functions, with
3,000,881 bytes and 39,917 functions of headroom. Those encouraging numbers
must retain their checkpoint identity. They do not prove a current deficit or
current reserve compliance.

Required closure: qualify the final candidate's eleven canonical roles and
four fixtures twice from clean inputs, retaining hashes, code/total/gzip bytes,
replica-limited defined functions, optimizer cross-checks, table entries,
capabilities, Candid, exports, provenance and finalizer evidence. Prove the
512 KiB code reserve and 2,500-function reserve under the frozen limits, the
independent total-module limit, and the maintained instruction allowance.
Only the four exact B2 cold-query exceptions remain accepted. Account for
representative maintained behavior, public-consumer checks and the accepted
validation resource envelope on the resulting candidate.

Owner: canic-host artifact tooling, runtime/control-plane and testing owners.

### F3 — Explicit reinstall-only release metadata contract is unfulfilled

The design's **Reinstall-Only Release Enforcement** section requires a
machine-readable reinstall-only transition mode in governed release metadata,
plus typed host rejection before platform effects and structured unchanged-state
evidence. This requirement was not removed by the B3/B4 scope amendment.

The current
[`ReleaseBuildPlanRecord`](../../../crates/canic-host/src/release_build/mod.rs),
[`CurrentReleaseSetManifest`](../../../crates/canic-host/src/release_set/current/mod.rs)
and [`RootReleaseSetManifest`](../../../crates/canic-host/src/release_set/manifest.rs)
carry build identity, versions, hashes and artifact authority, but no explicit
release transition policy. Reviewed infrastructure/application manifests and
release candidate/validation scripts do not supply that policy either.

There is useful existing enforcement:
[`InstallMode`](../../../crates/canic-host/src/fleet_ensure/model/mod.rs)
contains only `Install` and `Reinstall`, and the
[`lifecycle_boundary` regression](../../../crates/canic-tests/tests/lifecycle_boundary.rs)
rejects a changed release-build identity during upgrade, checks the committed
module and prepared readiness, then proves same-release retry. These do not
constitute the required explicit release metadata field or the complete B5
host pre-effect observation record. The latter test actually issues an upgrade
to exercise the runtime guard; it is not a host pre-effect rejection test.

This is a design/implementation and qualification gap, not proof that an unsafe
ordinary upgrade route exists. Required closure: implement and qualify the
declared metadata/host contract, or obtain an explicit design decision that
identifies the existing executable authority intended to satisfy it. Do not
silently waive the requirement because codec work stopped. Retain typed
rejection and unchanged module, stable-state, controller, cycle and workflow
observations at the promised boundary.

Owner: canic-host release/ensure policy and testing; maintainer owns any change
to the accepted design requirement.
