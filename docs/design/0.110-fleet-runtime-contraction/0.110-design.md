### Implementation boundaries

The first slice freezes effect-free Host review admission and the two management
evidence boundaries: independent operator custody before clearing any owner, and
empty held capacity after reset. Its maintained `v1` review binds current Fleet,
network, operator, build, operation, exact physical IDs/roles/controllers/subnets,
modules/versions, snapshot IDs, disposition evidence, native/reserved balances,
bounded calls/debit and external account recovery artifacts. Coordinator/Root
ownership observations must cover the complete reviewed closure and have no
active producers or unresolved paid effects. Known Coordinator/Root Cycles
Ledger accounts cannot disappear through matching empty account inventories.
Native credits at either custody/reset boundary leave the reviewed observations,
call/debit ceilings and digest unchanged. Checked native-plus-reserved totals
bound only net debit; each source must still retain its minimum native balance
and exact custody/content bindings.

This slice is a library admission boundary, not a live inventory collector,
durable effect journal, operator command or proof of quiescence. Its observation
inputs must come from the authenticated observation owner when execution is
wired. Review digests bind evidence; they do not authenticate its source. Runtime
quiescence, observed artifact qualification, account settlement, existing-journal
execution and real management proofs remain required for FR1 completion. Retained
account balances currently require operator-held IDs with explicit recovery
artifacts; pool destinations are preliminary availability checks, not admission
receipts. Existing retirement paths remain until the replacement is qualified.

The shared Host effect vocabulary now includes exact snapshot deletion. Each
action binds the target, original module, selected snapshot and complete remaining
inventory; it requires stopped sole-operator custody. Only that exact before/after
inventory reconciles, including a successful deletion whose response was lost
while the journal still retained `Intent`. This is a single-effect primitive,
not a whole-Fleet reset compiler or a second journal. It does not infer that
disappearance proves which caller deleted a snapshot. FR1 must retain all owner
and account obligations before compiling destructive effects.

Authenticated physical sampling now covers stopped sources after independent
operator custody. Free preparation binds the signer, network trust anchor and
certified subnet/controllers. Consuming it performs at most four management
reads: two status samples and two snapshot inventories, without automatic retry.
Changed versions, code, custody, running state or snapshot inventories refuse the
sample. Snapshot reading and deletion share one raw-size/decoder/deadline-bounded
inventory reader. The returned current balances still require reviewed conservation
checks; a sample is not a lock against subsequent operator changes. Observation
now consumes an opaque reservation from the existing Fleet journal, borrowing its
exclusive operation lock through the reads. The maintained source review freezes
the per-call debit quote. Each reservation persists four calls and their full
worst-case allowance before issuing a token; failed or lost replies do not refund
it. Reopening preserves the counters, review and separate executable-plan identity.
An uncertain journal write prevents token issuance and requires reopening the
owner. Ordinary Ensure/import cannot take over an unfinished release.

This remains an internal integration boundary: it attaches to an already retained
matching operation envelope, and introduces neither another journal nor a release
command. Account recovery, producer/paid-effect quiescence, operation creation and
the whole-Fleet effect compiler remain unimplemented. The physical reader and its
reservation do not establish those obligations or destructive authority.

The ownership collector now reuses the authenticated Registry and paginated Root
inventory readers. It requires exact reviewed Coordinator/Root placement, every
Store and child, stable Registry replies, and matching certified modules,
controllers and subnets. Owner custody brackets the queries; all selected IDs
receive a final custody check, without duplicate preliminary child reads.
The shared decoder bounds
raw replies, decoding/skipping work, type count and header complexity. Pending
registered assets remain visible in the census. This is a time-local membership sample;
unchanged membership does not prove a producer fence, account settlement, or the
absence of pending paid effects. An unfinished creation or import may also own
physical IDs outside the registered pool; its reconciliation remains mandatory
before this census can become a whole-Fleet destructive inventory.
The selected current-build Registry and artifact
bytes still require retention/qualification. No old role endpoint becomes a
prerequisite for discarding completed historical installations.

The existing authority snapshot fence is not by itself release admission. It
suspends resumable work and blocks ordinary handoff commands; it does not establish
that all retained paid obligations have settled. Release quiescence and the exact
child handoff path must be qualified together before owner state is discarded.

Core now distinguishes a durable release seal from the resumable snapshot seal
inside the current `v1` fence. A release binds operation ID, review digest and
recipient; exact replay preserves the original seal and changed bindings refuse.
Snapshot prepare/resume cannot reopen or replace it. The synchronous internal
workflow hook requires the role owner to check settled obligations before producer
suspension and the durable commit in one message, with no intervening await.
Release sealing does not admit existing ordinary or snapshot-recovery commands.
The role settlement checks, exact bounded handoff commands and their endpoint
classification still require integration and PocketIC proof before exposure.
This is an internal boundary, not a release command or a claim of whole-Fleet
quiescence. Same-installation persistence does not authorize cross-release reuse
of the changed fence record or Candid status; ordinary transitions remain reinstall-only.

## Why This Line Changed

The earlier tracked 0.110 revision put build acceleration, operator inventory,
status cleanup and stateful retirement ahead of the strongest measured Wasm
work. It also measured defined functions without requiring final function
headroom. That structure could spend the reserve it was supposed to create.

The restored direction follows the actual evidence:

1. Binaryen has already produced its material general-purpose reduction;
2. the remaining downstream pressure is both code-section size and the exact
   local-function quantity enforced by the replica validator;
3. shallow post-`v0.109.28` attribution found large overlapping
   Serde/Ciborium reachability around Canic stable records; and
4. global storage registration can make role-inapplicable records, codecs and
   recovery work reachable in otherwise small actors; and
5. non-storage macro expansions can retain all-role endpoints, Candid roots,
   providers, timers and control-plane dispatch even when the consuming actor
   does not expose those capabilities; and
6. downstream artifacts can expose combined pressure, but Canic must qualify
   its own contraction from repository-owned roles and capability fixtures.

The roughly 725 KiB Canic-associated Ciborium total is routing evidence, not a
savings forecast. Activation, authorization and other symbol families overlap,
and shared machinery may remain after one family is removed. Controlled
ablation builds and fresh marginal measurements therefore own every
implementation decision.

## B1: Immutable Baseline And Absolute Budgets

B1 freezes one immutable post-0.109 source, toolchain, feature and optimizer
baseline. Its qualification lane contains every canonical Canic role and the
repository-owned capability fixture matrix described below. No consumer
repository, lockfile, source commit or application-state decision enters this
authority.

For every artifact, record:

- code-section bytes;
- total Wasm bytes;
- deterministic compressed artifact bytes;
- the exact local/defined-function count reported by the repository-owned
  replica-validator-equivalent counter;
- the independently emitted optimizer defined-function count;
- table elements and other indirect-function entries;
- representative instruction counts;
- a named post-`-Oz` Canic monomorphization report;
- exports, Candid and selected capabilities; and
- clean/warm release-build time, peak RSS and process/thread high-water marks
  when making a build-performance claim. On 2026-09-23 the maintainer accepts
  the retained B1 runs as footprint attribution only, without repeating them
  to backfill those resource quantities. No build-speed/resource claim follows;
  any later such claim requires its own controlled qualification.

B1 also records the dated authoritative network limits for code-section bytes,
total module bytes and defined functions. The acceptance measurement uses a
repository-owned counter frozen to the IC replica validator source; it does not
substitute `ic-wasm`'s imports-plus-definitions total. The optimizer's defined-
function metric remains a separately produced cross-check.
Completion is defined against the final artifact:

The frozen interpretation follows the
[IC WebAssembly module requirements](https://docs.internetcomputer.org/references/ic-interface-spec/canister-interface/),
which state the function limit in terms of functions declared by the module.

```text
code_headroom =
    network_code_section_limit - final_code_section_bytes

function_headroom =
    network_defined_function_limit - final_replica_limited_function_count

required_function_reserve =
    ceil(network_defined_function_limit * 5 / 100)

required_code_reserve =
    ceil(network_code_section_limit * 5 / 100)
```

`final_replica_limited_function_count` is the exact local-function quantity
counted by the frozen replica validator. At DFINITY `ic` commit
`2f8dc21e2e5c37a4cae7f65d2a4230ac8f143e5a`,
`rs/embedders/src/wasm_utils/validation.rs` filters the module function arena
with `is_local()` before applying `max_functions`; imports are validated
separately and are not included. `rs/config/src/embedders.rs` sets that default
to 50,000. B1 records the repository counter source and executable hashes,
frozen IC commit, structural-validator version and result, and rejects a
disagreement with the independently emitted optimizer defined-function count.

The worst qualified artifact must satisfy all independent gates:

```text
code_headroom >= required_code_reserve
function_headroom >= required_function_reserve
final_total_module_bytes < network_total_module_limit
```

Under the retained 10 MiB code-section limit, the binding 5% reserve is
512 KiB. A 1 MiB code-section reserve is preferred. Reduction from a failing
baseline is useful attribution but never completion evidence. If a network
limit or toolchain changes, the baseline and accepted limits must be frozen
again.

Representative workloads receive one explicit maximum 1% instruction
regression allowance. B1 may select a smaller allowance; later batches cannot
silently expand it.
