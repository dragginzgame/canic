## Why This Line Changed

The former 0.110 plan combined indexed estates, application retirement,
parallel creation/reset lanes, reserve Fleets, cross-Fleet transfer, funding
policy and 10/100/1,000 qualification. The binding 0.109 complexity audit
rejected that breadth as an automatically earned successor.

Toko Miner then supplied the missing downstream operating evidence. Its 0.109
adoption repeatedly found defects only after complete CI and real no-effect
release preparation crossed the preceding boundary. The relevant current
feedback is:

- `CANIC-014`: mutable narrative repeatedly contradicted immutable release
  facts after publication;
- `CANIC-087`: nine retained release artifacts require redundant declaration
  links and serial release-profile runtime links;
- `CANIC-090` and `CANIC-091`: a stopped exact Root must yield one management-
  bound Start prerequisite before protected child observation, followed by
  complete protected revalidation after Start; and
- the endpoint-heavy downstream Wasm report: optimizer convergence is
  exhausted, so shared wrapper/runtime ownership must provide useful mainnet
  headroom rather than relying on another Binaryen pass.

`CANIC-091` and the remaining 0.109 findings stay in 0.109. This design does
not defer an active release blocker or weaken the 0.109 closeout gate. It makes
the lessons durable successor constraints.

### Failure Pattern To Remove

The error count does not come from one failed multi-Fleet premise. It comes
from recurring boundary mistakes around an otherwise coherent authority
model:

1. focused policy or planner fixtures used newly complete state and missed the
   older public adoption shape that reached the same code;
2. release truth, build context and recovery evidence had more than one
   projection that could drift from its structured authority;
3. endpoint generics and role-specific build inputs duplicated work across a
   large real application; and
4. each safe patch added another validation/recovery case while the binding
   0.109 complexity verdict was already failing.

0.110 responds by reducing owners and compiled projections, making public
handoffs part of every qualification shape and enforcing fixed size, build and
validation budgets. Multi-Subnet and multi-Fleet authority remain the target;
additional autonomous protocols no longer advance ahead of those budgets.

## Downstream Steering Boundary

Toko Miner is the primary real-application steering source for this line. It
remains read-only from the Canic repository and creates no production
dependency, private API or application-specific authority.

Each downstream-shaped claim requires both:

1. a repository-owned fixture that can run without Toko Miner; and
2. retained read-only Toko evidence showing whether the maintained public
   surface solves the same application boundary.

Toko evidence may reveal a Canic requirement. It does not authorize Canic to
copy Toko code, depend on IcyDB, parse Toko-owned files at runtime or make a
Canic release depend on mutable downstream source.

## Decision

0.110 is a contraction line with one new safety capability.

1. Every retained runtime capability has one owner, one compiled projection
   and one measurable code/build cost.
2. Exported endpoint functions are minimal trampolines. Shared authentication,
   admission, decoding, reply and error work lives in non-generic helpers when
   specialization is not semantically required.
3. Role selection cannot compile unused command, metrics, provisioning,
   configuration or diagnostic implementations into a role.
4. Release declaration and runtime compilation are separate cost classes.
   Declaration extraction never requires a discarded release-LTO artifact.
5. Distinct package/role protocol identities use one canonical bounded build-
   context map so Cargo can batch compatible runtime builds.
6. Release facts come from structured version, tag, package, validation and
   publication records. The current handoff summarizes those facts but is not
   a second publication-state authority.
7. Fleet Ensure remains the sole current convergence workflow. A prerequisite
   plan may short-circuit ordinary observation only for an exact management-
   verified effect and must require full authority revalidation afterwards.
8. Validation owns an explicit time, RSS, process/thread and case-count
   envelope. A new case must replace duplicated evidence or justify a distinct
   distributed invariant inside that envelope.
9. Stateful managed Components may require one application-owned retirement
   acknowledgement before ordinary stop, uninstall, reset or recycling.
10. No estate-transfer, reserve-Fleet, high-throughput maintenance or generic
    observatory protocol is implemented by this line.

## Non-Goals

0.110 does not:

- move any unresolved 0.109 finding into a later minor;
- add a quick, unsafe or noncanonical release artifact;
- weaken Candid, export, feature, provenance, hash, deterministic-gzip or
  release-build validation;
- add a generic workflow engine, compatibility layer or product protocol v2;
- add rolling, mixed-version or cross-release operation;
- implement reserve Fleets, cross-Fleet asset transfer, batch creation/reset or
  1,000-canister qualification;
- add a runtime observatory, HTML renderer or one new endpoint per view; or
- modify Toko Miner, IcyDB or another sibling repository.

## Contraction Baseline And Budgets

B1 freezes one immutable post-0.109 baseline containing:

- raw, code-section and gzip bytes for every canonical role and one endpoint-
  heavy managed fixture;
- defined functions, exports and per-capability shallow-byte attribution;
- declaration, Cargo runtime, link/LTO, Binaryen and total release-build time;
- compiler-cache deltas and peak process/RSS evidence;
- current command/status/Candid methods and feature/capability projections;
- the three 0.109 gravity-well module spans and their accepted ownership seams;
- current handoff lines and operator success/recovery steps; and
- governed pure, ordinary and PocketIC test inventories.

The endpoint-heavy fixture must mirror the downstream pressure shape without
copying application code. Against the current IC-mainnet network profile, the
accepted target is useful headroom: at least 350 KiB of additional code-section
reduction from the failing qualified baseline, with 500 KiB as the preferred
target. If the IC limit changes, the named network profile changes; the
measured capability budget and regression-headroom requirement remain.

No line-count or byte target permits moving behavior into an unowned layer,
removing a security check, flattening typed errors or hiding code in an
unmeasured artifact.

## Release-Build Contraction

The release builder must:

1. compile Candid declarations through a shared non-LTO batch using the exact
   package features, configuration, network and declaration cfg;
2. read and hash canonical built-in sidecars before their sole runtime build,
   using declaration compilation only where no canonical sidecar exists;
3. replace one process-wide protocol-digest scalar with a canonical bounded
   per-package/role build-context map;
4. batch compatible final runtime packages and split only genuine same-package
   profile conflicts;
5. compare fat LTO and ThinLTO/multiple-codegen-unit candidates through the
   complete Binaryen, determinism, size and runtime-instruction gates; and
6. retain one production profile, selected by evidence rather than an
   operator-visible fast-release mode.

Clean and warm Toko-shaped A/B evidence must record the full phase breakdown.
A one-role source edit must not force unrelated declaration or runtime links
without an explicit shared-authority reason.

## Runtime And Endpoint Contraction

The endpoint expansion audit maps each generated function to:

- transport decoding;
- authentication and admission;
- workflow delegation;
- response/reply encoding; and
- diagnostic conversion.

Repeated code moves behind shared non-generic functions where endpoint types
do not require specialization. Each export remains a thin marshalling and
delegation boundary. The audit must separately measure Canic wrappers,
application/upstream code and stripped-unattributed structure; it must not
guess ownership from symbol order.

Role-selected metrics Core, Runtime and Security providers compile once for a
role. An ordinary role retains only the capability implementations and compact
authority it consumes. Root remains the sole full control-plane configuration
owner.

## Control-Plane And Operator Contraction

0.109 B9 must already decompose the accepted gravity wells enough to pass its
audit. 0.110 then enforces those seams as budgets:

- admission decisions have one pure owner;
- Component allocation, installation, Directory, draining and removal do not
  share an undifferentiated module;
- Coordinator Registry, admission and funding workflows retain distinct
  owners;
- recovery-plan decisions can be proved without IC or PocketIC drivers; and
- ordinary success and documented same-release recovery use Fleet Ensure
  vocabulary, not internal journal phases.

The current handoff remains below 250 physical lines. Completed evidence moves
to archives or canonical audits; no release guard parses explanatory prose as
machine authority.

## Stateful Retirement Safety

A role opts in explicitly to application retirement. For an opted-in role:

1. the application owns the meaning and bounded opaque receipt;
2. Canic binds the acknowledgement to the exact Component, application
   revision and immutable removal operation;
3. ordinary removal enters `Draining` and admits only the bounded application
   retirement workflow plus protected observation;
4. stop, uninstall, reset and recycle remain blocked until the exact receipt is
   durable and Root-observed;
5. retry reuses the same removal authority; and
6. forced unqualified removal is separately authorized and leaves a permanent
   data-disposition tombstone.

Retirement adds no second lifecycle owner and no generic application-data
decoder. The receipt is evidence, not business policy.

## Validation Policy

B1 records the exact accepted validation envelope. Later batches may not grow
serial PocketIC merely because a new interruption point can be enumerated.

Prefer, in order:

1. pure policy/state-transition tests;
2. stable/model property and corruption tests;
3. host fixtures with deterministic fake platform observations;
4. one representative PocketIC journey per distinct external-effect or
   cross-canister invariant; and
5. read-only downstream qualification.

Every retained PocketIC case names the invariant unavailable at a cheaper
layer. The closeout report compares the baseline and final inventory, time,
RSS and process/thread high-water marks.

## Completion Criteria

0.110 is complete only when:

1. every retained capability has one owner and measured runtime/build cost;
2. declaration extraction performs no discarded release-LTO link;
3. compatible final roles batch without losing distinct protocol identity;
4. two clean release builds remain byte deterministic and preserve all
   artifact, Candid, export, feature and provenance gates;
5. the endpoint-heavy fixture retains at least 350 KiB additional headroom
   against the accepted failing baseline under the current network profile;
6. unused role capability, metrics and full-configuration implementations do
   not enter ordinary Wasm artifacts;
7. Fleet Ensure remains the sole current convergence owner and prerequisite
   effects cannot widen ordinary observation authority;
8. release publication truth is derived from structured facts and the current
   handoff remains below 250 lines;
9. the validation matrix remains inside its accepted case/time/RSS/process
   envelope;
10. opted-in stateful Components cannot be destroyed or recycled before exact
    retirement evidence, while forced removal remains permanently distinct;
11. repository-owned downstream-shaped fixtures pass without a Toko or IcyDB
    production dependency;
12. read-only Toko feedback confirms the maintained public boundary or records
    a newly classified Canic-owned blocker; and
13. a human-requested immutable closeout audit is accepted before 0.111 begins.
