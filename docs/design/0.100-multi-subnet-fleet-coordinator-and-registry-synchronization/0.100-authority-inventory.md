# Canic 0.100 Live Topology Authority Inventory

Date: 2026-07-26

## Scope

This inventory anchors 0.100 Slice 1 to immutable `v0.100.0`
(`b100e83c2dcfcd2f807597d7906578315a620fec`). It records the live
single-root authorities that must be replaced, the physical Subnet facts that
remain and the intermediate Tree configuration already implemented.

It is an implementation inventory, not a compatibility plan. A fresh current
installation does not read any durable record, Candid payload or host journal
from 0.99 or an earlier 0.100 patch.

The 2026-07-26 design amendment removes the intermediate Tree layer entirely.
The sole target is one Fleet Subnet Root per occupied
`(FleetKey, SubnetId)`, managing root-allocated Component instances with
direct Component Children.

Different Fleets may each have their own Fleet Subnet Root on the same
physical Subnet. Those roots share placement only; every authority and durable
owner remains Fleet-bound.

## Durable and Protocol Cut Set

The following live families are one coupled hard-cut set:

- `TreeSpecId`, `TreeGroupId`, `TreeId` and every generated or persisted Tree
  projection;
- environment record, `EnvBootstrapArgs`, `EnvSnapshotResponse` and
  `CanisterInitPayload`;
- `SubnetRegistryData`, its stable map, ops, DTO response and topology query;
- `SubnetDirectoryData`, its stable map, ops, DTO input/page and query;
- `FleetDirectoryData`, its current role/principal map and shared provenance;
- cascade state and topology snapshots, validation, forwarding and retry;
- root/non-root init, post-upgrade, Component/Component-Child provisioning and
  activation;
- Wasm Store bootstrap, release-set projection, manifest admission and
  artifact selection;
- facade exports, Candid surface tests, state-contract registration and memory
  ownership declarations; and
- host install journal, deployment truth, status and CLI text.

Renaming only one layer would leave false authority. Registry, Directory,
protected bindings, Component Topology, Component admissions, active release
set, Wasm Store Catalog, Candid and stable owners therefore move as coherent
slices with no alias or decoder.

## Physical Subnet Terms That Remain

These are not topology sediment:

- the IC Subnet principal or `SubnetId`;
- Coordinator and Fleet Subnet Root placement evidence;
- Fleet Cycles Steward placement, limits and root assignments;
- root configured limits and Component Spec admissions;
- trusted Subnet type/profile/capability metadata;
- restricted-Subnet creation funding;
- management-Canister observation of a Canister's physical Subnet; and
- control-plane state whose keys and behavior genuinely describe one physical
  Subnet.

`ComponentInstanceId` is logical Component identity. `SubnetId` is physical
placement. One Fleet Subnet Root is unique for one Fleet/Subnet pair, not for
the physical Subnet globally. Another Fleet may independently own another
root on that Subnet.

## Intermediate Configuration Cut

The open 0.100.1 implementation completed an intermediate declaration cut:

- `ConfigModel` parses and embeds `TreeSpecId`-keyed Tree Specs and
  `TreeGroupId`-keyed scale declarations;
- every Tree Group references an existing Spec and has positive ordered
  counts;
- the sum of group maxima is limited to 4,096 concrete Trees;
- active configs, scaffolding, host projections and
  `canic app role attach --tree-spec` use those tables; and
- the current installer fails closed unless exactly one initial Tree is
  declared.

That entire Tree declaration layer is now superseded, not merely its
`kind = "root"` rule. Before the batch is releasable, the maintained surface
must instead:

- replace `TreeSpecId` with `ComponentSpecId`;
- remove `TreeGroupId`, `TreeId` and empty logical instance allocation;
- replace `canic app role attach --tree-spec` with exact
  `--component-spec <component-spec>` selection;
- declare one direct Component role and direct child set per Component Spec;
- reject `root`, `service` and `component` kinds plus `owner_component`;
- derive ownership structurally from the non-recursive Component Spec;
- put the Fleet instance ceiling on the Component Spec;
- distribute positive root-local ceilings through immutable
  `ComponentSpecAdmission` rows;
- allocate `ComponentInstanceId` only when a root creates a concrete
  Component; and
- derive Component Topology, release-set and Wasm Store construction from the
  exact admitted Specs and children.

The temporary environment declaration selector is not final protected runtime
identity.

The later 0.101 `ComponentGroupSpecId` does not preserve `TreeGroupId`. It
identifies a bounded compile-time deployment composition that flattens to
direct Components before planning. It identifies no concrete instance,
runtime parent, root, Registry partition or lifecycle authority.

The later `ComponentGroupPlacementId` likewise does not preserve `TreeId`. It
distinguishes concrete copies of one flattened deployment when several copies
may share a root. It owns no Canister, Component identity, Registry partition,
runtime parent or lifecycle effect; the root still allocates every
`ComponentInstanceId`.

## Ordered Remaining Cut

1. remove Tree Spec, Tree Group and Tree ID from config, compiled bootstrap,
   host/CLI projections and facade exports, including replacing
   `--tree-spec` with `--component-spec`;
2. add non-recursive Component Specs and freeze
   `ComponentSpecId`/`ComponentInstanceId`;
3. derive the canonical Component Topology, build the separate infrastructure
   manifest and qualified application artifact union, then project exact root
   release-set manifests;
4. freeze `SubnetId`, Coordinator binding, `FleetSubnetRootBinding`,
   Component admissions, root limits and Component/child bindings;
5. replace Fleet Root with one Fleet Subnet Root per occupied Fleet/Subnet
   pair while allowing another Fleet's independent root on the same Subnet;
6. replace `SubnetRegistry` with root-owned,
   `ComponentInstanceId`-partitioned `ComponentRegistry`;
7. split Fleet/Component Directory provenance and replace `SubnetDirectory`
   with `ComponentDirectory`;
8. make lifecycle root- and Component-bound, distribute Directories directly
   from the root and partition ongoing root funding through bounded Fleet
   Cycles Stewards; and
9. verify active source, Candid, stable contracts and documentation contain no
   Tree identity, logical Subnet Slot, nested Component or arbitrary artifact
   fallback.
