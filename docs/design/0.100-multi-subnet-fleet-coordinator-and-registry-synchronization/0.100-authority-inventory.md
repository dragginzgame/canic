# Canic 0.100 Live Topology Authority Inventory

Date: 2026-08-03

## Scope

This inventory anchors 0.100 Slice 1 to immutable `v0.100.0`
(`b100e83c2dcfcd2f807597d7906578315a620fec`). It records the live
single-root authorities that must be replaced, the physical Subnet facts that
remain and the intermediate Tree configuration already implemented.

It is an implementation inventory, not a compatibility plan. A fresh current
installation does not read any durable record, Candid payload or host journal
from 0.99 or an earlier 0.100 patch.

The 2026-07-26 design amendment removes the intermediate Tree layer entirely.
The sole target is one Fleet Subnet Root per occupied
`(FleetKey, SubnetId)`, managing root-allocated Component instances with
multi-level, dynamically parented Component Children.

Different Fleets may each have their own Fleet Subnet Root on the same
physical Subnet. Those roots share placement only; every authority and durable
owner remains Fleet-bound.

## Durable and Protocol Cut Set

The following live families are one coupled hard-cut set:

- `TreeSpecId`, `TreeGroupId`, `TreeId` and every generated or persisted Tree
  projection;
- environment record, `EnvBootstrapArgs`, `EnvSnapshotResponse` and
  `CanisterInitPayload`;
- `SubnetRegistryData`, its stable map, ops, DTO response and topology query;
- `SubnetDirectoryData`, its stable map, ops, DTO input/page and query;
- `FleetDirectoryData`, its current role/principal map and shared provenance;
- application cascade state/topology endpoints, validation and forwarding;
  the implicit Wasm Store retains its separately composed infrastructure
  activation surface, selected from root-owned Store inventory rather than
  `SubnetRegistry` authority;
- root/non-root init, post-upgrade, Component/Component-Child provisioning and
  activation;
- Wasm Store bootstrap, release-set projection, manifest admission and
  artifact selection;
- facade exports, Candid surface tests, state-contract registration and memory
  ownership declarations; and
- host install journal, deployment truth, status and CLI text.

Renaming only one layer would leave false authority. Registry, Directory,
protected bindings, Component Topology, Component admissions, active release
set, Wasm Store Catalog, Candid and stable owners therefore move as coherent
slices with no alias or decoder.

Released 0.100.92 removes `SubnetRegistry` from maintained Fleet-state and
topology propagation. Root Fleet-state mutation freezes the canonical union
of root-owned Store inventory and current top-level Component Registry
partitions before applying and fanning out the command. Non-roots forward only
through their maintained direct-child cache. Legacy provisioning, pool
recovery and root-derived Fleet Directory resolution remain the final local
Registry consumers.

Released 0.100.93 removes those final consumers. Each Fleet Subnet Root now
owns its prepaid Canister assets in explicit control-plane inventory,
Component provisioning uses the root-owned Component Registry, and Fleet
Directory projection is derived from the Coordinator Registry mirror. No
maintained runtime path reads the retired role-based `SubnetRegistry`.

Released 0.100.94 gives the Fleet Coordinator and every Fleet Subnet Root one
stable v1 authority snapshot fence at memory ID 59. Controller-only prepare
seals mutation against the authority's independently observed IC Canister
history and suspends timers; exact live resume reopens and rearms them. Loading
the sealed snapshot advances live Canister history outside the restored stable
record, so the restored authority remains queryable but rejects resume and all
ordinary updates before dispatch.

Released 0.100.95 groups the reinstall-only stable-memory ledgers by their
current owners and hard-cuts the broad root Subnet-state label to root Wasm
Store state. Released 0.100.96 first consolidated one canonical host artifact
builder for Coordinator, Fleet Subnet Root and Wasm Store and made every
output carry exact Cargo package identity. The boundary measurement then
exposed the remaining root-embedded Store and root-owned install path. The
accepted final amendment keeps all three outputs independent, moves Store
placement/install/handoff recovery into the host journal and leaves only
runtime Store inventory/publication/lifecycle under the root. Released
0.100.98 implements that source and installation cut; open 0.100.99 removes
the final root-triggered Store build and records the passing post-extraction
measurement in the
[infrastructure Wasm boundary audit](0.100-wasm-boundary-closeout.md).

## Physical Subnet Terms That Remain

These are not topology sediment:

- the IC Subnet principal or `SubnetId`;
- Coordinator plus Fleet Subnet Root/Store co-placement evidence;
- root configured limits and Component Spec admissions;
- trusted Subnet type/profile/capability metadata;
- separate restricted-Subnet Coordinator, root and Store creation funding;
- management-Canister observation of a Canister's physical Subnet; and
- root-owned Store, Fleet Registry mirror, Component Registry and prepaid
  Canister inventory whose bindings are explicitly tied to that root's
  physical Subnet.

`ComponentInstanceId` is logical Component identity. `SubnetId` is physical
placement. One Fleet Subnet Root is unique for one Fleet/Subnet pair, not for
the physical Subnet globally. Another Fleet may independently own another
root on that Subnet.

## Historical Intermediate Configuration Cut

Immutable `v0.100.0` implemented this intermediate declaration layer:

- `ConfigModel` parsed and embedded `TreeSpecId`-keyed Tree Specs and
  `TreeGroupId`-keyed scale declarations;
- every Tree Group referenced an existing Spec and had positive ordered
  counts;
- the sum of group maxima was limited to 4,096 concrete Trees;
- configs, scaffolding, host projections and
  `canic app role attach --tree-spec` used those tables; and
- the installer failed closed unless exactly one initial Tree was
  declared.

Released 0.100.1 then removed that entire Tree declaration layer, not merely
its `kind = "root"` rule. The maintained surface now:

- uses `ComponentSpecId` instead of `TreeSpecId`;
- contains no `TreeGroupId`, `TreeId` or empty logical instance allocation;
- exposes exact `canic app role attach --component-spec <component-spec>`
  instead of `--tree-spec`;
- declares one direct Component role and flat potential child-role/Wasm catalog
  per Component Spec;
- rejects `root`, `service` and `component` kinds plus `owner_component`;
- derives artifact admission from the flat Spec and concrete ownership from
  root-journalled parent bindings;
- places the Fleet instance ceiling on the Component Spec;
- distributes positive root-local ceilings through immutable
  `ComponentSpecAdmission` rows;
- allocates `ComponentInstanceId` only when a root creates a concrete
  Component; and
- derives Component Topology, release-set and Wasm Store construction from the
  exact admitted Specs and children.

The temporary environment declaration selector was not retained as protected
runtime identity.

The later 0.101 `ComponentGroupSpecId` does not preserve `TreeGroupId`. It
identifies a bounded compile-time deployment composition that flattens to
direct Components before planning. It identifies no concrete instance,
runtime parent, root, Registry partition or lifecycle authority.

The later `ComponentGroupPlacementId` likewise does not preserve `TreeId`. It
distinguishes concrete copies of one flattened deployment when several copies
may share a root. It owns no Canister, Component identity, Registry partition,
runtime parent or lifecycle effect; the root still allocates every
`ComponentInstanceId`.

## Cut Order

Steps 1-9 are complete. The accepted follow-up 0.100 batch must complete step
10 before the source-side sequence is final:

1. remove Tree Spec, Tree Group and Tree ID from config, compiled bootstrap,
   host/CLI projections and facade exports, including replacing
   `--tree-spec` with `--component-spec`;
2. add flat Component Specs with multi-level runtime child bindings and freeze
   `ComponentSpecId`/`ComponentInstanceId`;
3. derive the canonical Component Topology, build the separate infrastructure
   manifest and qualified application artifact union, then project exact root
   release-set manifests;
4. freeze `SubnetId`, Coordinator binding, `FleetSubnetRootBinding`,
   host-materialized `FleetSubnetWasmStoreAuthority`, Component admissions,
   root limits and Component/child bindings;
5. replace Fleet Root with one Fleet Subnet Root per occupied Fleet/Subnet
   pair while allowing another Fleet's independent root on the same Subnet;
6. replace `SubnetRegistry` with root-owned,
   `ComponentInstanceId`-partitioned `ComponentRegistry`;
7. split Fleet/Component Directory provenance and replace `SubnetDirectory`
   with `ComponentDirectory`;
8. make lifecycle root- and Component-bound and distribute Directories
   directly from the root; and
9. verify active source, Candid, stable contracts and documentation contain no
   Tree identity, logical Subnet Slot, nested Component or arbitrary artifact
   fallback; and
10. independently host-install each root's sibling Store, remove root-embedded
    Store bytes and root-owned create/install state, and remeasure the final
    root/Store boundary.
