# Canic 0.100 Live Topology Authority Inventory

Date: 2026-07-25

## Scope

This inventory anchors 0.100 Slice 1 to immutable `v0.100.0`
(`b100e83c2dcfcd2f807597d7906578315a620fec`). It records the live
single-Tree authorities that must be replaced, the physical Subnet facts that
must remain, and the first completed configuration cut.

It is an implementation inventory, not a compatibility plan. A fresh 0.100
installation does not read any durable record, Candid payload or host journal
from 0.99 or an earlier 0.100 patch.

## Durable and Protocol Cut Set

The following live families are one coupled hard-cut set:

- environment record, `EnvBootstrapArgs`, `EnvSnapshotResponse` and
  `CanisterInitPayload`;
- `SubnetRegistryData`, its stable map, ops, DTO response and topology query;
- `SubnetDirectoryData`, its stable map, ops, DTO input/page and query;
- `FleetDirectoryData`, its current role/principal map and shared provenance;
- cascade state and topology snapshots, validation, forwarding and retry;
- root/non-root init, post-upgrade, child provisioning and activation;
- facade exports, Candid surface tests, state-contract registration and memory
  ownership declarations; and
- host install journal, release-set projection, deployment truth, status and
  CLI text.

Renaming only one layer would leave a false authority. The Registry,
Directory, protected binding, Candid and stable owners therefore move as
coherent slices with no alias or decoder.

## Physical Subnet Terms That Remain

These are not topology sediment:

- the IC Subnet principal or future `SubnetId`;
- Coordinator placement and Tree placement evidence;
- trusted Subnet type/profile/capability metadata;
- restricted-Subnet creation funding;
- management-Canister observation of a Canister's physical Subnet; and
- control-plane state whose keys and behavior genuinely describe a physical
  IC Subnet.

`TreeId` is logical identity. `SubnetId` is repeatable placement metadata.
Neither substitutes for the other.

## First Configuration Cut

The open 0.100.1 batch completes the declaration-side cut:

- `ConfigModel` parses, validates and embeds `TreeSpecId`-keyed Tree Specs and
  `TreeGroupId`-keyed scale declarations;
- every Tree Spec has exactly one root;
- every Tree Group references an existing Spec and has positive ordered
  counts;
- the sum of group maxima is limited to 4,096 concrete Trees;
- active configs, scaffolding, host projections and
  `canic app role attach --tree-spec` use only the new tables; and
- the current single-Tree installer fails closed unless exactly one initial
  Tree is declared.

The temporary environment declaration selector is `TreeSpecId`; it is not the
final protected runtime identity. Slice 1 remains open until `TreeBinding`,
`TreeId`, `TreeGroupId`, Spec hash, Tree Root and `SubnetId` replace that
selector as one protected contract.

## Ordered Remaining Cut

1. freeze `SubnetId`, Coordinator binding and protected `TreeBinding`;
2. replace Fleet Root with distinct Coordinator and Tree Root authorities;
3. replace `SubnetRegistry` with `TreeRegistry`;
4. split Fleet/Tree Directory provenance and replace `SubnetDirectory` with
   `TreeDirectory`;
5. make cascade and lifecycle Tree-bound; and
6. verify active source, Candid, stable contracts and documentation contain no
   logical Subnet Slot or Fleet Root fallback.
