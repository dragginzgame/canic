# Standalone Blob Service Extraction

## Selected scope

On 2026-10-04, after publishing 0.110.52, the maintainer explicitly requested
starting the blob removal previously discussed. This prioritizes the extraction;
it does not declare FR1 complete, accept the 0.110 closeout audit, assign a release
version, or authorize a deployment. The directory retains its roadmap location;
release assignment remains a maintainer decision.

The source cut removes application blob semantics from Canic Core, the facade,
CLI, default validation graph and stable-allocation catalog. No compatibility
features, command aliases or old service implementation remain. Current Canic
owns Fleet lifecycle and ordinary managed Components.

## Ownership and build boundary

`ic-blob-storage` owns content identity, upload manifests, references, tenant
policy, provider interaction and accounting. Its standalone entrypoint and client
tools have no Canic dependency. The sibling checkout is read-only context.

Canic owns `integrations/blob-service`, a separate Cargo workspace that depends
on the published service library and the Canic facade. It owns only endpoint,
platform and lifecycle composition. Its lockfile and build directory are separate;
ordinary Canic testing, packaging and deployment do not resolve or qualify it.
The selected published service is exactly 0.14.1. The adapter is unpublished.
This isolation is the maintained ownership boundary, not a second storage engine.

The adapter uses ordinary Canic managed endpoints and Fleet guards. Explicit
rejection mode preserves the provider's plain certificate reply. Service-specific
authority remains enforced by the shared service workflows; controllers do not
become tenant operators. Certificate issuance commits synchronously without an
intervening await. Query/update decoding has raw-byte, work, skip, type and header
bounds. The owning lifecycle macro bounds the outer envelope before restoration;
the participant bounds the nested configuration.

Canic owns the sole default `ic-memory` runtime. The adapter declares seventeen
service grants in its application-owned range before bootstrap, then opens those
committed grants synchronously. It must never bootstrap a second runtime.
Restoration opens the shared service fenced. Platform-version observation and
independent current-instance proof preserve the library's recovery contract.
Older-snapshot activation and cross-release migration are unsupported.

## Removal and operator behavior

Remove the embedded blob/billing features, DTOs, macros, storage records,
provider client, stable IDs 55–58, CLI command group and Medic option. Remove their
standalone probes, protocol pins, main-workspace PocketIC suite and release gate.
Retain generic feature resolution, descriptor integrity, bounded endpoints,
lifecycle and authorization tests using current Canic-owned fixtures.

The independent service CLI owns blob operations. Its status command does not
implement Canic's former `--check-ready` exit contract. Direct provider funding
has no qualified replacement command in the selected standalone service. These
are explicit removed operator surfaces, not reasons to retain obsolete code.

The source cut does not delete any canister, reset stable state, upload content or
spend cycles. Existing providers may retain liability after logical release. Keep
observed obligations and their evidence until separately reviewed retirement can
account for them; source removal is not physical deletion or billing cessation.

## Qualification

Qualify the changed Core/facade/Host/CLI surfaces with targeted native tests and
warning-denied lint. Validate the changed shell runner and test inventory. Check
that the main Cargo graph contains no service dependency or former blob target.
Refresh the embedded allocation peer if its canonical source inputs change.

The maintainer explicitly removed the remaining blob-specific adapter tests on
2026-10-04. Keep this adapter free of test fixtures, standalone test modes and
PocketIC runners. Check its maintained managed build and lint explicitly; the
main release graph remains independent. Generic Canic guards, decoders, lifecycle
and memory composition retain their framework-owned coverage.

The service repository owns its existing certificate, authority, restoration,
snapshot and history tests. Missing decoder-budget coverage is tracked in
[ic-blob-storage#7](https://github.com/dragginzgame/ic-blob-storage/issues/7).
Publisher/serving and lifetime work already have upstream issues; do not duplicate
those suites here. Upstream service evidence does not qualify a specific deployed
wrapper, and neither source removal nor this task authorizes paid operations.

The current implementation/evidence handoff is [status.md](status.md). Versioning,
full release validation and publication remain maintainer-owned boundaries.
