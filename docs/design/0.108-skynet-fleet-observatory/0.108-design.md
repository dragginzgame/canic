Date: 2026-08-16

- Predecessor: 0.107 reusable Fleet Subnet Canister estates must be accepted,

## Decision

Canic 0.108 promotes Skynet from an idea reservoir into one bounded flagship
demonstration. Every installed Canister in the Skynet Fleet serves a local,
navigable T2-inspired observatory at its own HTTP gateway URL and exposes the
same evidence-labelled machine view at `/api/status.json`.

The renderer consumes the bounded role status variants accepted in 0.103. It does
not restore separate readiness, runtime, topology, funding or estate Candid
methods for presentation convenience.

Every page answers four questions immediately:

1. **Where am I?** The exact Canister, role, package, version, parent, Fleet,
   root and physical Subnet represented by this page.
2. **What exists?** The current Coordinator, roots, Stores, application
   service members, descendants and reusable-estate summaries.
3. **What is happening?** Current lifecycle, readiness, funding, estate,
   transfer, diagnostic and bounded metric observations.
4. **Who owns the truth?** The authoritative source, evidence class, revision,
   observation time and freshness of every displayed fact.

The observatory is a view, never another Registry, Directory, estate ledger,
funding authority, controller or operation journal. No browser request starts
a mutation.

## Meaning Of Every Canister

The 0.108 serving contract covers every **installed** Canister in the Skynet
Fleet:

- the Fleet Coordinator;
- every Fleet Subnet Root;
- every Wasm Store;
- every Skynet Authority or Replica service member;
- every T-800 scaling child; and
- every memory-cell sharding child.

An empty 0.107 estate asset in `Ready`, `Resetting`, transfer or another
module-free physical state cannot serve HTTP because it deliberately has no
installed Wasm. Installing an observatory module would make that asset no
longer empty and would violate 0.107 estate semantics. Such assets therefore
appear as bounded inventory nodes and aggregate state counts on installed
Canister pages, but are not falsely described as serving pages themselves.

This is the only exception to the phrase “served by every Canister.” It is a
physical platform boundary rather than reduced product scope.

## Current Baseline

The checked-in Skynet application already provides:

- one Authority and seven initial Replicas on eight distinct configured roots;
- admission and scale-out policy for up to 32 pre-installed roots;
- one initial T-800 and one initial memory cell per service node, with
  independent policy ceilings of four;
- shared code-native HTML and JSON rendering across Fleet Subnet Root,
  service-node, T-800 and memory-cell roles;
- live identity, cycles, readiness, environment, deployment, Directory,
  service-membership, descendant, metric and endpoint observations; and
- raw-gateway navigation between published members and direct relatives.

The current baseline does **not** provide the requested complete product:

- the canonical Fleet Coordinator and Wasm Stores do not serve the T2 page;
- not every installed role receives one complete revisioned Fleet overview;
- role snapshots do not use one exact evidence-class and freshness contract;
- 0.106 funding and 0.107 estate/transfer summaries are not integrated;
- high-cardinality estate data lacks an observatory-specific bounded summary
  and paging presentation;
- topology navigation is informative but not yet a comprehensive Fleet map;
  and
- the shared renderer remains application-owned even though canonical
  infrastructure must consume the generic presentation engine.

## Goals

0.108 must:

1. serve one consistent T2-inspired HTML observatory and JSON model from every
   installed Skynet Fleet Canister;
2. give every page a complete bounded Fleet overview plus exact local detail;
3. show Coordinator, root, Store, Component, service, parent/child, Subnet and
   estate relationships without inventing a second topology authority;
4. integrate 0.106 root-funding and 0.107 estate, concurrency, reset and
   transfer observations without gaining mutation authority;
5. make Observed, Configured, Derived, Planned, Simulated and Unavailable
   evidence visibly and structurally distinct;
6. preserve exact Registry revision, content hash, source, observation time
   and freshness for replicated topology views;
7. keep global counts complete while bounding every detailed list, response,
   label and metric set;
8. use one application-neutral rendering engine and one data-only Skynet
   presentation profile rather than infrastructure depending on an App crate;
9. remain useful and accessible on a phone, without external assets or a
   required JavaScript framework;
10. expose truthful protected-operation descriptions without making public
    HTTP an operator surface;
11. prove every installed Canister produces valid, mutually navigable HTML and
    JSON; and
12. account for the post-demo disposition of every installed and empty asset
    without claiming unsafe live-workload adoption.

## Non-Goals

0.108 does not:

- implement application-data replication or call a Replica read-ready;
- add health-based routing, load balancing or request failover;
- add autonomic placement, scale-in, live root expansion or self-healing;
- add Coordinator Workers;
- implement authentication profiles or a browser mutation console;
- add Motoko support;
- extract blob storage or implement remote snapshot archives;
- create a central Skynet database, topology ledger or metric warehouse;
- perform inter-Canister fanout while answering an HTTP query;
- expose controllers, credentials, protected records, backup contents,
  application data or unbounded reject text;
- certify raw-gateway content or imply certification when none exists;
- install observatory Wasm into empty estate assets;
- adopt live Skynet state into Toko or another App;
- add a second product-schema generation; or
- add weapons control, targeting, physical-device actuation, surveillance of
  people or any capability intended to injure people.

Transport, authentication, Workers, blob/archive storage, Motoko and
autonomous-operation concepts remain independent ideas. They do not gate the
0.108 read-only observatory.

## Presentation Architecture

~~~text
authoritative role state
  Coordinator Registry / root Registry and estate / Store inventory /
  Component runtime and Directory / local child bindings / metrics
                              |
                              | bounded role-owned conversion
                              v
                public observatory snapshot views
                              |
                 revisioned Fleet overview projection
                              |
                              v
              application-neutral Canic renderer
                 + data-only Skynet T2 profile
                       |             |
                       v             v
                    HTML /     /api/status.json
~~~

Canic owns the application-neutral snapshot types, validation, escaping,
bounded renderer and HTTP adapter in one flat workspace crate. The B1 contract
freezes its final package name; the intended owner is `canic-observatory`.

Skynet owns only a bounded data-only presentation profile:

- Fleet display name;
- safe role codenames;
- palette and fixed theme token;
- short explanatory labels; and
- links between admitted local resources.

The profile cannot carry HTML, CSS, JavaScript, URLs, endpoint names, Candid
payloads or executable behavior. Canonical Coordinator and Store artifacts
therefore depend only on the Canic-owned renderer, never on `apps/skynet`.
Protected install authority distributes the same validated profile to every
installed role.

The current `apps/skynet/console` implementation is hard-cut into these owners.
No compatibility wrapper or second template remains.

## Evidence Classes

Every field in HTML and JSON has one evidence class:

| Class | Meaning |
| --- | --- |
| Observed | Read from current local state, an exact accepted projection or a metric observation. |
| Configured | Frozen by checked-in App configuration or protected Fleet input. |
| Derived | Deterministically calculated from named Observed or Configured inputs. |
| Planned | A durable accepted policy or operation whose effect is incomplete. |
| Simulated | Explicitly inert fictional presentation or test-only scenario. |
| Unavailable | Not exposed, not authorized, not implemented, stale beyond policy or unreachable. |

Configured never renders as Observed. A configured Replica is never called
read-ready. Simulated never renders as live. Missing or stale data renders as
Unavailable, not healthy or zero.

Each accepted projected fact also retains:

- authoritative source role and Canister;
- Fleet identity;
- source revision and content hash where applicable;
- observation timestamp;
- receiver timestamp; and
- current, stale or unavailable freshness classification.

## Fleet Overview Projection

Every installed Canister needs a complete bounded overview, but it must not
query the entire Fleet on each page request.

0.108 therefore extends the existing Registry/Directory propagation path with
one sanitized observatory projection:

1. the Coordinator derives the Fleet topology portion from the authoritative
   Fleet Registry;
2. each root publishes a bounded role-owned summary of its Store, Component
   Registry, 0.106 funding state and 0.107 estate state;
3. the Coordinator accepts only exact registered-root summaries bound to the
   current Fleet and source revision;
4. one canonical overview revision and content hash is distributed to roots;
5. roots distribute the exact accepted projection to their sibling Store and
   admitted Components; and
6. Components propagate the exact projection to newly created or refreshed
   descendants through their existing protected parent authority.

Every receiver validates Fleet, source, audience, revision, content hash,
encoded size and monotonic acceptance. Equal-revision unequal-content input
fails closed. Older input never replaces newer accepted content. Exact retry
after interruption is idempotent.

These protected publications add variants to the receiving role's ordinary
`canic_command`: root summary acceptance on the Coordinator, overview
acceptance on Root/Store/managed canister, and descendant propagation on the
managed canister. Observatory and projection reads add bounded role status
variants. No publication, propagation, overview, freshness, role or recipient
gets its own Canic method. The Skynet HTTP method remains application-owned or
externally fixed by the IC HTTP protocol and is reported separately.

Compiled-capability presentation consumes the exact external protocol-profile
identity frozen by 0.103 B1. Protected artifact, release-set or Directory
metadata selects the profile-specific binding before the first role call; the
bounded role `Overview` response may then verify the same immutable role,
capability and profile digest. The observatory does not turn `Overview` into
schema negotiation, create a duplicate authority or add another discovery
method.

The projection is passive read state. It cannot authorize creation,
installation, scaling, funding, estate transitions, transfer or deletion.

## Topology Model

The global overview contains bounded summaries for:

- Fleet identity, package release set and overview revision;
- Coordinator identity and lifecycle state;
- physical Subnets;
- Fleet Subnet Roots and their lifecycle eligibility;
- sibling Wasm Stores and artifact-count/byte summaries;
- published Fleet services and Authority/Replica/PoolMember purposes;
- Component Group deployments and current versus configured placement;
- parent/child relationships for T-800 and memory-cell descendants;
- 0.106 root operating-balance classes and funding-policy state;
- 0.107 owned target, immutable maximum, Ready reserve, state counts,
  effective concurrency, pause state and transfer summaries;
- incomplete durable operations by typed class and count;
- compact diagnostic identities and safe remediation when implemented; and
- the post-demo disposition class of every known installed or empty asset.

The overview never embeds all 1,000 estate Principals per root. It shows exact
complete counts and bounded samples. Root-local pages expose cursor-bounded
detail using 0.107 indexes; a global page links to the owning root rather than
copying the asset ledger.

## Local Canister Detail

Every installed role serves the same page structure with a prominent
“YOU ARE HERE” node and role-specific sections.

### Fleet Coordinator

- Fleet identity, release set and Registry revision/hash;
- root and Store membership;
- root-funding treasury state, reserve, windows and kill switch;
- overview-projection convergence and stale recipients;
- protected operation catalogue; and
- links to every installed root and Store.

### Fleet Subnet Root

- physical Subnet, Coordinator and sibling Store;
- Component Registry and Directory summaries;
- 0.106 operating balance and exact funding state;
- 0.107 estate policy, state counts, progress, lanes and transfers;
- bounded installed Components and estate-asset pages;
- local metrics, diagnostics and lifecycle state; and
- links to parent infrastructure and local workloads.

### Wasm Store

- physical Subnet, root and Coordinator relationship;
- admitted release-set and artifact inventory summaries;
- publication/garbage-collection state where publicly safe;
- storage and cycle observations;
- protected Root/Store command-variant and externally mandated method
  catalogue; and
- links to the root and Fleet overview.

### Skynet Service Member

- Authority or Replica purpose without claiming replicated data readiness;
- Component Spec, Group deployment, placement and immutable ceilings;
- Fleet-service membership and Directory revision;
- T-800 and memory-cell pools, children and limits;
- local metrics, diagnostics and safe demo endpoints; and
- links to root, service peers and descendants.

### T-800 And Memory Cell

- exact parent, root, Subnet and Component binding;
- scaling or sharding pool and inherited policy;
- readiness, cycles, metrics and safe endpoints;
- parent and Fleet-overview navigation; and
- an explicit statement that the themed role grants no infrastructure or
  harmful authority.

## T2 Presentation Contract

The experience is a code-native homage to the visual language of Terminator 2:

- black, gunmetal and high-contrast red terminal palette;
- dense but readable diagnostic panels;
- scanline, targeting-grid and system-map motifs;
- restrained motion with a complete reduced-motion mode;
- clear node codenames such as Defense Grid Root, Neural Net Processor,
  T-800 Unit and Cyberdyne Memory Cell;
- an animated topology only when the underlying relationship is real; and
- unmistakable styling for Simulated and Unavailable information.

The repository does not embed film frames, actor likenesses, studio logos,
audio, dialogue quotations or third-party fonts/assets. The theme remains an
original code-native presentation, not a copy of copyrighted media.

Accessibility is part of the theme contract:

- every graph has a table/list equivalent;
- colour is never the only state signal;
- keyboard focus is visible;
- Principals and hashes wrap or expose accessible complete values;
- the primary overview works without horizontal phone scrolling;
- reduced-motion preference disables scan and transition effects; and
- semantic headings and landmarks remain useful without CSS.

## HTTP And JSON Contract

Every installed role exposes:

- `GET /` for HTML;
- `HEAD /` for metadata-only availability;
- `GET /api/status.json` for the same semantic snapshot; and
- bounded cursor/filter query parameters only where a role owns a paged local
  list.

Other methods return `405`; unknown paths return `404`. Responses remain
`no-store`, deny framing, deny referrer leakage, disable content sniffing and
load no external resource by default.

HTML and JSON are projections of one in-memory view. Tests reject a field,
state class, count or freshness result that appears differently between them.
The JSON schema remains version 1 and is hard-cut in place before 1.0.

The raw HTTP gateway is not certified by this line. Every page labels that
integrity boundary; 0.108 makes no certified-response claim.

## Bounds And Cost

The implementation freezes measured ceilings in B1 and revalidates them at
closeout:

- maximum overview projection bytes;
- maximum roots, Stores, service members and relationship edges;
- maximum local child rows per page;
- maximum estate samples per page;
- maximum metric rows and label bytes;
- maximum endpoint and capability rows;
- maximum profile labels and UTF-8 bytes;
- maximum HTML and JSON response bytes; and
- maximum rendering instructions and heap growth.

Complete totals remain exact even when lists are paged or sampled. Truncation
is explicit and links to the owning role/page. No local counter claims to
enforce an external provider bill.

0.108 creates no Canister merely to improve a graphic. Its qualification uses
the existing Skynet topology and separately approved environments. No test or
helper deploys to mainnet implicitly.

## Recovery And Freshness

Overview publication and propagation use same-release durable operations with
intent-before-effect, exact retry and terminal receipts where an inter-Canister
effect is involved.

After restart, each role:

1. restores its last accepted projection synchronously;
2. serves it as stale when its freshness policy has elapsed;
3. resumes any nonterminal propagation operation before new work;
4. accepts an equal-revision exact replay without rewriting state; and
5. fails closed on contradictory content or authority.

The last accepted view may remain visible as stale evidence. It never silently
becomes current and never authorizes an effect.

## Security And Privacy

Public observatory output must not expose:

- controllers merely because the browser can reach a Canister;
- bearer tokens, identity material, credentials or signing keys;
- raw protected Registry, Directory, funding, estate or operation records;
- backup contents, archive keys or repository credentials;
- application user data or personal data;
- unbounded reject messages, provider responses or logs; or
- mutation payloads disguised as navigation.

Every string is escaped before HTML insertion and encoded through the typed
JSON serializer. Public facts come from explicit allowlisted conversions.
Adding a field requires an owner, evidence class, bound, privacy review and
HTML/JSON parity test.

## Layering And Ownership

- DTOs remain passive HTTP/Candid boundary data.
- `model/` owns accepted projection records and monotonic revision invariants.
- `ops/` reads role state and converts it into named observatory views.
- `policy/` classifies freshness, visibility and bounds without storage or IC
  calls.
- `workflow/` owns root-summary publication and overview propagation.
- role command dispatch authenticates protected propagation variants; role
  status dispatch derives variant authority, rejects before protected state
  access and delegates public or protected reads immediately.
- the observatory renderer consumes views only and performs no state access.
- `apps/skynet` owns T2 labels and demo-specific safe endpoints, not generic
  infrastructure or Fleet authority.

## Validation Matrix

### Model And Rendering

- every fact has one evidence class and authoritative source;
- current/stale/unavailable classification is deterministic at equality;
- all visible strings escape HTML and serialize without semantic drift;
- malformed profile labels, colours, bounds and unknown theme tokens reject;
- graph and table contain the same nodes and relationships;
- counts remain complete when detailed rows truncate or page; and
- HTML/JSON size and render-cost ceilings reject first excess.

### Authority And Recovery

- anonymous or foreign root summary publication rejects;
- root/Fleet/source/audience substitution rejects;
- equal-revision equal-content replay is idempotent;
- equal-revision unequal-content rejects;
- old revision cannot replace new;
- restart before and after each propagation effect converges exactly;
- a stale projection remains labelled stale and authorizes nothing; and
- a child receives only the exact projection accepted by its protected parent.

### Every Installed Role

- Coordinator;
- Fleet Subnet Root;
- Wasm Store;
- Skynet Authority;
- Skynet Replica;
- T-800 child; and
- memory-cell child.

Each role must pass GET, HEAD, JSON, not-found, method-rejection, security-
header, local-identity, global-overview and mutual-navigation checks.

### Truthfulness

- Replica never implies data synchronization or read readiness;
- root health never implies load-balancer eligibility;
- configured maximum never renders as current membership;
- an empty estate asset never claims to serve HTTP;
- protected endpoints display as protected and cannot run through the page;
- missing controller-only facts render unavailable rather than inferred;
- raw-gateway output makes no certification claim; and
- T2 fiction never changes authority or operation semantics.
